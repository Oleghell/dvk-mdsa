# 0.3.27 — таймер возврата и одна кнопка новой десятки

В присланном rootless-automatic-pass-0.3.26.json выполнены три обработчика отправки. На третьем цикле таймер истёк в wait-chat-back: обработчик Back вернулся, но возврат в поиск ещё не был подтверждён. Причину задержки анимации/перехода этот отчёт не устанавливает. Сообщения не объявляются доставленными только по возврату обработчика.

## Исправлено
- Жёсткий общий лимит полного цикла поиск → профиль → чат → проверка → отправка → возврат: **30 с вместо 16 с**. Бюджет не сбрасывается после действий; по истечении — остановка без повторного Back и без повторной отправки.
- Ожидание открытия/закрытия чата опрашивается раз в секунду, включая неготовый экран. Ожидание не расходует 180 callback-кадров за несколько секунд. Повторных UI-действий нет.
- Внешний ограничитель всего отправляющего прохода: 350 с вместо 200 с, чтобы не обрывать сумму десяти ограниченных циклов и их подготовки.
- Не изменены: 100 мс на callback, 6000 managed-вызовов, 180 наблюдённых кадров, 64 временных handles, 8 переносов чтения поиска, паузы 1 с, проверки личности и пустоты чата, лимит 10 анкет и защита от повторов.
- Старая кнопка «Автопроход · до 10 анкет» убрана из главного окна. Рядом с одиночным приветствием теперь только **«Новая десятка · сохранить привязки»**. Старый backend оставлен для совместимости и регрессионных тестов, но из окна больше не запускается.

## Что нажать
1. Вручную проверь третье сообщение в оставшемся открытым чате и вернись в поиск. Повторять отправку не нужно.
2. Закрой прежнюю программу, запусти 0.3.27. Оба MuMu включены; на #4 загруженная сетка поиска.
3. Нажми **«Новая десятка · сохранить привязки»** один раз.
4. Пришли только `rootless-new-ten-0.3.27.json` рядом с test-apks.

Прошлый отчёт относится к старому запуску без долговременных привязок. Новая кнопка использует отдельный локальный журнал, старую блокировку не удаляет. Если новая десятка уже запускалась с записью, не удаляй её журнал ради повтора. Уже непустые чаты пропускаются; число новых привязок может быть меньше 10.

Журнал остаётся в `%LOCALAPPDATA%/DvkRootless/new-ten.sqlite3` (и возможных -wal/-shm): **не прикладывай его**. Запись привязки с synchronous=FULL и подтверждение записи происходят до отправки. Черновой исходный ID чата сохраняется как есть, положительный ID не придумывается. Неизвестный исход не повторяется после перезапуска.

Нативные регрессионные тесты моделируют 12-секундный возврат после третьей отправки и полностью застрявший возврат: первый завершается без повторных действий, второй ограниченно останавливается после одной команды Back. Это тестовый стенд, не гарантия исправления задержки в Android пользователя.
