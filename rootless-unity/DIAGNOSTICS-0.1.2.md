# Диагностика 0.1.2 — независимые признаки загрузки Unity, без установки

Отчёт 0.1.1 подтвердил token-authenticated соединение Gadget 17.24.1, единственный
процесс, ARM64 runtime и оба RPC. При этом стандартный Frida API перечислил 11 модулей,
не обнаружив даже сам работающий Gadget. Это **не доказательство отсутствия Unity**.
В исходном ARM64 `libil2cpp.so` офлайн подтверждены все четыре запрошенных C API-экспорта.
Цепочка Activity в APK создаёт UnityPlayer; конкретное состояние UI тестового устройства
из отчёта не известно. Ни обход защиты, ни переустановка сейчас не обоснованы.

## Запуск

1. Скачайте/распакуйте новый архив, запустите `Dvk-rootless-diagnostics.exe`.
2. Оба MuMu оставьте запущенными: рабочий #0 (5555), тестовый #4 (5563).
3. На #4 оставьте установленный тестовый ДругВокруг открытым. Вход в аккаунт не нужен.
4. Выберите тот же ADB и **старую папку `test-apks`** из частного комплекта.
5. Нажмите **«Собрать подробный отчёт — без установки»**.
6. Передайте `rootless-diagnostics-0.1.2.json` рядом с `test-apks` в приватный чат.

Android APK не менялся. Ничего не удаляйте/переустанавливайте. В публичном архиве APK
нет; сохранённый частный комплект нужен только для хеш-проверок и локального токена.

## Что проверяет новая версия

После уже работающих базовых RPC она независимо читает **`/proc/self/maps` самого
целевого процесса**, а не `/proc/<чужой pid>/maps`, и проверяет только четыре фиксированных
имени: `libfrida-gadget.so`, `libunity.so`, `libil2cpp.so`, `libmain.so`.
Сырые строки, адреса/диапазоны памяти, полные пути и неизвестные имена не возвращаются
на компьютер и не записываются в отчёт. Возвращаются только счётчики совпадений.
Это карта отображённых файлов, **не чтение содержимого памяти или данных приложения**.
Лимит: 20 000 строк, 4 MiB текста, 8 KiB на строку, файл всегда закрывается. EOF/ошибка/
достижение лимита различаются; неполный просмотр не объявляется отсутствием библиотек.

Также независимо проверяется только **наличие** четырёх глобальных символов через
`Module.findGlobalExportByName`, без вызова полученных функций и без выдачи адресов.
Из Android system properties читаются primary ABI и вид NativeBridge: в отчёт попадают
лишь ограниченные заранее определённые значения, неизвестная строка не сохраняется.

Если и Unity, и IL2CPP отображены в maps, но отсутствуют в enumerateModules,
результат — `engine-mapped-not-fully-enumerated`. Это подтверждает расхождение способов
обнаружения, **не гарантирует возможность NativeFunction/перехвата или доступ к UI**.
Если найдены глобальные экспорты — `il2cpp-global-export-visible`. Их callable-совместимость
и API Unity в этой версии не проверяются. `engine-not-confirmed` не означает, что движок
точно отсутствует: библиотеки могут быть представлены APK-mappings/другим именованием.
Неизвестные пути не раскрываются; APK-mappings отмечаются только булевым признаком.

## Ограничения безопасности

Только #4 (5563), прежняя проверка отличия от #0 (5555), фиксированный скрипт,
токен из локального тестового APK, временный loopback ADB forward с очисткой.
Нет root, установки, запуска/остановки приложения, clear-data, сообщений, координат,
OCR, скриншотов, логов, профилей, чатов, произвольных файлов, Memory.read/NativeFunction,
Interceptor или обхода integrity/root/certificate-проверок. Нет публичного сервера/MCP.
Отказ ОС в чтении не обходится и не требует включать root.

Внутренний токен не попадает в отчёт. Сам частный APK доступен только доверенному
пользователю; токен нельзя считать секретом от того, кто имеет APK. Не публикуйте порт.
Если Windows блокирует запуск, не отключайте защиту, а сообщите о предупреждении.

Тесты: синтетические карты/ответы ADB, включая EOF, лимиты и фильтрацию приватных путей;
собственный дочерний процесс на Linux/Windows; frozen Tk/Frida self-check.
Это **не** тест MuMu runtime или workflow приложения. Доступ к UI-объектам не подтверждён.
