# DvkAssistant — единая линия приложения

Работаем в одной ветке и собираем один `DvkAssistant.exe`. Исправления не
создают отдельных нумерованных утилит или автоматических GitHub Releases.

## Что уже соединено

Одна выбранная видимая анкета → подтверждённое чтение числа друзей → при `< 50`
открытие чата → проверка полностью загруженной истории двумя стабильными
наблюдениями → отдельное окно подтверждения конкретного приветствия →
одна команда отправки → подтверждение возврата в поиск.
При `>= 50` или существующей переписке приветствия нет.
Количество друзей не выводится из координат, имени или случайного текста.
Отказ в подтверждении/Стоп/истечение срока останавливает проход; чат может
остаться открытым. Перед следующим запуском проверь экран вручную.

Новый журнал хранит просмотренные ID анкет, результат проверки, время и
состояние разрешённых попыток. Ранее просмотренные анкеты и получатели с
зарезервированной отправкой исключаются из дальнейшего выбора.
Имена, тексты переписки и токены в новый журнал не записываются.

## Запуск

1. Дождись успешного workflow **Build DvkAssistant**. Скачай артефакт
   **DvkAssistant-windows-x64**, распакуй целиком, сохрани папку `config` рядом
   с EXE. Исходный ZIP GitHub не содержит готового EXE.
2. Закрой прежние инструменты управления этим MuMu. Включи №4, открой поиск
   в уже установленной прежней копии ДругВокруг. APK не переустанавливай.
3. Пока выставь город и «Только онлайн» вручную. Приложение не утверждает,
   что автоматически применило или проверило эти настройки.
4. Запусти `DvkAssistant.exe`, укажи прежние ADB и папку `test-apks`.
   Сохраняются только эти пути, не согласия и не токен Gadget.
5. Разреши проверку и нажми **Проверить одну анкету**.
6. Если появился вопрос об отправке, проверь получателя и текст.
   **Отправить один раз** разрешает только показанное сообщение.
   По истечении 60 секунд разрешение недействительно. Перед вызовом отправки
   заново проверяется та же идентичность и пустая полностью загруженная история.
7. Появление успешного возврата обработчика — не подтверждение доставки.
   Результат проверь в приложении. Не пытайся повторять неизвестный исход.

## Конфигурация и локальные данные

- `config/cities.json` — единый список городов из ТЗ. Автосмена города ещё
  не подключена; файл пока валидируется, а не применяется к интерфейсу.
- `config/greetings.json` — активные редактируемые шаблоны приветствий.
  Изменения читаются перед новым проходом. Повреждённый/пустой конфиг
  блокирует запуск, а не подменяется незаметно встроенными значениями.
- `%LOCALAPPDATA%/DvkAssistant/settings.json` — только два пути.
- `%LOCALAPPDATA%/DvkAssistant/assistant.sqlite3` — журнал и защита от дублей.
- `%LOCALAPPDATA%/DvkAssistant/last-operation.json` — последний успешный
  результат транспорта, только фиксированные статусы и счётчики без ID/текстов.
  При ошибке до возврата транспорта прежний отчёт может остаться от старого
  прохода: ориентируйся на текущий статус окна, не на наличие файла.

Запись с `synchronous=FULL` завершается **до** передачи нативному коду
разрешения отправить сообщение. При исключении, аварии, потере ответа и даже
известном `not-invoked` резерв сохраняется: автоматического сброса нет.
Старые журналы `DvkRootless/new-ten.sqlite3` и `one-chat-check.sqlite3`
учитываются при разрешении получателя и не изменяются.
Старые безымянные `.dvk-ten-profile-pass.lock` / `.dvk-one-greeting.lock`
блокируют проход до отдельной сверки; программа не удаляет их.

Не удаляй базы/резервы для повтора. Очистка персональных данных и безопасное
архивирование резервов потребуют отдельного интерфейса; сейчас кнопки сброса
нет. Не присылай базы, папку test-apks или файл с токеном.

## Границы доступа

Используется прежний `TargetOnlyAdb`: только явный endpoint `127.0.0.1:5563`,
проверка boot ID, закреплённых APK и аутентифицированного Gadget.
Нет обращения к №0/5555, перебора устройств, root, переустановки, отключения
защиты, координатных нажатий, произвольных ADB-команд или произвольного JS.
Порт сам по себе не доказывает физический номер экземпляра.
Новый OS-lock не разрешает двум копиям DvkAssistant одновременно управлять
устройством и снимается ОС при завершении процесса. Старые утилиты этот lock
не знают — их нужно закрыть вручную.

## Честный статус готовности

Это первый соединённый участок основной программы, **не выполнение всего ТЗ**.
Следующие части ещё не подключены к новому окну:

- автоматическое применение/проверка города и фильтра «Только онлайн»;
- прокрутка ленты и определение её исчерпания;
- чтение ответов в нескольких разрешённых чатах и очередь черновиков;
- Telegram-уведомления и отдельные разрешения на передачу данных;
- определение установленной версии, восстановление интерфейса после сбоя;
- безопасная очистка/архивирование локальных данных;
- диагностика снимком экрана с контролем персональных данных.

Новые unit-тесты и реальные вызовы Frida→собственный C ABI-стенд проверяют
подтверждение/отказ, непустой чат, границу 50, пропуск просмотренных анкет,
черновой ID чата, смену идентичности, исключение обработчика, отказ записи
и запрет повторного прохода в одном скрипте. Это не запуск на Android.
Проверка packaged Tk EXE выполняется в Windows CI без аккаунтов.
Реальный прогон на пользовательском №4 остаётся обязательным до объявления
этого участка готовым к повседневной работе.

