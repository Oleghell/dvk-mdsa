# DvkAssistant — единая линия приложения

Работаем в одной ветке и собираем один `DvkAssistant.exe`. Исправления не
создают отдельных нумерованных утилит или автоматических GitHub Releases.

## Что уже соединено

Одна выбранная видимая анкета → подтверждённое чтение числа друзей → при `< 50`
открытие чата → проверка полностью загруженной истории двумя стабильными
наблюдениями → отдельное окно подтверждения конкретного приветствия →
одна команда отправки → подтверждение возврата в поиск.
При `>= 50` или существующей переписке приветствия нет.
Количество друзей не выводится из координат, имени или случайного текста.
Отказ в подтверждении/Стоп/истечение срока останавливает проход; чат может
остаться открытым. Перед следующим запуском проверь экран вручную.

Новый журнал хранит просмотренные ID анкет, результат проверки, время и
состояние разрешённых попыток. Ранее просмотренные анкеты и получатели с
зарезервированной отправкой исключаются из дальнейшего выбора.
Имена, тексты переписки и токены в новый журнал не записываются.

## Запуск

1. Дождись успешного workflow **Build DvkAssistant**. Скачай артефакт
   **DvkAssistant-windows-x64**, распакуй целиком, сохрани папку `config` рядом
   с EXE. Исходный ZIP GitHub не содержит готового EXE.
2. Закрой прежние инструменты управления этим MuMu. Включи №4, открой поиск
   в уже установленной прежней копии ДругВокруг. APK не переустанавливай.
3. Город пока выставь вручную. Для онлайн-фильтра есть отдельная кнопка
   **Включить только онлайн**. Она не запускает просмотр анкет или отправку.
   После успешного результата фильтра можно нажать **Проверить одну анкету**.
   Если операция с фильтром остановлена, проверь настройки вручную.
4. Запусти `DvkAssistant.exe`, укажи прежние ADB и папку `test-apks`.
   Сохраняются только эти пути, не согласия и не токен Gadget.
5. Разреши проверку и нажми **Проверить одну анкету**.
6. Если появился вопрос об отправке, проверь получателя и текст.
   **Отправить один раз** разрешает только показанное сообщение.
   По истечении 60 секунд разрешение недействительно. Перед вызовом отправки
   заново проверяется та же идентичность и пустая полностью загруженная история.
7. Появление успешного возврата обработчика — не подтверждение доставки.
   Результат проверь в приложении. Не пытайся повторять неизвестный исход.

## Подтверждённый запуск на MuMu №4

Пользователь подтвердил реальный запуск сборки из коммита
`6fbba8816a085f7d72512092c28009e5acc086b5`: открылась анкета, затем её чат,
затем окно подтверждения отправки. Эти переходы больше не считаются
проверенными только на синтетическом стенде. Отдельного подтверждения
доставки сообщения и восстановления после аварии из этого отчёта не следует.

## Пути без повторного ввода

По просьбе пользователя в окне сразу заполнены рабочие значения:

```text
ADB: C:/Users/XXX/Desktop/platform-tools/adb.exe
test-apks: C:/Users/XXX/Desktop/spam-dvk-main/test-apks
```

После запуска прохода пути сохраняются в
`%LOCALAPPDATA%/DvkAssistant/settings.json`. Они используются после закрытия
программы, обновления EXE и распаковки в другую папку. Если пользователь
выберет другие непустые пути, сохранённый выбор важнее этих начальных
значений. Пустые сохранённые значения не затирают рабочие начальные пути.
Согласие на чтение и подтверждение отправки вместе с путями не сохраняются.

## «Только онлайн» в основном окне

По присланным определениям реализована отдельная кнопка **Включить только онлайн**.
Открой поиск в №4, закрой остальные инструменты, дай разрешение в окне
и нажми кнопку. Переустановка APK не требуется. На запуске EXE ничего
автоматически не выполняется.

Команда проверяет доступный поиск, открывает его настройки, находит именно
видимую форму поиска людей, устанавливает `SearchFilter.OnlineOnly = true`,
обновляет форму через `ApplySearchFilter`, проверяет её готовность и валидность,
вызывает `SearchSettingsCardController.OnApplyButton`, затем после возврата
проверяет `SearchCM.SearchFilter.OnlineOnly`. Повторный вызов при уже включённом
фильтре не переключает его обратно: setter вызывается только для `false`.
Геокод, код региона и режим расстояния сравниваются до/после, но не экспортируются.
Город не выбирается и не подменяется. Остальные параметры не читаются напрямую.

Сигнатуры, владельцы методов/полей, типы параметров, виртуальные реализации,
точная идентичность контроллера/модели поиска и видимость формы проверяются
во время вызова. Неизвестный экран, переход, исключение или несовпадение
останавливают действие без автоматического повтора. Одна операция ограничена
180 кадрами, 6000 управляемыми вызовами, 100 мс на кадр, 16 с внутри скрипта
и 25 с транспортом. Используются прежний транспорт только №4 и общая блокировка
операций. Доступа к №0, профилям, чатам и отправке в этой команде нет.

**Стоп не является откатом.** Если setter или применение уже начались,
настройки могли измениться. Сообщение об успехе появляется только после
проверки итоговой модели поиска и успешной очистки транспорта. Это не
подтверждение сохранения после перезапуска Android-приложения.
При ошибке проверь текущий экран и настройки вручную.

Последний завершённый ответ записывается в
`%LOCALAPPDATA%/DvkAssistant/last-search-settings.json`: только статусы и флаги,
без имён/кодировок города, ID, переписки и токенов. При ошибке транспорта
старый файл может остаться; ориентируйся на текущий статус окна.

Этот новый путь проверен на собственном C ABI стенде: выключенный/уже включённый
фильтр, несоответствие сигнатур и виртуальных параметров, неготовая/невалидная
форма, исключения, потерянное применение, смена модели/местоположения, Стоп
во время setter и до запуска, переполненный код местоположения, отсутствие
утечек handles и вызовов вне UI-потока. **Реальный запуск этой кнопки на MuMu
пользователя ещё не подтверждён.** Проверенный ранее путь анкета → чат →
подтверждение сообщения остаётся отдельным и не изменён.

## Технические определения поиска и следующий этап города

В этом же `DvkAssistant.exe` добавлена кнопка **Подготовить настройки поиска**.
Сама эта кнопка **не применяет** город или онлайн-фильтр: она только читает
фактические определения моделей/обработчиков из установленного комплекта.
Рабочий проход анкета → чат → подтверждение не изменяется.

1. Закрой прежний EXE, распакуй обновлённую сборку целиком и открой
   `DvkAssistant.exe`. Пути уже заполнены и сохраняются как прежде.
2. Нажми **Подготовить настройки поиска**. MuMu можно не запускать.
   Галочка чтения чатов для этой кнопки не нужна: переписка не читается.
3. Дождись сообщения о сохранении сведений. Нажми **Открыть сведения**.
4. Приложи в чат только `search-settings-definitions.json`.
   По умолчанию он лежит в `%LOCALAPPDATA%/DvkAssistant/`.

Проверяются SHA256 прежних `base.apk` и `split-001.apk`. Из них извлекается
только `global-metadata.dat`, затем из таблиц определений выбираются имена
классов, полей и сигнатуры методов поиска/местоположения, а также объявленные
связанные типы. Методы не вызываются, значения полей и строковые литералы
не читаются. Параметры и родительские связи берутся из проверяемого v31 layout,
не угадываются. Ограничены число типов, глубина связей, методы/поля/параметры
и размер отчёта. Отсутствующие/неоднозначные типы и обрезка явно помечаются.

Нет ADB, подключения к MuMu, чтения конфигурации Gadget, токена, переписки,
ID пользователей, снимков, root или переустановки APK. Это не общий дамп
приложения и не весь APK. Журналы просмотра и отправок не изменяются.
Отчёт не загружается куда-либо автоматически: файл передаёт пользователь.
Все флаги применения города/онлайн в нём остаются `false`.

Определения онлайн-фильтра уже использованы для команды выше. Для города
ещё требуется связать реальную выдачу городов с выбранным результатом.
Нельзя подставлять придуманный ID города только по его названию. Наличие
метода в APK само по себе не доказывает успешное применение настройки.

## Конфигурация и локальные данные

- `config/cities.json` — единый список городов из ТЗ. Автосмена города ещё
  не подключена; файл пока валидируется, а не применяется к интерфейсу.
- `config/greetings.json` — активные редактируемые шаблоны приветствий.
  Изменения читаются перед новым проходом. Повреждённый/пустой конфиг
  блокирует запуск, а не подменяется незаметно встроенными значениями.
- `%LOCALAPPDATA%/DvkAssistant/settings.json` — только два пути.
- `%LOCALAPPDATA%/DvkAssistant/assistant.sqlite3` — журнал и защита от дублей.
- `%LOCALAPPDATA%/DvkAssistant/last-operation.json` — последний успешный
  результат транспорта, только фиксированные статусы и счётчики без ID/текстов.
  При ошибке до возврата транспорта прежний отчёт может остаться от старого
  прохода: ориентируйся на текущий статус окна, не на наличие файла.

Запись с `synchronous=FULL` завершается **до** передачи нативному коду
разрешения отправить сообщение. При исключении, аварии, потере ответа и даже
известном `not-invoked` резерв сохраняется: автоматического сброса нет.
Старые журналы `DvkRootless/new-ten.sqlite3` и `one-chat-check.sqlite3`
учитываются при разрешении получателя и не изменяются.
Старые безымянные `.dvk-ten-profile-pass.lock` / `.dvk-one-greeting.lock`
блокируют проход до отдельной сверки; программа не удаляет их.

Не удаляй базы/резервы для повтора. Очистка персональных данных и безопасное
архивирование резервов потребуют отдельного интерфейса; сейчас кнопки сброса
нет. Не присылай базы, папку test-apks или файл с токеном.

## Границы доступа

Используется прежний `TargetOnlyAdb`: только явный endpoint `127.0.0.1:5563`,
проверка boot ID, закреплённых APK и аутентифицированного Gadget.
Нет обращения к №0/5555, перебора устройств, root, переустановки, отключения
защиты, координатных нажатий, произвольных ADB-команд или произвольного JS.
Порт сам по себе не доказывает физический номер экземпляра.
Новый OS-lock не разрешает двум копиям DvkAssistant одновременно управлять
устройством и снимается ОС при завершении процесса. Старые утилиты этот lock
не знают — их нужно закрыть вручную.

## Честный статус готовности

Это первый соединённый участок основной программы, **не выполнение всего ТЗ**.
Следующие части ещё не подключены к новому окну:

- автоматическое применение/проверка города и фильтра «Только онлайн»;
- прокрутка ленты и определение её исчерпания;
- чтение ответов в нескольких разрешённых чатах и очередь черновиков;
- Telegram-уведомления и отдельные разрешения на передачу данных;
- определение установленной версии, восстановление интерфейса после сбоя;
- безопасная очистка/архивирование локальных данных;
- диагностика снимком экрана с контролем персональных данных.

Новые unit-тесты и реальные вызовы Frida→собственный C ABI-стенд проверяют
подтверждение/отказ, непустой чат, границу 50, пропуск просмотренных анкет,
черновой ID чата, смену идентичности, исключение обработчика, отказ записи
и запрет повторного прохода в одном скрипте. Это не запуск на Android.
Проверка packaged Tk EXE выполняется в Windows CI без аккаунтов.
Открытие анкеты, чата и окна подтверждения уже проверено пользователем на №4.
Доставка, остальные ветви отказа и восстановление всё ещё требуют живой проверки
до объявления всего участка готовым к повседневной работе.
