# Проверочная сборка DvkAssistant 0.4.6 — чтение без отправки

## Что делает «Старт»

На MuMu №4 проходит путь: анкеты → список сообщений → до пяти разрешённых
диалогов → список → анкеты. Открываются только чаты с непрочитанными
сообщениями среди активных привязок журнала и явно добавленных чатов
только для чтения. Для старых привязок терминальные, отказные и отмеченные
для ручной проверки диалоги не выбираются. Повторного открытия того же собеседника в одном проходе нет.
Прокрутки, новых приветствий и смены города нет.

Перед чтением проверяются аккаунт, собеседник и чат. В каждом диалоге читается
не более 20 сообщений из уже доступного снимка истории, без прокрутки и
запроса дополнительных страниц. Чтение требует подтверждённой готовности
истории и двух совпадающих снимков. Большой или нестабильный снимок приводит
к остановке, а не к обходу ограничений. Имена не читаются.

**Сообщения не отправляются. Telegram не используется, даже если включён
в сохранённых настройках.** Старый автоматический режим из «Старт» недоступен.
Открытие диалога может изменить отметку «прочитано» и порядок диалогов
в самом приложении. «Без отправки» не означает отсутствие эффектов интерфейса.

## Только непрочитанные диалоги

До открытия читается только счётчик `DV.Messages.Chat.get_UnreadCount`.
Точный метод взят из офлайн-каталога: без параметров, нестатический, `Int32`.
При нуле чат пропускается без открытия и без чтения сообщений. При положительном
значении повторно проверяются экран, ячейка и привязка, затем счётчик читается
ещё раз непосредственно перед открытием. Если он изменился, выбор отменяется.

При отсутствующей/неподходящей сигнатуре, отрицательном значении или ошибке
чтения проход останавливается. Перехода к открытию всех чатов нет. Последний
отправитель, текст последнего сообщения и положение строки не заменяют
счётчик непрочитанных. Общий счётчик вкладки и фильтры только для чатов
со включённым звуком не используются.

Если среди видимых привязанных чатов непрочитанных нет, ни одна переписка
не открывается: программа возвращается к анкетам. Уже прочитанный ответ
Александра не запустит обработку снова — нужен новый непрочитанный ответ.
Привязки сохраняются, удалять или заново привязывать старые чаты не нужно.
При привязке нового чата его ручное открытие также может отметить входящие
прочитанными; привязка действует для следующих непрочитанных сообщений.

## Привязать уже открытый чат

1. Вручную открой нужную переписку в MuMu №4, например чат с Александром.
2. Нажми «Привязать чат для чтения» и подтверди именно текущий открытый чат.
3. Не переключай экран до результата. Проверяются только аккаунт, собеседник
   и ID существующего серверного чата. Сообщения при привязке не читаются.
4. После успеха вручную вернись к анкетам и нажми «Старт».

Привязка хранится в отдельной таблице `read_only_bindings`. Она не создаёт
и не меняет записи `manual_actions` и не разрешает отправку. Повторная
привязка того же чата безопасна; другая привязка того же собеседника
автоматически не заменяется. Старые базы удалять или редактировать не нужно.

Для таких чатов отчёт показывает только счётчики чтения и `manual-review` /
`preview_actions.none`: цепочка ответов не анализируется и не запускается.
Общий лимит прохода остаётся пять видимых диалогов, без прокрутки.
Кнопка привязки, в отличие от «Старт», записывает только это явное согласие.

## Анализ без изменения журнала

Исходный SQLite-журнал открывается через `mode=ro` и `query_only=ON`. Его
согласованный снимок копируется только в оперативную память. Для ограничения
памяти журнал больше 64 МиБ не принимается. Копия на диск не записывается.
Если журнала нет, он не создаётся, устройство не используется.

Существующая модель цепочки вычисляет предполагаемый этап и вид следующего
действия в этой временной копии. Изменения этапов и гипотетические резервы
существуют только в памяти и исчезают после проверки. Исходный журнал,
этапы, резервы отправок и уведомления не меняются. Методы отправки и передачи
контактов не вызываются; Telegram-секреты при «Старт» не загружаются.

Результат анализа — не разрешение на отправку. Очерёдность не угадывается
по позициям или ID сообщений. Если исходное приветствие не подтверждено,
история пустая или снимок содержит 20 сообщений (нет запаса для проверки
отправки), результат анализа — `manual-review`, без предложения отправить ответ.

## Как проверить

1. Дождись успешной **Build DvkAssistant** для `fix/dialog-selection-diagnostics`.
2. Распакуй новый `DvkAssistant-windows-x64` отдельно от прежней сборки.
3. Сохрани прежние базу и журналы. В настройках укажи прежние ADB и `test-apks`.
4. Используй тестовый аккаунт с существующими активными привязками журнала.
5. На MuMu №4 открой анкеты, закрой фильтры и диалоги.
6. Нажми «Старт» один раз, не управляй экраном до завершения.
7. Пришли `%LOCALAPPDATA%/DvkAssistant/messages-pass-check.json`.

Если подходящих видимых диалогов меньше пяти, проверятся только они. Это
не полный обход лички. Устройство №0 не используется. При ошибке или «Стоп»
экран может остаться в личке/диалоге: автоматического отката и повторов нет.

## Отчёт без переписки

- `tool_version: 0.4.6`, `mode: visible-journal-dialog-read-check`;
- `read_only_check: true`, `unread_only: true`, `dialog_limit: 5`, `journal_read_only: true`;
- `unread_dialogs_verified`: сколько открытий имели подтверждение непрочитанных
  до входа; `read_rows_skipped`: проверки строк привязанных чатов с нулевым
  счётчиком. Повторные проверки строк считаются отдельно, это не уникальные чаты;
- `dialogs_opened`, `dialogs_read`, `dialogs_processed`: открыто, прочитано,
  завершено с подтверждённым возвратом в список;
- `observed_messages`, `incoming_messages`, `outgoing_messages`,
  `nontext_messages`: только суммарные счётчики;
- `states`: предполагаемые этапы; `preview_actions`: количество предложений
  `question`, `contact` и `none`. Тексты ответов не включаются;
- `chat_content_read_attempted` и `chat_content_read` различают попытку чтения
  и получение проверенного снимка;
- нулевые счётчики отправки, `telegram_used: false`;
- `return_verified`: подтверждён ли конечный возврат к анкетам;
- `last_navigation` и `last_reader`: только фиксированные категории и счётчики
  остановки, без произвольного текста ошибок.

В отчёте нет переписки, имён, контактов, ID собеседников и токенов. Успешная
навигация и чтение пяти диалогов подтверждены отчётом 0.4.5 на MuMu №4.
Новый фильтр непрочитанных этой сборки пока проверен только синтетически
и ещё требует проверки на устройстве. Успех не подтверждает готовность отправки или общего цикла.

## Для разработчика

Точка входа: `assistant_app.py` → `assistant_cycle.start` →
`assistant_read_check.run_read_check`. Общая блокировка удерживается на весь
проход. `one_chat_device.capture` получает точную разрешённую привязку без
`read_name`. При открытии всегда передаётся `unread_only=True`; отсутствие
подтверждения фильтра запрещает чтение истории. `Chain.consume` вызывается
для старых привязок только на SQLite-копии в памяти,
с `contact_notifications=False`; `step`, `finish`, `notify` не вызываются.
Старый одно-диалоговый navigation-only режим сохранён отдельно для тестов.

Проверки стабильности выбранного диалога сохранены. Обновление оболочки списка
допустимо только при сохранении класса, числа строк и той же ячейки на выбранной
позиции. Привязка чата проверяется отдельно. Временные ссылки обхода освобождаются
после каждой проверки видимости и повторного поиска контроллера. Лимит 64
одновременных временных ссылок и ограничения глубины не увеличены. Те же области
жизни используются фиксированным адаптером чтения.

Локальные тесты без аккаунта:

```text
python rootless-unity/run_unit_tests.py
cc -shared -fPIC -O0 -pthread rootless-unity/fixtures/dialog_browser_fixture.c -o browser_fixture.so
python rootless-unity/smoke_dialog_browser.py ./browser_fixture.so
cc -shared -fPIC -O0 -pthread rootless-unity/fixtures/one_chat_fixture.c -o one_chat_fixture.so
python rootless-unity/smoke_one_chat.py ./one_chat_fixture.so
```
