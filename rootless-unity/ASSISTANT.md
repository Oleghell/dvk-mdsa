# DvkAssistant

## Текущий статус — проход диалогов, ещё не общий цикл

Главное окно: **Старт / Стоп / Настройки**, без дополнительных тестовых кнопок.
«Старт» теперь **может автоматически отправлять ответы** по согласованной
цепочке, без подтверждения каждого сообщения. Никаких отправок при запуске
окна или сохранении настроек нет.

### Как проходит один запуск

1. Открывается личка с экрана анкет на MuMu №4.
2. Из видимых строк выбираются только диалоги, связанные с журналом
   `manual_actions` и текущим аккаунтом. Посторонние строки, групповые и
   черновые чаты не открываются для чтения/ответов.
3. Привязка аккаунт + собеседник + серверный чат проверяется до чтения истории.
   Выбранная строка повторно сверяется перед открытием; открытый чат сверяется
   с тем же объектом и ID после перехода. Нет координат и имитации нажатий.
4. Читается полностью загруженный, дважды стабильный снимок не более 20 сообщений.
   Новые ответы продолжат цепочку: приветствие → «Как дела?)»/«Как настроение?)»
   → подходящий положительный ответ → предложение перейти в мессенджер.
5. Попытка этапа сохраняется в FULL-транзакции до вызова обработчика. Перед
   отправкой заново проверяется тот же снимок. Возврат обработчика не считается
   доставкой; появление исходящего проверяется отдельно, до трёх чтений.
6. Выполняется возврат в список, затем следующий привязанный видимый диалог.
   Один собеседник обрабатывается не более одного раза за проход, максимум 32.
7. В конце выполняется возврат к анкетам. Проход заканчивается; сам не повторяется.

Обычные ответы не пересылаются в Telegram. Явный отказ завершает цепочку.
Неясные ответы, изменения истории и неподтверждённое исходное приветствие
блокируют цепочку этого диалога; разрешение новой отправки не выдумывается.
Транспортная ошибка, несоответствие привязки или неизвестный результат отправки
останавливают проход. «Стоп» запрещает дальнейшие действия, но не откатывает
уже сделанные. Неизвестные попытки не повторяются и после перезапуска.

### Что сделать

1. Дождись успешного **Build DvkAssistant**, распакуй `DvkAssistant-windows-x64`
   отдельно. Проверь ADB и прежнюю папку `test-apks`. Переустановка не нужна.
2. Если нужны контакты в Telegram, проверь галочку и локальные настройки бота
   в «Настройках». Токен не отправляй в чат или технический отчёт.
3. На **MuMu №4** открой поиск анкет, закрой фильтры/открытый диалог.
4. Нажми **Старт** один раз. Не управляй экраном до завершения или остановки.
5. Пришли **messages-pass-check.json** из `%LOCALAPPDATA%/DvkAssistant/`.
   При ошибке экран может остаться в личке/диалоге — проверь его вручную.

Если в журнале нет активных привязок, программа сообщает об этом и никому не
отвечает. Не удаляй и не пересоздавай базы для обхода ограничений.
В отчёте только счётчики, категории этапов и фиксированные проверки; нет
снимков истории, имён, контактов, ID людей, APK и токенов.
`reply_submission_calls` — число вызовов адаптера после сохранённого резерва,
а не число доставленных сообщений. `reply_handler_returns` тоже не доставка.

### Границы готовности

Переход анкеты → список личных сообщений → те же анкеты подтверждён на №4
пользовательским отчётом версии 0.4.1. Выбор строки, возврат из отдельного чата,
интеграция чтения/цепочки и контактные уведомления проверены синтетически.
Работа всего нового прохода на реальном MuMu пока **не подтверждена**.
Новые приветствия, смена городов, прокрутка лички и периодический обход ещё не
подключены. Поле интервала в настройках зарезервировано для будущего цикла и
не запускает таймер в этой сборке. Нельзя считать видимый список всей личкой.

## Целевой алгоритм

Город + онлайн → новые подходящие анкеты → приветствия → личка → продолжение
цепочек при новых ответах → другой город. Старые диалоги также проверяются
по интервалу. Переходы должны проверять текущий экран и фактический результат.
Нет сообщений без ответа, повторов при неизвестном исходе и сброса журналов.

## Telegram: только свой контакт и имя

В библиотеке автоматической цепочки обычные входящие больше не создают
Telegram-уведомлений. Пересылаются только имя проверенного текущего собеседника
и контакт, который он явно сообщил как свой. Отдельный контакт без пояснений
принимается только как ответ на предложение перейти в мессенджер.
Чужие/цитируемые контакты, отрицание принадлежности, отказ и неясность не
вызывают передачи. Достоверность принадлежности не гарантируется распознаванием;
неоднозначный случай остаётся для ручного разбора.

Имя читается проверенным `User.get_Name` только после сверки ID и двух
стабильных снимков той же переписки. Нет извлечения контактов из анкеты.
Полная переписка не пересылается. Контактная очередь хранится отдельно в
`chain_contact_outbox`, только под Windows DPAPI, без plaintext fallback.
Перед сетевым вызовом попытка фиксируется; ошибка/таймаут не разрешают повтор.
Старые обычные уведомления из `chain_notifications` не отправляются.

Контактная библиотека и чтение имени подключены к ограниченному проходу
диалогов, но ещё не проверены через него на реальном MuMu. Уведомления
отправляются только при включённой настройке контактов, один раз. Настройки бота сохраняются только локально через DPAPI:
`%LOCALAPPDATA%/DvkRootless/telegram.dpapi`.

## Для разработчика

Прежний интерфейс сохранён в `assistant_legacy.py` только для регрессионных
тестов; он не является точкой входа EXE. Рабочий entry point — `assistant_app.py`.
Журналы просмотров, резервов отправки и этапов не удаляются и не сбрасываются.

```text
python rootless-unity/run_unit_tests.py
python rootless-unity/smoke_one_chat_name.py ./one_chat_fixture.so
python rootless-unity/smoke_dialog_navigation.py ./dialog_fixture.so
python rootless-unity/smoke_dialog_browser.py ./browser_fixture.so
```
