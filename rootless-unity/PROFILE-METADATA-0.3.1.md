# ДругВокруг 0.3.1 — точная проверка метаданных, без нажатий

## Почему отдельная проверка

В пользовательском отчёте 0.3.0 соединение с Gadget и базовые метаданные IL2CPP успешно проверены. Новый профильный сценарий остановился на этапе `metadata`, до установки наблюдателя: `managed_calls=0`, `observed_calls=0`, `open_attempted=false`, `close_attempted=false`. Причина пока не установлена: общий `native-call-failed` не показывает конкретную проверку. Это не доказательство ошибки ADB, входа в аккаунт или необходимости root.

Версия 0.3.1 повторяет **только подготовку метаданных** 0.3.0 и добавляет 81 фиксированную контрольную точку. Она **не выполняет сценарий открытия профиля**, не устанавливает UI-наблюдатель, не вызывает managed-методы, не читает объекты анкет и не выполняет нажатия. Даже если все проверки пройдут, программа остановится после подготовки метаданных и очистки подключения.

Это дополнительная диагностика, не обещание, что открытие профиля уже исправлено. Рабочая версия фильтров 0.2.3 и код профиля 0.3.0 сохранены.

## Запуск

1. Распакуйте `Dvk-rootless-profile-metadata-0.3.1-windows-x64.zip` отдельно. Старые версии и `test-apks` не удаляйте.
2. Запустите оба MuMu. На тестовом **#4 / 127.0.0.1:5563** оставьте уже установленный ДругВокруг открытым. Рабочий **#0 / 5555 не изменяется**.
3. Запустите **Dvk-rootless-profile-metadata.exe**, укажите прежние `adb.exe` и `test-apks`.
4. Отметьте разрешение проверки метаданных и нажмите **«Проверить метаданные — без нажатий»**. Дождитесь завершения.
5. Прикрепите **rootless-profile-metadata-0.3.1.json**, созданный рядом со старой папкой `test-apks`. Исходный отчёт 0.3.0 не перезаписывается.

**APK не обновлять, не удалять и не переустанавливать. Root не нужен. OCR, снимков экрана, CV и координат нет.** Нет сообщений, лайков, подарков, покупок, извлечения токенов или переноса аккаунта. Эта проверка сама не открывает профили и не создаёт визитов посредством UI-действий. Как при любом выполнении native-кода, возможен сбой или замедление тестового приложения.

## Что будет в отчёте

`gadget.uikit_root.profile_metadata`:
- `checkpoint`: одна из закрытого списка точек — базовый класс/метод, вложенные типы SearchTableView, конкретная профильная сигнатура или `ready`;
- `failure`: только `none`, `metadata`, `signature`, `hierarchy`, `return-type` либо `native-call-failed`; текст исключения не экспортируется;
- `nested_types_found`: число найденных **семи ожидаемых** вложенных типов, не данные пользователя;
- `method_found`, ожидаемые и фактические arity/return-kind, признаки соответствия владельца и класса возврата. Если факт ещё не проверялся, значение `null`.

При успехе: `profile-metadata-ready`. Это значит только, что подготовка метаданных прошла; поиск видимой анкеты, её открытие, проверка пользователя и возврат **не проверялись**. При остановке контрольная точка позволит исправлять конкретное несовпадение вместо повторения общего теста вслепую.

Нет сырых имён неизвестных классов, исключений, адресов памяти, PID, boot ID, полных путей, токенов, текстов, ID, фото и переписок. Исходные APK, ключи и полные метаданные не публикуются.

## Реализация и проверка

Новые файлы: `profile_metadata.py`, `diagnose_profile_metadata.py`, `smoke_profile_metadata.py`, `tests/test_profile_metadata.py`, эта инструкция и отдельный workflow `rootless-profile-metadata.yml`.

Обновлены `diagnose_device.py` (отдельный явный флаг и отдельный файл отчёта), `fixtures/profile_navigation_fixture.c` (дополнительные синтетические ошибки), README. Несовместимые сочетания metadata-only с UI-режимами отклоняются до соединения. Исходники `uikit_navigation.py`, `navigate_device.py`, `uikit_profile_navigation.py`, `navigate_profile_device.py` не менялись.

Подготовка использует те же IL2CPP metadata API и проверки сигнатур, что 0.3.0, с остановкой после `finally` очистки потока. Код UI-наблюдателя и исполняемая часть навигации отсутствуют в новом probe. Старые режимы остаются отдельными. Сборка не содержит APK или частных ключей.

Синтетические проверки настоящей Frida/C ABI: успешные метаданные; неверная arity открытия; неверный параметр индекса; неверный возврат Iterator.MoveNext; отсутствующий вложенный тип; неверный владелец вложенного типа; отсутствующий AvatarView; неверный возврат getter; присоединение/отсоединение metadata-потока. Во всех девяти сценариях **ноль UI-вызовов, открытий, закрытий, чтений VisibleCells и GC handles**.

185 unit-тестов включают запрет UI-действий, закрытую схему отчёта, разделение устройств и сохранение старых режимов. Старые сценарии профиля и навигации также запускаются в CI. **Результат этой версии на пользовательском MuMu ещё не получен.**

Из исходников: Python 3.13 с Tk, `pip install frida==17.24.1`, затем `python rootless-unity/diagnose_profile_metadata.py`.
