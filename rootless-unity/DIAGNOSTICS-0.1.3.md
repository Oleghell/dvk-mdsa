# Диагностика 0.1.3 — вызовы IL2CPP API, без root и OCR

Отчёт 0.1.2 подтвердил ARM64 Gadget в MuMu x86_64 с libnb и наличие четырёх
глобальных IL2CPP-экспортов. Список модулей и карта файлов движок по именам не
обнаружили. Доступность символа ещё не доказывает работоспособность вызова.

Новая версия впервые проверяет фиксированные нативные C API: доступен ли IL2CPP
домен, перечисляются ли сборки и существуют ли заранее известные классы UI и
методы. Это **не проверка объектов экрана и не готовая автоматизация**.

## Как запустить

1. Распакуйте новый публичный ZIP, запустите `Dvk-rootless-diagnostics.exe`.
2. Оставьте оба MuMu запущенными: рабочий #0 (5555), тестовый #4 (5563).
3. Откройте уже установленный тестовый ДругВокруг на #4. Вход в аккаунт не нужен.
4. Выберите прежний `adb.exe` и **старую частную папку `test-apks`**.
5. Нажмите **«Проверить IL2CPP API — без нажатий в приложении»**.
6. Пришлите `rootless-diagnostics-0.1.3.json`, созданный рядом с `test-apks`.

APK не менялся. Ничего не удаляйте и не переустанавливайте. В публичном архиве
нет APK, токена и ключей. Старая частная папка нужна для проверки хешей и локальной
аутентификации с Gadget. Рабочее устройство #0 не изменяется.

## Важное отличие от 0.1.2

Это уже не только поиск символов: выполняются девять фиксированных C API.
Если поток Frida не зарегистрирован в IL2CPP, он временно регистрируется через
thread_attach; в finally снимается только собственная регистрация. Уже
зарегистрированный поток не снимается. Поэтому тест не является полностью
пассивным: он выполняет служебные операции runtime и чтение метаданных в памяти.
**Возможны зависание или сбой тестового приложения при несовместимости ARM-трансляции.**
Ограничения цикла и таймер RPC не гарантируют прерывание зависшего нативного вызова.
Если приложение закрылось или тест завис, не повторяйте его много раз — пришлите
полученный отчёт и опишите поведение. Автоматического повторения нативного RPC нет.

Не выполняются managed-методы, runtime_invoke, инициализация managed-классов,
чтение полей/значений UI, поиск экземпляров, перехваты, делегаты и команды интерфейса.
Названия get_text/get_onClick в отчёте означают **лишь наличие метаданных метода**;
они не вызываются. Unity scene API с фонового потока не вызываются.

## Ограничения данных и доступа

- Только #4 (5563); перед тестом подтверждается отличие от #0 (5555).
- Только ARM64/Linux runtime для нового нативного RPC; другие архитектуры не вызываются.
- Фиксированный список 9 экспортов, 16 типов и 12 сигнатур методов.
- До 2048 сборок; имя читается не более 192 байт, неизвестные имена не возвращаются.
- Бюджет обхода 2,5 секунды между вызовами; общий отменяемый RPC до 20 секунд.
- Отчёт содержит флаги и счётчики, не адреса, токены, пути, аккаунты или содержимое чатов.
- Нет root, OCR, скриншотов, координатных нажатий, сообщений, покупок, обхода защиты.
- Нет установки, удаления, clear-data, запуска/остановки приложения через ADB.
- Временный loopback ADB forward очищается. Порт нельзя публиковать в сеть.

`metadata-ready` означает, что ограниченный обход метаданных завершился, **не то,
что все типы найдены или кнопками уже можно управлять**. Смотрите known_types и
known_methods. Ошибки и неполные результаты сохраняются отдельно. Дальше потребуется
проверить главный поток Unity и конкретные объекты интерфейса; в этой версии этого нет.

## Проверки сборки

Unit-тесты проверяют ограничения ADB, разделение устройств, формат/приватность отчёта
и фиксированный контракт RPC. Linux/Windows smoke-тесты исполняют точный JS в собственном
синтетическом дочернем процессе. Отдельная синтетическая C-библиотека проверяет реальные
NativeFunction bindings, null domain, лимит/ноль сборок и снятие только собственной
регистрации потока. Она не входит в EXE. Frozen Tk/Frida self-check не обращается к устройству.
Эти проверки **не заменяют запуск в MuMu с ARM-трансляцией**.
