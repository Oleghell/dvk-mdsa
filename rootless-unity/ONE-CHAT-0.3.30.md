# 0.3.30 — чтение одного тестового чата, без отправки

Отдельный инструмент **Dvk-one-chat-check.exe**. Это следующий шаг после
подтверждённых сигнатур 0.3.29, не новая рассылка и не готовые автоответы.

## Что сделать

1. Скачай ZIP prerelease **rootless-one-chat-v0.3.30** или артефакт
   **Dvk-one-chat-check-0.3.30-windows-x64** из успешного workflow
   **Build one-chat read-only checker 0.3.30**. Распакуй в новую папку.
   Старый EXE закрой. Полный ZIP исходного кода не содержит готового EXE.
2. Включи только тестовый MuMu **#4 / 5563** с прежним тестовым приложением.
   Рабочий #0 можно оставить выключенным. Ничего не переустанавливай.
3. В тестовом приложении вручную открой переписку со своим вторым аккаунтом.
   Используй короткую историю (не больше 20 сообщений), без личных данных.
   Пустое поле ввода, клавиатуру закрой. Не переключай экран во время чтения.
   Само ручное открытие чата может пометить сообщения прочитанными в приложении.
4. Запусти **Dvk-one-chat-check.exe**. Выбери `adb.exe` и прежнюю папку
   `test-apks`. Токен повторно вводить не нужно; не присылай эту папку.
5. Отметь подтверждение, что это твой второй аккаунт. Нажми
   **«1. Привязать открытый чат»**. Сообщения на этом шаге не читаются.
   В локальном окне увидишь ID текущего аккаунта, собеседника и чата.
   Подтверди привязку только для своих аккаунтов. Автоматической перепривязки нет.
6. Нажми **«2. Проверить · без отправки»**. Первое чтение запоминает уже
   имеющуюся историю как исходную: старые ответы НЕ считаются новыми событиями.
7. Со второго аккаунта вручную отправь **одну новую текстовую реплику**,
   например «Проверка связи». Дождись её появления в открытом тестовом чате.
   Нажми **«Проверить»**: ожидается **«Новых входящих: 1»**.
8. Нажми «Проверить» ещё раз, затем закрой/открой программу и повтори проверку.
   Без новых сообщений ожидается **«Новых входящих: 0»** в обоих случаях.
   Вторично привязывать чат после перезапуска не нужно.
9. Пришли только **rootless-one-chat-0.3.30.json** рядом с выбранной папкой
   `test-apks`. Это последний результат проверки, предыдущий перезаписывается.
   Можно сохранить копии JSON после шагов 6–8 под разными именами.

## Если проверка остановилась

Пришли обезличенный JSON, не повторяй рассылку. Нельзя удалять старый журнал,
снимать lock, менять порт, переустанавливать приложение или отключать защиту ОС.
Неизвестный/другой чат, draft-чат без положительного серверного ID,
неполная/меняющаяся история, больше 20 сообщений или несовместимые сигнатуры
останавливают проверку без отправки. Не удаляй сообщения ради прохождения
лимита. Отредактированное или удалённое сообщение после исходного замера
также требует ручного разбора; это не новый ответ.

## Что гарантирует код, а что ещё проверяется

- Фиксированный тестовый endpoint с TargetOnlyAdb; нет обращения к #0 / 5555,
  перечисления устройств, выбора другого endpoint, установки или запуска APK.
  Сохранены проверка прежнего закреплённого APK bundle, токен Gadget и
  сверка boot ID до/после операции. Номер порта сам по себе не доказывает номер MuMu.
- Нужна одна аутентифицированная сессия Gadget ожидаемого процесса. Нет повторов
  после ошибки авторизации/чтения и произвольных RPC.
- До первого чтения тел сообщений проверяется точное совпадение сохранённых
  ID аккаунта, собеседника и чата. Проверяются личный действующий недрафтовый
  чат, UIKit main thread, видимость и неизменность объектов.
- Читаются только фиксированные getter-методы. История должна быть полностью
  загружена, два одинаковых снимка с интервалом не менее секунды. Каждый
  элемент проверяется по ID, автору, ID чата и IsMine. Порядок коллекции НЕ
  объявляется хронологическим, ID не сортируются как время.
- Максимум 20 сообщений, 2048 UTF-16 единиц на текст и 16384 на снимок.
  Сохранены прежние ограничения кадров, вызовов, времени и GC handles.
  Нет прокрутки, запроса дополнительных страниц, нажатий или изменения черновика.
- Состояние отдельно в `%LOCALAPPDATA%/DvkRootless/one-chat-check.sqlite3`:
  привязка ID и солёные HMAC-отпечатки сообщений, без текстов. Перезапуск не
  превращает уже наблюдавшееся сообщение в новое. Речь о дедупликации наблюдения,
  не о гарантии обработки события внешним сервисом.
- Сырые тексты временно присутствуют в памяти устройства/процесса во время
  чтения. Полное стирание управляемой памяти не обещается. SQLite содержит
  идентификаторы привязки: не присылай БД, её WAL/SHM, дампы или снимки экрана.
- JSON содержит только фиксированные статусы/счётчики, без ID, текстов, имён,
  boot ID, ключей и произвольных исключений. При сбое чтение могло начаться,
  но результат не подтверждён. Нет фонового старта или фонового наблюдения.
- Старые `new-ten.sqlite3`, `reply-review.sqlite3` и Telegram не используются.
  Нет отправки приветствий/ответов, контактов, новой партии или смены города.

Проверки на синтетических объектах и упаковка Windows не доказывают работу
реального MuMu. После выпуска требуется один ручной запуск по инструкции.
Не запускай на обычных пользователях вместо согласованного тестового аккаунта.

## Проверки разработчика

```sh
python rootless-unity/run_unit_tests.py
cc -shared -fPIC -O0 -pthread rootless-unity/fixtures/one_chat_fixture.c -o one_chat_fixture.so
python rootless-unity/smoke_one_chat.py ./one_chat_fixture.so
```

Native ABI-тест использует только вымышленные локальные объекты, не подключается
к Android и не содержит секретов. Отдельно проверяются неверный чат/автор,
дубли ID, лимит текста, смена собеседника, пустая история, несовместимая сигнатура,
отсутствие отправок и утечек handles, дедупликация после перезапуска,
неизменность старых журналов и очистка подключения при ошибках.
