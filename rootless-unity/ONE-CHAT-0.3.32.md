# 0.3.32 — локальный предпросмотр в одном своём тестовом чате

**Ничего не отправляет и не вставляет в поле ввода.** Отдельный инструмент
`Dvk-one-chat-check.exe`, только для прежнего привязанного чата со своим вторым
аккаунтом в тестовом MuMu #4 / endpoint 5563. Не рассылка и не готовые автоответы.

## Запуск после 0.3.31

1. Закрой старый EXE. Скачай ZIP prerelease `rootless-one-chat-v0.3.32` и распакуй
   в новую папку. Запусти новый `Dvk-one-chat-check.exe`.
2. Выбери прежние `adb.exe` и папку `test-apks`, отметь подтверждение своего
   второго аккаунта. Ничего не переустанавливай; токен повторно вводить не нужно.
3. Вручную открой **тот же уже привязанный чат** в тестовом приложении.
   Поле ввода пустое, клавиатура закрыта. Не переключай экран во время чтения.
   **Не привязывай чат заново и не удаляй БД или старые журналы.**
4. Нажми **«2. Проверить · без отправки»**, пока новых сообщений нет.
   Старая история не должна создавать черновик. Если есть свежие события,
   они будут учтены этим контрольным чтением; это ещё не проверка шага 5.
5. Со своего второго аккаунта отправь ровно одну новую текстовую реплику:
   **Тест предпросмотра**. Дождись её появления и один раз нажми «Проверить».
6. В отдельном блоке программы ожидается **«Новый тестовый черновик: Как дела?)»**.
   В JSON: `new_incoming: 1`, `preview_created: true`,
   `preview_available: true`, `preview_reason: new-test-text`.
   Сохрани копию отчёта **rootless-one-chat-0.3.32.json** рядом с выбранной папкой
   `test-apks` и пришли её. Текстов чата и самого черновика в JSON нет.
7. Без новых сообщений повтори проверку. Ожидается `new_incoming: 0`,
   `preview_created: false`, `preview_available: true`, а в окне —
   **«Сохранённый тестовый черновик (не новое событие)»**.
8. Закрой и открой программу, снова проверь тот же чат без новых сообщений.
   Ожидается тот же сохранённый черновик, не новое событие. Пришли второй отчёт.
   Последний JSON перезаписывается каждым запуском проверки: сохраняй копии.

Само ручное открытие чата может пометить сообщения прочитанными в приложении.
Программа не создаёт сообщений, не нажимает кнопки и не меняет черновик Android.

## Что именно проверяет демонстрация

Это **только фиксированный тестовый ответ на одну контрольную фразу**.
Не анализ настроения, не восстановление стадии разговора по старой переписке,
не извлечение контактов и не подтверждение возможности безопасных автоответов.
Другие сообщения учитываются, но требуют ручного ответа и не создают черновик.
Регистр и пробелы по краям контрольной фразы не существенны.

- Предложение появляется только при одном новом входящем с контрольной фразой
  и отсутствии новых исходящих в том же проверенном снимке.
- Несколько новых входящих, новое исходящее, нетекстовое или другое текстовое
  сообщение скрывают предыдущий черновик и требуют ручной проверки.
  Эти наблюдения учитываются: повторное нажатие не превратит их в новый черновик.
- Исходный снимок никогда не создаёт предложение из старых сообщений.
- Повтор/перезапуск не создаёт новое событие, но после успешной проверки того же
  чата показывает уже сохранённое предложение с явной пометкой.
- Порядок коллекции **не считается хронологическим**; ID не сортируются как время.
  Это не многошаговый сценарий: каждое новое тестовое событие показывает ту же
  демонстрационную фразу. Перехода к просьбе контактов или Telegram нет.
- При остановке, отмене или ошибке записи отчёта черновик скрывается. После сбоя
  записи повтори проверку без новой реплики: успешно сохранённый черновик можно
  восстановить, но он будет помечен сохранённым, а не новым.

## Совместимость и приватность

Сохранена БД `%LOCALAPPDATA%/DvkRootless/one-chat-check.sqlite3`. Новая версия
добавляет отдельную таблицу фиксированного кода черновика и HMAC-отпечатка снимка.
Привязка и ранее учтённые сообщения 0.3.31 не сбрасываются. Учёт события и запись
кода предпросмотра — одна SQLite-транзакция. Тел сообщений и текста предложения
в БД нет; предложение восстанавливается из фиксированного кода в программе.
Старый читатель не знает новых полей: не запускай 0.3.31 параллельно с этим тестом.
Если история была учтена вне предпросмотра, несоответствующий старый черновик
скрывается при следующей проверке.

БД всё ещё содержит ID привязки. Не присылай БД/WAL/SHM, папку `test-apks`,
токены, дампы и снимки переписки. Сырые тексты кратковременно читаются в память;
полное стирание управляемой памяти не обещается. JSON содержит только счётчики,
фиксированные коды и флаги, не тексты, ID, имена или произвольные исключения.

Сохранены все ограничения читателя 0.3.31: один фиксированный тестовый endpoint,
проверка прежнего APK bundle, аутентификация Gadget, проверки boot ID до/после,
UIKit main thread и два одинаковых снимка, точная сохранённая привязка до чтения
тел сообщений, проверка каждого автора и chat ID, очистка hook/handles/forward.
Максимум 20 загруженных сообщений, 2048 UTF-16 единиц на текст, 16384 на снимок.
Нет прокрутки, чтения других чатов, поиска, отправки, фонового наблюдения,
Telegram или использования `new-ten.sqlite3` / `reply-review.sqlite3`.
Не удаляй сообщения ради лимита. При изменённой/удалённой истории или другом
чате проверка останавливается; пришли только обезличенный JSON.

## Проверки сборки

```sh
python rootless-unity/run_unit_tests.py
cc -shared -fPIC -O0 -pthread rootless-unity/fixtures/one_chat_fixture.c -o one_chat_fixture.so
python rootless-unity/smoke_one_chat.py ./one_chat_fixture.so
```

Unit-тесты покрывают совместимость состояния 0.3.31, базовый снимок, новое событие,
повторы/перезапуск, перестановку коллекции, несколько входящих, новое исходящее,
другой текст/нетекст, неверную привязку, изменения истории, откат транзакции,
сбой записи отчёта и восстановление, устаревший/повреждённый черновик и отсутствие
текстов в БД/JSON. Native ABI-тесты используют вымышленные локальные объекты.
Windows CI проверяет настоящий упакованный GUI и видимый блок предпросмотра
на синтетических данных, без ADB и аккаунтов.

Сборка/синтетические тесты не доказывают работу новой функции на реальном MuMu.
После выпуска нужен ручной прогон выше. Отправка и автоответы недоступны.
