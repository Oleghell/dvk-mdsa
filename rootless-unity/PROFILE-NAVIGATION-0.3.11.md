# 0.3.11 — чтение настоящего счётчика друзей

1. Скачай **Dvk-rootless-profile-navigation-0.3.11-windows-x64** из успешного Actions и распакуй.
2. На **MuMu #4 (5563)** открой загруженный поиск анкет. Закрой фильтры и диалоги.
3. В программе нажми **«Проверить профиль»**, не «Найти счётчик». Она откроет одну анкету, проверит счётчик и вернётся.
4. Пришли **rootless-profile-navigation-0.3.11.json** рядом с test-apks.

Источник подтверждён определениями из твоего отчёта 0.3.10: ProfileViewController.get_Profile() возвращает DV.Models.Profile, а Profile.get_FriendsCount() возвращает System.Int64. Старые предположения про User и Int32 удалены. get_IsActual() должен быть true: незагруженная модель не считается нулём друзей, повторная проверка — не чаще раза в секунду. Все три getter-а проверяются по владельцу, типу, отсутствию параметров/static/byref.

Модель удерживается GC-handle, число читается дважды как signed Int64. Только стабильные значения 0…1 000 000 переводятся в JSON-число. Подмена модели, изменение пользователя/контроллера или устаревшая модель после чтения останавливают тест без публикации счётчика. 49 проходит порог «меньше 50», 50 и 97 — нет. Некорректные и неизвестные значения остаются null, а не 0.

Компактное окно, ADB по умолчанию, запуск без галочки, паузы 1 с, защита #0 и отсутствие отправки сообщений сохранены. Контакты, имена, тексты и фото не читаются. Кнопка «Найти счётчик» остаётся отдельной офлайн-диагностикой.

Локально пройдены 218 unit-тестов, 101 сценарий C ABI/Frida и 12 сценариев metadata preflight. Дополнительно проверено финальное секундное ожидание модели. Тесты проверяют Int64, 0/49/50/97, большие и отрицательные числа, неполную загрузку, смену модели и ошибки сигнатур. Реальный Android-счётчик этой версии ещё не проверен; нужен отчёт из шага 4.
