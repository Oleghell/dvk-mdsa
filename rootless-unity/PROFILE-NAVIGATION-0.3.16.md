# 0.3.16 — проверка открытого чата

1. Запусти оба MuMu. На **#4 / 5563** вручную открой **один личный чат**.
2. В сборке выбери прежнюю **test-apks** → нажми **«Проверить чат»**. До завершения не меняй экран.
3. Пришли **rootless-open-chat-state-0.3.16.json** рядом с test-apks.

Результат: доступная история пуста / не пуста / неизвестно. Программа ничего не открывает, не закрывает, не вводит и не отправляет. Тексты сообщений, имя собеседника, ID, телефоны и контакты не читаются и не сохраняются. Чат остаётся открытым. Само приложение при ручном открытии может отметить сообщения прочитанными.

## Что проверяется

Реальный отчёт 0.3.15 подтвердил MessagesCM → MergeableCM`2 → BaseContentManager`2 → ContentDataList`1 → DataList`1 → ListBackedDataList`1 → BaseDataList`1. Нужные определения сохранились полностью; limited относился к другим узлам. Используются ContentDataList.get_LoadInProgress, get_AllIsLoaded и BaseDataList.get_Count.

AllIsLoaded — DataField, не Boolean. Тип фактического результата должен быть Core.dll/DataKit/DataField`1. get_Value проверяется в runtime: ноль параметров, instance, не abstract, не byref, результат Boolean, точный владелец. Если сигнатура не подходит, проверка останавливается до UI-наблюдателя, с checkpoint loaded-value и фактами о сигнатуре в отчёте. Никакой подмены generic typeIndex или чтения полей по смещениям. Значимый DataField при необходимости вызывается через корректно распакованный receiver; reference DataField — как объект.

На независимо подтверждённом UI-потоке проверяется видимый MessagesViewController, его User и Chat, личный диалог с тем же User, актуальная модель не-draft, существующий MessagesCM. User/Chat/CM/controller удерживаются GC handles и должны сохранять идентичность. Все временные ссылки освобождаются после кадра; постоянные — при завершении, отмене или ошибке.

Пустой итог допустим только при AllIsLoaded=true, LoadInProgress=false до/после чтения, трёх совпадающих неотрицательных Count в пределах 1000000 и отсутствии LastMessage. Ненулевой LastMessage при Count=0 — противоречие, а не пустой чат. Читается только наличие LastMessage, не его содержимое. Повторный согласованный замер — не раньше чем через 1 с. Загрузка/черновая или неактуальная модель/изменение привязки/ошибка/отмена никогда не превращаются в ноль.

Count — количество записей в доступной истории приложения. Даже полностью загруженная пустая история **не доказывает, что сообщений никогда не было**: удалённые или исчезнувшие сообщения этим способом не восстанавливаются. Нет команд загрузки дополнительных страниц, создания чата или отправки сообщений.

## Ограничения и проверки

Старые пределы кадра 100 мс между вызовами, 180 активных кадров, 6000 managed-вызовов и общий timeout 16 с сохранены. В UI ничего не нажимается; секундные паузы старых профильных режимов сохранены. ADB по прежнему пути, без галочки и автозапуска, #0/5555 защищён, APK не переустанавливаются. Кнопки доступны только по одной задаче.

Отчёт различает history_state_read и message_text_read: состояния читаются, тексты — нет. app_actions_attempted/messages_sent остаются false/0. Финальный неизвестный статус не содержит числового message_count. При отмене/ошибке очистки ранее вычисленный итог сбрасывается.

Unit-тесты проверяют запрет действий/текстов, неизвестное значение вместо ложного нуля, обязательность загруженной истории, стабильность/тип счётчика, поток/видимость/ресурсы, смешение режимов, транспорт и компактную кнопку. Нативный C/Frida стенд: 28 сценариев — пустой/nonempty, reference/value DataField, загрузка/неполная/черновая история, null/неверные модели, изменения привязки/счётчика/LastMessage, неподдержанная сигнатура, исключение и отмена. Ни одного открытия/закрытия, off-thread вызова или утечки handles. CI проверяет оба OS и упакованный GUI. Реальный Android-тест этой версии ещё требуется.
