# 0.3.9 — определить настоящий источник числа друзей

Счётчик 97 ещё не исправлен: из старых отчётов нельзя узнать, в каком поле/типе приложение хранит это число. Добавлена кнопка **«Найти счётчик»**, которая анализирует определения из твоих локальных тестовых APK, а не угадывает getter-ы.

1. Скачай **Dvk-rootless-profile-navigation-0.3.9-windows-x64** из успешного запуска Actions и распакуй.
2. Выбери прежнюю **test-apks**. Нажми **«Найти счётчик»**, не «Проверить профиль». MuMu и ADB для этой кнопки не нужны.
3. Нажми **«Отчёт»** и пришли **rootless-friends-metadata-0.3.9.json** рядом с test-apks.

Отчёт содержит названия методов/полей, классов и сигнатурные сведения из APK: friend_methods/friend_fields, user_getters/user_fields, profile_getters/profile_fields. В каждой группе total/truncated и до 128 definitions. Это определения программы, не значения полей пользователя. Методы не исполняются, профиль не посещается, фото/контакты/переписка/токены не читаются и не отправляются. Для расшифровки местоположения счётчика потребуется этот новый отчёт.

Проверяются SHA256 обоих APK, версия/границы/владение записей метаданных v31, размер и однозначность секции. APK не распаковывается на диск и не изменяется. Раскладка полей сверена с MetadataClass.cs в Perfare/Il2CppDumper. Лимитированные технические определения могут раскрывать внутренние имена приложения — отправляй отчёт в этот чат, не публикуй APK.

Компактное окно, путь ADB по умолчанию, запуск без галочки и секундные паузы обычного теста сохранены. Код Frida-навигации идентичен 0.3.8. Старое чтение двумя getter-ами не объявляется исправленным; новая кнопка нужна именно для определения настоящего источника.

208 unit-тестов прошли в Linux, включая реальный разбор синтетических metadata v31 внутри ZIP, имена полей/методов, неверные хеши/версии/границы/владение, лимиты, отмену и запуск кнопки без ADB. Windows-проверка и упаковка выполняются в CI. Реальные тестовые APK недоступны в среде разработки, поэтому результат именно для твоего APK пока не подтверждён.
