# UIKit 0.1.8 — адаптер ShortList<UIView>.Iterator, без OCR/root

## Почему 0.1.7 остановилась

Полученный отчёт 0.1.7 подтвердил все проверки ADB, отдельность #0/#4, естественный callback `UIKit.UIRuntimeComponent.Update`, главный поток и наличие MainWindow. Обход получил только корневой UIWindow и остановился с `unsupported-collection`; ссылки и наблюдатель были освобождены. Дерево не было прочитано полностью.

Офлайн-проверка определения `UIView.get_Subviews` в предоставленном APK/metadata v31 установила объявленный возвращаемый тип: **вложенная value-type структура `Core.Collections.StructBased.ShortList<UIView>.Iterator`**, а не reference-type список. Предыдущий адаптер намеренно отказывался вызывать методы неизвестной структуры. Проверены таблица типов ELF, владелец вложенного определения, аргумент UIView и сигнатуры методов. Только фиксированное резюме сохранено в `SUBVIEWS-OFFLINE-EVIDENCE.json`; APK, полный metadata, адреса и таблицы не публикуются.

## Исправление

- Сохранён прежний адаптер проверенных reference-type списков.
- Новый адаптер разрешает **только** известный вложенный `Iterator` из Core.dll, с родителем `Core.Collections.StructBased.ShortList<T>`, признаком value type и точным совпадением фактического класса с объявленным возвращаемым классом Subviews.
- Перед вызовами проверяются нулевая арность, instance-флаги, declaring class, отсутствие byref и типы возврата `Count:Int32`, `MoveNext:Boolean`, `Current:UIView`, `GetEnumerator:тот же Iterator`.
- Используется стандартный протокол `GetEnumerator → Count → MoveNext → Current`. `get_Item(Int32)` не предполагается для этого типа: в исходных метаданных у него другая generic-сигнатура.
- `runtime_invoke` возвращает boxed copy value type. Для вызова instance-метода получатель получается через **`il2cpp_object_unbox`**, не через guessed object-header offset. Все боксы удерживаются opaque pointer-sized GC handles и освобождаются.
- `MoveNext` меняет только временную закреплённую копию итератора, возвращённую GetEnumerator. Методы действий UIView/Control, setter и UI-ввод не вызываются.
- Count ограничен 0…4096; преждевременное/лишнее значение MoveNext даёт `iterator-count-mismatch`. Неизвестный тип или неподходящая сигнатура по-прежнему останавливает обход.
- В отчёт добавлены только фиксированные `collection_adapters` и `last_collection_stage`. `unity_root_access` отдельно отмечает корень, чтобы ошибка дерева не скрывала успешную проверку окна.

## Запуск

1. Распакуйте ZIP 0.1.8 в новую папку. Старую `test-apks` сохраните.
2. Запустите оба MuMu. На **#4 / 127.0.0.1:5563** откройте уже установленную тестовую копию ДругВокруг, обычный экран без переписки.
3. В `Dvk-rootless-diagnostics.exe` укажите прежние `adb.exe` и старую `test-apks`.
4. Отметьте разрешение только для #4 и нажмите **«Снять структуру UIKit — без текста и нажатий»** один раз.
5. Пришлите **`rootless-diagnostics-0.1.8.json`** рядом со старой `test-apks`, включая результат с ошибкой/ограничением. Во время проверки не переключайте экраны.

APK **не переустанавливается**. Не нужны root, удаление данных, смена MuMu, перенос аккаунта или повторный вход. Рабочий #0 / 5555 не изменяется: сохранены только прежние проверки ADB состояния и различия устройств. Сбор ADB-категорий из 0.1.7 сохранён без новых команд.

## Ограничения

Это диагностический снимок, не готовый автокликер. Нет OCR, скриншотов, CV, координат, UI-текстов, имён UI-объектов, нажатий, отправки сообщений/подарков, heap scan или обхода защиты.
Максимум 64 узла, глубина 8, до 32 детей на узел, 512 managed-вызовов дерева. В сумме допускается до 192 acquire/release операций GC handle для узлов и временных коллекций; они не остаются между запусками.
Бюджет обхода 150 мс проверяется **между** вызовами, наблюдатель ждёт до 8 секунд. Выполняющийся зависший native/managed getter безопасно прервать нельзя: возможны пауза или сбой тестового приложения.

`tree-ready` означает завершение доступного графа данного окна в пределах ограничений. `tree-limited` — частичный снимок с фиксированной причиной; отсутствующие в нём узлы нельзя считать отсутствующими на экране. `tree-error` сохраняет фиксированный этап и причину, не запускает OCR. При `cleanup-failed` не повторяйте подряд; закройте и откройте только тестовое приложение #4.

## Проверки и предел доказательств

Синтетический C ABI стенд проверяет обычный список и boxed Iterator: обязательный GetEnumerator, строго unboxed receiver, Count/MoveNext/Current, неправильного declaring owner, generic-тип, byref, несовпадение Count, исключения, null, повторные ссылки, лимиты детей/глубины/узлов/вызовов и освобождение высокоадресных pointer handles. Полный тестовый набор выполняется на Linux/Windows; Windows EXE проверяется на запуск Tk/Frida.

**Адаптер 0.1.8 ещё требует проверки на реальном MuMu.** Офлайн-доказательство типа и синтетические тесты не подменяют эту проверку и не подтверждают полный пользовательский workflow.
