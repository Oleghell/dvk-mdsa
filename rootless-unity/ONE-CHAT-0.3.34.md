# 0.3.34 — локальная переписка от старых сообщений к новым

Исправление представления после успешного теста 0.3.33: исходящее наблюдалось,
локальный снимок сохранился, пользователь подтвердил получение вторым аккаунтом.
Приложение возвращает коллекцию в наблюдаемом пользователем порядке «новые сверху».
Теперь **и локальное окно, и `one-chat-transcript.json` разворачивают её**:
ранние сообщения сверху/в начале списка, последние — снизу/в конце.

## Обновление без повторной отправки

1. Закрой прежнюю утилиту, скачай и распакуй ZIP `rootless-one-chat-v0.3.34`.
2. Запусти новый `Dvk-one-chat-check.exe`, выбери прежние ADB и `test-apks`.
3. Открой тот же привязанный чат со своим вторым аккаунтом в тестовом MuMu #4.
   Подтверди галочку своего аккаунта. Если нужен обновлённый файл, включи
   «Сохранять тексты и ID локально…».
4. Нажми только **«2. Проверить · без отправки»**, затем
   **«Показать переписку локально»**. Новые тестовые сообщения не нужны.
5. В окне и обновлённом локальном файле сообщения должны идти в одном направлении:
   начало переписки сверху, конец снизу.

**Не перепривязывай чат, не удаляй SQLite-журнал и не повторяй отправку.**
Существующий лимит одной попытки, привязка, исходная история и дедупликация
сохраняются. После уже выполненной попытки кнопка отправки остаётся заблокирована.

Файл прежний: `%LOCALAPPDATA%/DvkRootless/one-chat-transcript.json`.
Он обновляется только после успешного чтения при включённой галочке. Это последний
снимок до 20 сообщений, а не полный архив. Он содержит тексты и ID в открытом виде,
без шифрования; не присылай его. Агент не видит локальное окно или этот файл напрямую.
Снятие галочки не удаляет старый файл и не перестраивает его: для обновления нужен
один успешный запуск чтения с включённой галочкой.

## Технические границы исправления

- Изменена только копия списка для представления. Исходный снимок, порядок чтения
  getter-ов, HMAC-отпечатки, расчёт новых сообщений и защита отправки не переставляются.
- ID не сортируются как время. Используется простой обратный порядок коллекции,
  основанный на наблюдении пользователя для этого тестового приложения.
- Временные метки пока не читаются и универсальный порядок истории не доказан.
  `chronological_order_verified=false` и `transcript_order_verified=false`
  остаются честными. Исправление не включает многошаговые автоответы.
- Формат локального JSON — `owned-test-chat-latest-snapshot-v2`:
  `presentation_order=reversed-source-collection`,
  `order_basis=user-observed-newest-first`. Массив `messages` теперь в порядке
  представления. ID, авторы и тексты не изменены; исходный объект в памяти не мутирует.
- Диагностический отчёт называется `rootless-one-chat-0.3.34.json` и по-прежнему
  не содержит текстов/ID. После возможной отправки `messages_sent=null` и
  `delivery_confirmed=false` не заменяют ручное подтверждение второго аккаунта.
- Сохранены все ограничения 0.3.33: один свой тестовый чат, только endpoint 5563,
  pinned APK/Gadget и boot ID, стабильные снимки, проверки привязки/авторов,
  одна явная подтверждённая попытка с постоянным запретом повторов, без фонового
  старта, рассылки, Telegram, контактов или обращения к рабочему #0.

Подробности режима отправки и локальной приватности:
[инструкция 0.3.33](https://github.com/Oleghell/spam-dvk/blob/feature/android-ui-hierarchy/rootless-unity/ONE-CHAT-0.3.33.md).
Она не требует повторять уже выполненную тестовую отправку.

## Проверки

Unit-тесты проверяют одинаковый порядок окна/JSON, неизменность исходного снимка,
немонотонные ID (без сортировки как времени), пустой/одиночный список, Unicode и
нетекстовые сообщения, а также сохранение дедупликации и резерва отправки.
Windows CI дополнительно открывает настоящее окно переписки упакованного EXE
на синтетическом снимке и проверяет, что `OLD_SYNTHETIC` стоит перед `NEW_SYNTHETIC`.
Все прежние unit/ABI-проверки читателя и однократной отправки сохранены.
Сборка не подключается к реальному MuMu и не содержит пользовательскую переписку.
