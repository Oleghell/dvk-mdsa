# 0.3.29 — только тестовая копия MuMu

Пользовательский отчёт 0.3.28 прошёл строгую проверку: 7 классов и все 23
сигнатуры подтверждены, `contract-ready`, ошибок очистки нет. Получать эти же
определения заново ради продолжения разработки не требуется. Эта версия меняет
только подключение отдельного диагностического инструмента.

## Что изменилось

- Для **Dvk-reply-contract.exe 0.3.29** нужен только тестовый MuMu #4, endpoint
  `127.0.0.1:5563`. Рабочий #0 можно оставить выключенным.
- Нет `connect`, `get-state`, чтения boot ID или других команд для #0 / 5555.
  Защитный ADB-класс запрещает и чтение, и запись на любом другом endpoint;
  не выполняется даже общий `adb devices`. Нет автоматического выбора другого
  устройства, если тестовое недоступно.
- Сохранены проверка загрузки Android и наличия пакета на тестовом endpoint,
  закреплённые SHA256 прежних локальных тестовых APK и аутентификация Gadget
  их существующим токеном. Неверный bundle/токен или недоступный Gadget
  останавливают операцию без обхода и без обращения к рабочей копии.
- Boot ID проверяется в памяти до соединения и повторно после проверки Gadget.
  Смена или перезагрузка устройства во время операции делает результат
  неуспешным. Сам ID не записывается в JSON или локальные настройки.
- Номер порта сам по себе не доказывает номер экземпляра MuMu. Это явная
  привязка к тестовому endpoint и его аутентифицированному Gadget, а не
  утверждение о постоянной аппаратной идентичности. Для этого инструмента
  разрешены только определения — никакие действия с аккаунтами не добавлены.

Новый отчёт честно содержит `device_scope=test-only`,
`working_device_contacted=false`, `instances_verified_distinct=false`.
Последнее не ошибка: без обращения к #0 различие двух устройств не проверяется.
`test_session_identity_rechecked=true` означает проверку неизменности тестового
Android в рамках одной операции, не подтверждение личности пользователя.

## Запуск новой версии

1. Скачай ZIP отдельного prerelease **rootless-reply-contract-v0.3.29** либо
   Windows-артефакт успешного workflow **Build test-only reply contract checker
   0.3.29**. Распакуй в новую папку, старый инструмент закрой.
2. Включи **только тестовый MuMu #4**. Тестовое приложение уже должно быть
   запущено; достаточно любого обычного экрана. Открывать чат не требуется.
3. Запусти **Dvk-reply-contract.exe**, укажи ADB и прежнюю папку `test-apks`.
4. Если проверяешь новый одноэкземплярный запуск, нажми **«Проверить сигнатуры ·
   без сообщений»** один раз. При ошибке пришли новый
   **rootless-reply-contract-0.3.29.json** рядом с выбранной папкой `test-apks`.

Для уже подтверждённых определений повторный запуск необязателен. Не запускай
новую десятку и не удаляй журнал или lock-файлы; не переустанавливай APK и не
присылай папку test-apks, токен или SQLite-базу.

Если ОС блокирует EXE, не отключай защиту и не меняй политики ради обхода.

## Что осталось без изменений

Это всё ещё инструмент **метаданных**, не чтение входящих: 7 фиксированных
классов, 23 сигнатуры, максимум 12 000 API-вызовов, 5 секунд на определения и
10 звеньев цепочки родителей. Сохранены нулевые счётчики действий/отправок и
отдельные флаги, что порядок истории и живые ответы ещё не проверены.

Нет чтения переписки, открытия профилей/чатов, скриншотов, OCR, смены города,
ввода, отправок, установки или запуска приложения. Локальный временный ADB
forward к Gadget удаляется после проверки. Журнал семи привязок и Telegram
не читаются и не изменяются.

Старые установщик и отправляющие режимы 0.3.27 не переведены в этот режим и не
получили ослабления защит: `test_only` допускается только отдельной проверкой
сигнатур и только с ограниченным TargetOnlyAdb.

## Проверки

Синтетические ADB-тесты проверяют отсутствие всех обращений к #0, работу при
его отсутствии, отказ без fallback, неверную авторизацию, смену boot ID,
проверку после Gadget, очистку forward и запрет установки/ввода/неявных целей.
Отчёт не экспортирует boot ID, ключи или тексты ошибок транспорта.

Сохранены native C ABI-тесты определений, все rootless unit-тесты и настоящая
проверка запуска упакованного Tk EXE на Windows CI. Это не заменяет проверку
одноэкземплярного подключения на пользовательском MuMu.
