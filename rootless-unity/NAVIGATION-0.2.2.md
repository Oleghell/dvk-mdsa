# ДругВокруг 0.2.2 — первый функциональный тест без OCR и root

## Исправление 0.2.2: реальный UIView вместо presentation-флага

В присланном отчёте 0.2.1 цепочка уже найдена: **dv-navigation → main-tabs → search**. ADB, Gadget, основной поток и доступ к окну исправны. Остановка `screen-not-ready` произошла до действий: open/cancel не вызывались, handles освобождены.

Последовательность из 18 навигационных вызовов в коде 0.2.1 соответствует остановке на `DVViewController.IsEffectivelyPresented`: HasView уже прочитан, а View ещё не получен. Свойство проверяет presentation-состояние контроллера/его цепочки, а не универсальную видимость выбранной вкладки. Нельзя требовать от вложенной вкладки признака представленного окна.

В 0.2.2 проверяется **сам UIView**:

- контроллер выбран в активной цепочке навигации, а не найден среди всех сохранённых экранов;
- HasView=true: getter View не должен создавать отсутствующее представление;
- EffectivelyHidden=false и UserInteractionEnabled=true;
- цепочка UIView.Parent доходит именно до текущего MainWindow (не null и не другое окно);
- отсутствует неразрешённое модальное окно и переходная анимация.

IsPresented записывается только как диагностический булев признак: false не запрещает действия на видимой, выбранной и присоединённой вкладке. Ни IsEffectivelyPresented, ни UI-тексты не читаются.

Если View временно скрыт, недоступен или ещё не присоединён, программа ждёт следующие естественные UI-кадры в пределах прежнего timeout. Пустой контейнер и короткий промежуток регистрации модального окна после собственного open также ожидаются. Неизвестный экран по-прежнему запрещает действия. Новый отчёт показывает `readiness_check`, отдельные булевы проверки и глубину Parent: причину остановки больше не нужно выводить только из числа вызовов.

Синтетические тесты включают видимый non-presented экран, скрытый/недоступный/отсоединённый UIView, другое окно, цикл/избыточную глубину Parent, отсутствующий View и его переход в готовность. **Результат 0.2.2 на пользовательском MuMu ещё требуется подтвердить.** Повторять 0.2.1 и переустанавливать APK не нужно.

Исправление 0.2.1 сохранено: Root/Navigation/CurrentViewController/MainTabs обходятся по активному содержимому; нет перебора всех вкладок или поиска закешированных SearchTabController.

## Что теперь делает программа

Только на **MuMu #4 / 127.0.0.1:5563**, в уже установленной тестовой копии:

1. На естественном Unity UI-кадре независимо проверяет главный поток.
2. Получает активный UIKit-контроллер через UIWindow, цепочку известных контейнеров и выбранную вкладку; представленное модальное окно имеет приоритет. Не ищет случайный сохранённый объект в памяти.
3. Только для точного `DV.Search.SearchTabController` проверяет наличие и видимость View, доступность взаимодействия, присоединение к текущему MainWindow и отсутствие переходной анимации.
4. Один раз вызывает **существующий UI-обработчик `ShowSearchSettings()`**.
5. На следующих естественных кадрах ждёт точный `DV.Search.SearchSettingsCardController`; подтверждает его повторно и проверяет возможность закрытия.
6. Один раз вызывает **`CardViewController.DismissWithCancel()`** — не Apply/Reset и не галочку.
7. Ждёт возврата к тому же экземпляру контроллера поиска. Только это считается `navigation-ready`.

Это **семантический backend UIKit внутри Unity**, а не Android Accessibility/UI Automator и не эмуляция физического нажатия Android-кнопки. Два разрешённых UI-обработчика зафиксированы в коде. Универсального RPC для произвольных методов/текста/кликов нет.

## Как запустить

1. Распакуйте `Dvk-rootless-navigation-0.2.2-windows-x64.zip`.
2. Оставьте прежнюю папку **test-apks**, которая использовалась для успешного отчёта 0.1.8. Она нужна для аутентификации к уже установленному Gadget. **Не переустанавливайте APK.**
3. Запустите оба MuMu: рабочий **#0 (5555)** и тестовый **#4 (5563)**.
4. На **#4** вручную откройте поиск людей — сетку анкет с выбранной лупой. Закройте фильтры, профиль, чат и другие диалоги.
5. Запустите `Dvk-rootless-navigation.exe`, укажите `adb.exe` и прежнюю `test-apks`, отметьте разрешение и нажмите **«Открыть фильтры → отменить → проверить возврат»**.
6. Во время проверки не нажимайте ничего на #4. Прикрепите **rootless-navigation-0.2.2.json**, созданный рядом с прежней папкой test-apks.

**Рабочий #0 не изменяется.** Только проверки подключения/состояния и различимости устройств. Нет root, установки/удаления APK, скриншотов, OCR, CV, координат, чтения переписок, отправки сообщений и покупок. Значения фильтров не читаются и не задаются.

При остановке после открытия фильтры могут остаться открытыми: закройте их вручную **крестиком, не галочкой**. Остановка не выполняет дополнительные UI-действия и не повторяет обработчики. Не запускайте повторно вслепую при ошибке.

## Что подтверждено и что ещё нет

- Пользовательский отчёт **0.1.8** подтвердил живое дерево UIKit: 64 узла, boxed ShortList iterator, главный поток и освобождение 192/192 handles. Это не означало подтверждение функциональных переходов.
- Предоставленные установочные файлы 6.8.1 содержат точные классы поиска в **DV.Search.dll**, их обработчик открытия и статические шаблоны экрана фильтров. В документацию не включены APK, полная база шаблонов, адреса, ключи и токены.
- Проверено наследование: SearchTabController → DVScrollViewController → DVViewController; SearchSettingsCardController → TabbedCardViewController → CardViewController → UIViewController. Карточка не наследует DVViewController. Готовность и вкладки, и карточки проверяется по активной цепочке контроллеров и реальному View, а не presentation-флагу.
- Методам проверяются image/class, arity, static/instance, тип возвращаемого значения, byref и владелец; virtual-вызовы разрешаются через `il2cpp_object_get_virtual_method`, не по смещениям.
- Синтетические C ABI тесты на Linux/Windows проверяют сценарий, неправильные экраны, скрытый/недоступный интерфейс, исключения, невозможность отмены, смену экземпляра, остановку, таймаут кадров и освобождение pointer-sized handles. Это **не заменяет первый запуск навигации на MuMu пользователя**.
- Готовая автоматизация всех анкет/сообщений ещё не реализована. Эта версия выполняет только описанный сценарий поиска/фильтров.

## Защита и ограничения

Один open и один cancel максимум за запуск. Неизвестный экран, класс, состояние или сигнатура останавливают тест. Нет обхода auth/integrity/pinning/root-checks. Начальный экран должен быть готов; программа не пытается угадывать путь из логина, профиля или чата.

Наблюдение ограничено 16 секундами / 180 UI-кадрами, до 6000 навигационных managed-вызовов, бюджет кадра проверяется между вызовами (100 мс). Это не жёсткое прерывание зависшего native/managed-вызова: возможны замедление, зависание или сбой тестового приложения. Общий RPC-транспорт ограничен отдельным таймером. Отмена останавливает только собственный workflow; не закрывает произвольные окна.

Сильные pinned GC handles сохраняют идентичность только исходного поиска и открытой карточки; временные handles очищаются каждый кадр, постоянные — при завершении/ошибке/отмене. Лимит общего числа временных navigation handles — 64 на кадр плюс два постоянных; глубина цепочки контроллеров — не более 12, цепочки UIView.Parent — не более 32. Циклы и превышение глубины запрещают действия. Отчёт содержит только фиксированные категории/этапы, счётчики и булевы признаки, а не UI-тексты, имена пользователей, PID, boot ID, полные пути или адреса памяти.

## Разработчику

- `uikit_navigation.py`: фиксированный многошаговый сценарий, состояния/валидация, наблюдение естественного UI-кадра, два UI-handler action.
- `navigate_device.py`: отдельное окно с явным разрешением действий только #4.
- `diagnose_device.py`: новый явно включаемый режим, тот же защищённый ADB/Gadget-транспорт; старые metadata/root/tree режимы сохранены.
- `fixtures/navigation_fixture.c`, `smoke_uikit_navigation.py`, `tests/test_uikit_navigation.py`: синтетическая проверка сценария и запретов.
- `fixtures/root_fixture.c`: дополнительное условное изображение DV.Search только для navigation fixture; прежние root/tree стенды сохранены.
- `.github/workflows/rootless-diagnostics.yml`: Linux/Windows тесты, сборка и проверка EXE, публикация только программы.

Запуск из исходников: Python 3.13, `pip install frida==17.24.1`, затем `python rootless-unity/navigate_device.py`. Нужны Windows/Tk, старые приватные test-apks и работающий ADB.

Уточнение прежней документации 0.1.8: у `ShortList.Iterator.get_Item` правильная секция parameterDefinitions подтверждает **Int32**. Прежнее утверждение об иной generic-сигнатуре было ошибочным. Адаптер 0.1.8 использует рабочий GetEnumerator/Count/MoveNext/Current и не требует изменения; новый сценарий вообще не обходит коллекции дочерних UIView.
