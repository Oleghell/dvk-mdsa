# 0.3.26 — новая десятка с сохранением привязок

## Запуск
1. Закрой старую программу, распакуй новую. Оба MuMu оставь включёнными.
2. На #4 открой загруженный поиск людей — сетку анкет.
3. Нажми **«Новая десятка · сохранить привязки»** один раз.
4. Пришли `rootless-new-ten-0.3.26.json` рядом с test-apks.

Это отправляющий проход: не более 10 уникальных видимых анкет. Друзья 50+ и непустые чаты пропускаются, поэтому привязок/приветствий может быть меньше 10. Рандомизация прежних 30 приветствий, двукратная проверка пустой загруженной истории и паузы 1 с сохранены. Нет прокрутки и смены города. Старые диалоги не подключаются.

## Что сохраняется
Перед каждой отправкой главный поток передаёт привязку аккаунт/собеседник/исходный чат/вариант приветствия локальному журналу. Отправка разрешается только после подтверждённой SQLite-транзакции с synchronous=FULL. Между записью и отправкой цель и история повторно проверяются. При ошибке записи, смене цели, сбое или неизвестном результате автоматического повтора нет.

У draft-чата серверный ID может ещё отсутствовать: исходное подписанное Int64 сохраняется как есть, положительный ID не придумывается. Основная привязка — подтверждённые ID аккаунта и собеседника. Возврат OnSendText не объявляется доставкой.

Журнал: `%LOCALAPPDATA%/DvkRootless/new-ten.sqlite3` (возможны соседние -wal/-shm). В нём личные идентификаторы; **не прикладывай его к отчёту или GitHub**. Полные тексты переписки, имена, контакты и Telegram-токен эта версия в журнал не записывает. JSON содержит только счётчики и технические признаки. После возможной отправки повторный запуск новой десятки заблокирован, в том числе после перезапуска программы. Для восстановления не удаляй журнал и старые lock-файлы.

Старая `.dvk-ten-profile-pass.lock` не снимается: новая кнопка использует отдельный долговременный журнал только потому, что пользователь явно выбрал новую десятку. Старый «Автопроход» сохранён для совместимости, но для этого запуска нужна именно новая кнопка.

## Граница готовности
Эта версия сохраняет новую группу для дальнейших ответов. **Живые Android-автоответы и автоматические Telegram-уведомления ещё не включены.** Нужные определения чтения сообщений уже найдены в отчёте 0.3.25; повторный общий инвентарь не требуется. Привязки не будут потеряны при обновлении программы.

Нативный стенд проверяет полный проход, draft ID, неверный аккаунт, смену цели, отсутствие ACK, ошибку диска, отмену после записи и неизвестный исход отправки. Это собственные тестовые объекты, не проверка новой версии на Android пользователя.
