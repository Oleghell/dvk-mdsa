# Проверка структуры UIKit 0.1.6 — без root, OCR, снимков и нажатий

Следующий этап после подтверждения главного потока и UIKit-окна в 0.1.5.
Это диагностический инструмент, не законченная автоматизация ДругВокруг.
Только отдельный MuMu **#4 / 127.0.0.1:5563** с уже установленной тестовой копией.
Рабочий **#0 / 127.0.0.1:5555** не изменяется: только проверки наличия и разделения устройств.

## Запуск

1. Распакуйте ZIP 0.1.6 в новую папку. Старую `test-apks` сохраните.
2. Запустите оба MuMu. На #4 откройте ранее установленный тестовый ДругВокруг; оставьте обычный экран без переписки.
3. Откройте `Dvk-rootless-diagnostics.exe`, укажите `adb.exe` и **старую папку test-apks** из частного комплекта для #4.
4. Отметьте разрешение одноразового чтения структуры только на #4.
5. Нажмите **«Снять структуру UIKit — без текста и нажатий»** один раз. Во время проверки не переключайте экраны.
6. Прикрепите `rootless-diagnostics-0.1.6.json`: он появится рядом с выбранной старой `test-apks`.

APK не устанавливается и не переустанавливается, данные/аккаунт не переносятся.
`test-apks` нужна для проверки идентичности старого комплекта и локальной аутентификации Gadget.
Новый APK, root, новая версия эмулятора и ввод пароля не нужны.

## Что проверяется

- Существующий Gadget 17.24.1; только фиксированный диагностический скрипт, без произвольного RPC.
- Метаданные UIKit и сигнатуры getter через экспортированный IL2CPP C API, без угаданных смещений.
- Естественный Update-наблюдатель с ожиданием до 8 секунд. После завершения исходного вызова проверяется `UIRuntime.IsOnMainThread`.
- Только на подтверждённом главном потоке: `OptionalInstance` → `MainWindow` → одноразовый ограниченный обход `UIView.Subviews`.
- Только фиксированные категории типов (`UIWindow`, `Button`, `DVButton`, `Label`, `TextField`, `UITextView`, `Control`, `UIView-derived`), связи родитель–потомок, `EffectivelyHidden`, `UserInteractionEnabled`, `Control.Enabled`, количество детей.
- Индексы узлов действуют только внутри одного отчёта: это **не** постоянные идентификаторы для автоматизации.
- `Subviews` разрешён только для известных reference-type коллекций с проверенными `Count`/`Item(Int32)` и типом возвращаемого UIView. Неизвестная коллекция останавливает обход, а не включает OCR.
- Временные ссылки удерживаются opaque pointer-sized GC handles; узлы/коллекции закрепляются на время обхода, затем освобождаются. Собственный наблюдатель снимается, локальный ADB forward удаляется.

## Ограничения и результат

Максимум 64 узла, глубина 8, не более 32 детей на узел, 512 managed-вызовов дерева. Значение Count вне 0…4096 считается ошибкой. Повторные ссылки не обходятся повторно.
Бюджет обхода **150 мс проверяется между вызовами**. Это НЕ жёсткий таймаут: уже выполняющийся нативный/managed getter нельзя безопасно прервать. Возможны пауза, зависание или сбой тестового приложения; не запускайте проверку на рабочем #0.

- `tree-ready`: весь достижимый от данного MainWindow граф прочитан в пределах ограничений. Это не доказательство наличия каждого визуального элемента приложения.
- `tree-limited`: только часть графа; причина указана в `truncated_reasons`. Нельзя считать отсутствующий узел отсутствующим в интерфейсе.
- `tree-error`: частичный результат и фиксированная причина, например `unsupported-collection` или `signature-mismatch`. Не означает, что нужен root.
- `cleanup-failed`: освобождение ресурсов не подтверждено; не повторяйте проверку подряд, сначала закройте и вновь откройте только тестовое приложение #4.
- Остальные статусы: прежняя проверка потока/корня не завершилась; дерево не читается.

В JSON нет UI-текстов, названий объектов, изображений, координат, сырых исключений, токенов, boot ID, PID, адресов памяти или полных путей. Не читаются переписки; не вызываются setter, клики, отправка сообщений, подарков или обход проверок приложения. Нет heap scan, замены функций или перехвата сетевого трафика.

## Проверки сборки

Unit-тесты и реальные Frida/C ABI проверки запускаются только на искусственных локальных графах: нормальное дерево, повторные ссылки, лимит узлов/детей/глубины/времени, неверный Count, неизвестная/значимая коллекция, managed-исключение, освобождение высокоадресных pointer handles. Отдельно сохраняются 10 проверок прежнего наблюдателя и проверки метаданных. CI выполняет тесты на Linux и Windows, затем собирает EXE и проверяет запуск GUI/импорт Frida.

Снимок структуры 0.1.6 на реальном MuMu ещё требует проверки пользователя; успех 0.1.5 не подменяет эту проверку. После анализа дерева можно проектировать стабильные семантические селекторы и отдельные подтверждаемые действия без OCR.

В публичном релизе — только исходники/инструмент и лицензия Frida. APK, подписи, секреты и полные метаданные приложения не публикуются.
