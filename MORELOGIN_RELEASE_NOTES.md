# MoreLogin 2.0.0-beta.7

Добавлен отдельный явный установщик DvkCloudInstaller.exe и кнопка «Установить Gadget».

- Один Cloud Phone ID за операцию. Используются существующие DPAPI-ключи и проверенный SSH-ключ. Ручные SSH-команды и передача ключей в чат не нужны.
- Проверяются точные хеши частного split-комплекта, локальная конфигурация Gadget с токеном, SDK 34/35 и основная архитектура arm64-v8a. Работа Gadget на реальном Android 15A ещё не подтверждена.
- Отдельные блокировки выбранного ID и boot UUID исключают одновременную установку и цикл на этом телефоне. Все ADB-команды имеют явный изолированный loopback endpoint; MuMu не выбирается и общий сервер ADB не перезапускается.
- Перед установкой есть подтверждение. Для существующего приложения сначала пробуется обновление install-multiple -r без удаления. Только точный INSTALL_FAILED_UPDATE_INCOMPATIBLE разрешает предложить замену.
- Удаление требует отдельного ручного ввода ТОЧНОГО Cloud Phone ID и успешного сохранения/проверки исходных APK. Резервные APK НЕ сохраняют аккаунт, вход, переписку или данные приложения. Требуется 4 ГБ свободного места. Новая установка всё равно может завершиться ошибкой.
- Исходные APK сохраняются в phones/<ID>/apk-backups; отчёт без секретов — phones/<ID>/last-install.json. Перед удалением сохраняется маркер; при ошибке/таймауте нет автоповтора или автоматического восстановления. Остановка не откатывает выполненные действия.
- Нет root, отключения SELinux, обхода подписи, автоматического входа, запуска приложения, Gadget attach или сообщений. После установки пользователь сам открывает приложение и входит, затем проверяет «Только ответы» на одном телефоне.
- APK и токены в публичный релиз НЕ включены. Нужно выбрать частную папку test-apks. МуМу и отложенные задачи циклов/статистики не изменены.

Это предварительная сборка. Синтетические тесты и offline self-check Windows не заменяют реальной проверки установки, входа и Gadget на Cloud Phone пользователя.


## beta.7: проверка Gadget, причина установки и компактная сборка

В окне «Установить Gadget» появилась отдельная кнопка **«Проверить установленный Gadget»**.
Для неё нужны только Cloud Phone ID и ADB: локальная папка test-apks не нужна.
Она читает только установленные APK и сравнивает SHA256 всего комплекта с известными APK Gadget.
Ничего не устанавливает, не удаляет, не запускает приложение, не подключается к Gadget и не отправляет сообщения.
Результаты: наш комплект подтверждён / другой комплект / приложение отсутствует / проверка не завершена.
Другой комплект НЕ означает доказанное отсутствие любого Gadget: проверяется именно наш частный комплект.
Отчёт — `phones/<ID>/last-gadget-check.json`. Временные APK после проверки удаляются.
Нужно 2 ГБ свободного места на компьютере; одна передача APK может ждать до 240 секунд.
Работу самого Gadget на Android 15A совпадение APK ещё не доказывает.
Перед проверкой остановите рабочий цикл. Блокировки не допускают одновременную работу с одним телефоном.

Обработчик SSH больше не подменяет ошибки операций внутри туннеля кодом ssh-unavailable.
Таймаут установки сохраняется как operation-uncertain, Android Failure — как adb-failed с разрешённым Android-кодом.
Неопределённая установка автоматически не повторяется. Старые отчёты не позволяют восстановить потерянную причину.
После сообщения Android об успешной установке программа дополнительно сравнивает установленные APK.
При несовпадении или ошибке проверки успех не подтверждается и повтор/удаление не выполняются.

Три EXE теперь используют одну общую папку **_internal**, а не три отдельных копии Python/Frida/библиотек.
Распаковывайте **весь архив в новую папку**; не переносите отдельные EXE и не удаляйте _internal.
Настройки DPAPI и общая база остаются в прежнем LOCALAPPDATA и не мигрируют молча.
Контрольные суммы общих библиотек включены в build-manifest.json.
CI запускает все три EXE из перемещённой папки с пробелами, без телефона и учётных данных.
