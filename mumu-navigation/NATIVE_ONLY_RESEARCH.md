# Отказ от OCR: проверенные варианты и следующий шаг

## Наблюдения, а не предположения

На пользовательском MuMu список анкет предоставляет 7 Android-узлов, с единственной содержательной поверхностью `drug.vokrug:id/unitySurfaceView` / `Game view`. Отдельные карточки, фильтры и кнопки в обычном дереве не обнаружены. В чате нативный EditText был найден и фокусировался через ACTION_CLICK. Открытие самого чата в прежнем тесте использовало CV — это **не** доказательство нативной навигации.

Новая версия не повторяет этот визуальный маршрут. Следующий эксперимент — `mumu_ui_diagnostics`: app-owned окна + non-important узлы, без изображений и действий. Полнота отчёта и доступность конкретного селектора проверяются отдельно.

## Что даёт документация

| Вариант | Без OCR | Требования / ограничение |
| --- | --- | --- |
| Android UiAutomation / UI Automator | Да | Только узлы, опубликованные приложением в Accessibility; native ACTION_CLICK / ACTION_SET_TEXT. Уже используется напрямую через Android instrumentation, не OCR-обёртка. |
| Дополнительные Android Accessibility flags и окна | Да | Может открыть неважные узлы/другие app-owned окна; не создаёт Unity GameObjects. Реализовано в beta.2 как диагностика. |
| UI Automator 2.4 Kotlin DSL | Да | Удобные селекторы, ожидания, windows(); другой клиент того же Accessibility API. Переписывание Python-хоста на Kotlin не исправляет отсутствие узлов. |
| Appium UiAutomator2 | Да | Удобный протокол Android-автоматизации; та же граница доступности Unity UI, не гарантированный обход. |
| Unity AccessibilityHierarchy | Да | Разработчик приложения должен создать и поддерживать Accessibility nodes. Внешний агент не может автоматически добавить их в чужой релиз. |
| Poco Unity SDK | Да, объектные селекторы | Нужен SDK внутри Unity-проекта и доступная инструментированная сборка. Один pip install недостаточен. Проверять тип действий драйвера отдельно: объектный поиск сам по себе не гарантирует отсутствие координатной инъекции. |
| AltTester Unity SDK | Да, Unity objects | Требует SDK в Unity-сборке и сервера; обычная установка Desktop/Appium не инструментирует уже установленный релиз. Тип инъекции также требует отдельного аудита. |
| Frida + IL2CPP bridge | Потенциально, через объекты/методы Unity | Исследовательская динамическая инструментализация: обычно root на тестовом Android либо Gadget/доступная сборка. Нужно подтвердить IL2CPP, версии и семантику конкретных методов. Не готовый UI-драйвер и не реализовано в beta.2. |
| Официальный API | Потенциально | В просмотренных публичных материалах ДругВокруг поддерживаемой API-документации не найдено. Запросить у support@drugvokrug.ru; это не утверждение, что API не существует. |

Публичный drugvokrug-server — сторонний эмулятор старого протокола из APK 2.3.1, не подтверждённый API актуального сервиса. Не подключать к нему реальную учётную запись и не представлять его как готовую замену UI.

## Решение после расширенного скана

1. Нужные resource-id / descriptions / actions найдены: добавить проверенные селекторы в UIWorkflow, затем проверить каждую переходную цепочку без изображений и без отправок.
2. Найдены только некоторые нативные редакторы: поддержать только доказанные действия; остальные явно недоступны.
3. Только Unity surface и неполезные контейнеры: предпочтительно запросить доступную сборку/Accessibility у разработчиков или официальный API. Дополнительный исследовательский путь — Frida/IL2CPP на отдельно разрешённом тестовом экземпляре; доступ к исходникам не всегда обязателен, но совместимость и безопасность действий придётся доказать. Это не включённый fallback и не обещание «Appium всё исправит».
4. Неполный скан: причину разбирать по Android-данным; не считать элементы отсутствующими и не выполнять действия по диагностическим строкам.

### Динамическая инструментализация — отдельная задача, не обещание готового решения

Frida документирует root либо альтернативное внедрение Gadget/debugger. IL2CPP bridge позволяет исследовать классы и методы Unity во время работы. Это техническая возможность исследования, а не доказанный способ найти и безопасно активировать все кнопки текущего ДругВокруг. Обычная Android Accessibility-диагностика не подтверждает наличие IL2CPP. Изменять APK, включать root, внедрять Gadget или вмешиваться в рабочую сессию эта версия не пытается; для этого потребуется отдельное согласование тестовой среды. Не предлагать обход проверок, извлечение сессий или отключение защиты.

Никакого снятия защиты, модификации установленного APK, перехвата сессий или извлечения токенов не выполнялось. Любая последующая инструментированная сборка — только с разрешением владельца приложения/среды.
