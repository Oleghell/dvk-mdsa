# Аудит и модернизация Android-автоматизации

## 1. Что было в проекте на самом деле

Проект состоит из нескольких поколений кода, а не одного OCR-кликера.

- Рабочий мост `mumu-navigation/mumu_bridge.py`: Python 3, Tkinter, встроенный HTTP/MCP-сервер, ADB через ограниченный subprocess, Pillow, Windows EXE через PyInstaller, SQLite-журнал. Android-помощники написаны на Java и вызываются как instrumentation через UiAutomation.
- Современный мост уже использовал Accessibility для native EditText, проверки фокуса/текста и части ввода. Основная проблема навигации — фиксированные точки, 900×1600 и пиксельные якоря. Поэтому добавление ещё одного постоянного OCR-цикла не решило бы проблему.
- Более ранние Windows-модули `chat-ocr.ps1`, `portable-ocr.ps1` используют локальный Tesseract TSV и Windows.Media.Ocr. `host_dark_reader.py`, `host_chat_observer.py`, `bubble_detector.py` анализируют изображения/области диалога и кандидатов пузырей. Это отдельный read-only контур, а не универсальный нативный навигатор.
- `ui-inspect.ps1` уже умел безопасно читать UI hierarchy/XML, но не являлся общим слоем действий.

### Проверка живого приложения

Во время аудита read-only инспекция показала 900×1600, `drug.vokrug:id/unitySurfaceView` с описанием `Game view`, а отдельно — нативный `android.widget.EditText`. Кнопки Unity не были представлены отдельными Android-узлами. Это наблюдение одного экрана/версии, не гарантия для всех версий.

Нельзя «включить resource-id» и получить структуру элементов, которую само приложение не публикует. Новый код явно возвращает неизвестное состояние и не выдаёт отсутствие узлов за отсутствие истории/сообщений.

## 2. Архитектура новой ветки

```text
MCP / именованный workflow
  → политика действия + существующий SQLite-журнал
  → AndroidUI / Element
      → нативный UI hierarchy
          resource-id → description → exact text → contains text
          → class + свойства → parent/ancestor/child/below
      → OCR по запросу, только после отсутствия элемента
      → целевой CV-модуль, если для такого элемента есть модель
  → повторная проверка контекста и элемента внутри Android
  → ACTION_CLICK / ACTION_SET_TEXT / системный Back
  → проверка нативного результата, без обещаний доставки сообщения
```

`find_element(resource_id=...).click(...)`, `find_element(description=...)`, `find_element(text=...)`, `wait_for_element(..., timeout=10)` реализованы в `ui_runtime.py`. Для мутаций требуется переданный policy callback; экземпляр без него работает только на чтение. Несколько атрибутов одного селектора соединяются через AND. Упорядоченные альтернативы задаются отдельно, а не заменяют несовпавшие ограничения незаметно.

Селекторы поддерживают `resource_id`, `description`, `text`, `text_contains`, `class_name`, `clickable`, `enabled`, `editable`, `focused`, `checked`, `checkable`, `selected`, связи `parent`, `ancestor`, `child`, `below`. Явный `first=true` выбирает первый по фактическому положению подходящий результат; без него неоднозначность — ошибка. Произвольный XPath/eval не исполняется.

### Ожидания

Читаются конкретные элементы/состояния до монотонного deadline. Короткая пауза используется между проверками, а не как предположение «за три секунды экран готов». На timeout возвращается отказ. Ожидания повторяют только чтение; действия автоматически не повторяются.

### Определение состояния

Есть консервативные правила `city_search`, `search_filters`, `profile`, `message_editor`, `unknown`, `ambiguous`. Они основаны на элементах, а не диапазонах фиксированных координат. Это расширяемые правила; некоторые подписи — семантические aliases для тестовой/доступной UI, не подтверждённые resource-id скрытых Unity-кнопок. Обычное поле ввода не означает `empty_chat`.

## 3. Что реально переписано

| Область | Новая реализация | Что не заявляется |
|---|---|---|
| Поиск | Общие селекторы, порядок стратегий, структура, уникальность | Не угадываются скрытые resource-id |
| Действия | Java UiHierarchyBridge, повторное чтение дерева, hash контекста | Успех ввода не равен успешной навигации/отправке |
| Клик | ACTION_CLICK; центр актуального native bounds только при отсутствии action | Нет фиксированной точки в новом бизнес-слое; нет fallback после попытки action |
| Ввод | ACTION_SET_TEXT + точное ожидаемое старое значение + нативное readback | Clipboard не трогается; скрытые/парольные поля запрещены |
| Город | Нативный поиск поля, канонический каталог, общий журнал city_actions; первый результат под полем | При непоказанном нативном city-picker состояние не угадывается |
| Профиль/чат | Счётчик визита до действия; native labels; OCR/CV при разрешённом fallback | Unity-карточка без структуры не становится автоматически нативной |
| Настройки | Native checkable/checked для «Только онлайн», подтверждение новой структуры | OCR-слово «онлайн» не доказывает положение переключателя |
| Логи | Этап/метод/код отказа, ограниченный размер и ротация | Не записываются тексты сообщений, селекторы, скриншоты, пароли |

Новые MCP-инструменты подключены к работающему HTTP-серверу и попадают в Windows EXE; это не отдельный неиспользуемый пример библиотеки. В `mumu_ui_action` нет произвольного selector/XY, отправки, покупки, лайка, рестарта или фонового цикла. Эти возможности нельзя добавлять, минуя политику и журнал.

## 4. Что сохранено

- Исходные OCR-модули выше не удалены и не включаются новым мостом постоянно.
- Добавлен ленивый `ui_ocr.py`: локальный Tesseract rus+eng, confidence, TSV, bounds, уникальность. Неуверенные слова не отбрасываются для получения ложного точного совпадения.
- OCR не применяется для доказательства class/checked/editable/структурных свойств. При неполном дереве, неоднозначности или другом пакете OCR не маскирует ошибку.
- После распознавания OCR-кнопки Android дважды сравнивает весь фактический RGB-кадр и ещё раз дерево; нажимается центр найденных границ. Анимация может вызвать безопасный отказ. Маски пользователя не допускаются.
- CV распознавание панели закрытие/чат/подарок оставлено последним целевым резервом для открытия чата. Это не общий распознаватель любого значка.
- Старые защищённые инструменты приветствия, проверки нового диалога, отправки и визуального подтверждения результата сохранены. Они явно помечены как совместимый путь там, где остаётся фиксированный layout.
- Лимит визитов, permanent duplicate history, city-actions, резервирование до действия, неизвестный исход и SQLite-файл не сбрасываются. Новый и старый семантический способ открытия чата делят запись попытки визита.

## 5. Где координаты ещё остаются и почему

| Файлы/контур | Зависимость | Причина |
|---|---|---|
| `mumu_bridge.py`, `session_bridge.py`, старый navigation helper | legacy 900×1600, точки сетки/ввода/send и фиксированные pixel anchors | Непоказанные Unity-элементы, прежние проверки нового чата/получателя. Не удалены без равноценного подтверждённого распознавания |
| `city_field.py`, `city_autotest.py`, старый city helper | фиксированные якоря и пробные точки поля | Совместимость старого сценария; новые UI-действия поля используют native bounds |
| `ProfileChatLocator.java` / `SemanticProfileTarget.java` | форма/цвет значков, относительная зона нижней панели, портретные пределы | Target-specific CV, не гарантия для произвольной темы/ориентации |
| новый `UiHierarchyBridge.java` | динамические bounds найденного узла/текста | Допустимый tap fallback: координаты получены из текущего элемента, не зашиты в бизнес-логику |
| старые OCR-observer/ROI-модули | явно выбранные области изображения | Экспериментальная read-only диагностика; не основной новый путь |

Нативный слой не привязан к портрету/900×1600: использует actual display size, DPI, rotation и bounds Android. Но это не делает весь оставленный legacy workflow независимым от разрешения. На неподдерживаемом экране он обязан отказать, а не масштабировать координаты вслепую.

## 6. Основные новые/изменённые файлы

**Новые модули:**
- `ui_model.py` — дерево, селекторы, ошибки, состояния.
- `ui_runtime.py` — Element, порядок стратегий, ожидания, orchestration fallback.
- `ui_backend.py` — строгий нативный транспорт и целевой CV-адаптер.
- `ui_ocr.py` — on-demand local Tesseract.
- `ui_protocol.py` — валидация и три MCP-инструмента.
- `ui_workflow.py` — именованные действия и общий journal/policy.
- `ui_logging.py` — metadata-only rotating logs.
- `control-android-v2/src/com/dvk/control/UiHierarchyBridge.java` и кандидат той же реализации.
- `city-android/fixture/drug/vokrug/HierarchyFixtureActivity.java` — synthetic UI, без сети и аккаунтов.
- `control-android-v2/test-hierarchy-emulator.py`, `tests/test_ui_runtime.py`, `tests/test_ui_workflow.py`.

**Интеграция/сборка:**
- `mumu_bridge.py`, `control_protocol.py`, `control_release.py`.
- `ControlInstrumentation.java` в signed/candidate вариантах; candidate staging.
- manifest/build fixture, versionCode, pinned public APK/source hashes.
- `.github/workflows/mumu-navigation.yml`: новая ветка, native matrix/OCR тест, отдельный prerelease, проверка подписей и Windows packaging.
- актуализированные regression tests и документация этой версии.

Полный перечень изменённых файлов доступен в коммите новой ветки. Закрытый ключ/пароль, реальные скриншоты, переписка и локальная база в коммит не включаются.

## 7. Проверки и пределы доказательств

- Unit/regression: старые сценарии плюс native-first, приоритеты, AND, уникальность, структура, timeout, ленивый OCR, confidence, password redaction, журнал, лимиты, отсутствие повторов/скриншотов при нативном успехе.
- Java: компиляция нового helper и synthetic fixture, source/DEX/APK pin verification, проверка прежнего сертификата.
- CI emulator: native ID lookup/ACTION_CLICK/SET_TEXT, stale context, duplicate labels, password redaction; 720×1280/240dpi, 1080×1920/320dpi, 1600×900/240dpi, 900×1600/240dpi; поворот; hidden drawn label → настоящий локальный OCR → guarded bounds tap. После тестов display/rotation восстанавливаются.
- Windows: сборка EXE, startup self-check, контроль состава/хешей ZIP.

Наличие теста в CI не означает, что он уже прошёл: актуальный результат смотрите в Actions конкретного коммита. Синтетические тесты не заменяют проверку полного workflow на живом «ДругВокруг». На живом устройстве во время разработки не выполнялись новый ввод/клики/отправка.

## 8. Запуск разработчиком

```powershell
py -m pip install -r requirements-core.txt
$env:PYTHONPATH='mumu-navigation'
py -m unittest discover -s mumu-navigation/tests -v
py mumu-navigation/mumu_bridge.py
```

Для GUI из исходников рядом необходимы проверенные APK и cloudflared согласно существующей упаковке. Готовый Windows prerelease предпочтительнее запуска неполной папки с исходниками. OCR опционален: существующий локальный Tesseract rus+eng устанавливается отдельно; автоматической загрузки нет.

Для добавления нового действия сначала задаются semantic selectors/state predicates и правило журналирования, затем тесты. Не следует обходить ограничение Unity через придуманные ID, автоматическую рассылку, отключение защит или бесконечный OCR-loop.
