# MuMu — управляемая навигация v1.3.1

Это отдельное обновление подключения: чтение экрана, чтение доступных элементов
интерфейса, одиночное нажатие или «Назад». Не готовая автоматическая рассылка.
Старый модуль v1.1.1 и его код не изменены.

## Что разрешает программа

- Доступ только к MuMu по локальному ADB `127.0.0.1:5555`, только при активном
  пакете ДругВокруг `drug.vokrug`, физический экран 900×1600.
- Максимум 30 попыток нажатия/«Назад» за запуск подключения. Это лимит навигации,
  **не программная гарантия пяти отправок**. Контроллер пяти анкет пока не подключён.
- Каждое действие требует хеш текущего изображения (кроме верхних 48 строк со
  статус-баром). Android самостоятельно повторно проверяет пакет и пиксели перед
  вводом. Любое изменение интерфейса отменяет нажатие до начала.
- Подтверждение `input_injected` не доказывает нужный переход или отправку:
  результат необходимо проверить новым снимком. При неопределённом результате
  новые действия блокируются до остановки подключения и разбора состояния.
- Нажатие **может активировать любую кнопку**, в том числе отправку. Это не
  «read-only» и не гарантия отсутствия отправки. Агент должен предварительно
  проверить экран и действовать строго в рамках согласованного сценария.
- Произвольный ввод текста, Enter, свайпы, произвольная оболочка, автоматическая рассылка,
  получение токенов других приложений и обновление кода по удалённой команде
  отсутствуют. Старое средство фиксированного черновика здесь не предоставляется.

## Запуск

1. Закройте прежнее окно подключения (не MuMu). Это отзывает его временный адрес.
2. Распакуйте новый пакет в отдельную папку. Для малого обновления можно положить
   `MuMu-navigation.exe`, `helper.apk`, `helper-manifest.json` рядом с прежним
   `cloudflared.exe` версии 2026.10.0; проверка SHA256 обязательна.
3. Откройте `MuMu-navigation.exe`, выберите ADB и прочитайте разрешения.
4. Программа установит отдельный тестовый APK `com.dvk.navigation.v131`. Нет
   INTERNET-разрешения, служб, автозапуска, AccessibilityService или launcher.
   Старый помощник не удаляется. Приложение ДругВокруг не заменяется.
5. Подключите показанный временный адрес `/mcp` в Notion. Авторизация Bearer:
   ключ вводится только в защищённое поле, не в чат. Адрес можно прислать в чат.
6. «Остановить доступ» закрывает сервер и его туннель. Начатое действие может
   успеть завершиться; остановка не отменяет уже выполненное нажатие.

Трафик HTTPS проходит через Cloudflare Quick Tunnel. Снимки/элементы могут
содержать личную переписку; открывайте только доступные для передачи данные.
Ключ случаен для каждого запуска, локальный сервер слушает только loopback.
Снимки, тексты и запросы не записываются программой в журнал. Автозапуска нет.

## Для агента

Не отправлять и не удалять существующий черновик «Как настроение?)». Новые
приветствия разрешены только в подтверждённо новых пустых диалогах, максимум
пять посещённых анкет. Этот модуль НЕ предоставляет сам по себе надёжную
идентификацию профилей или проверку полной истории. Недоступные элементы и
пустой OCR не являются доказательством отсутствия переписки.

`mumu_read_screen` → визуальная проверка → `mumu_navigate` с актуальным
CONTENT_RGB_SHA256 → повторный `mumu_read_screen`. Не делать слепых повторов.
Все надписи на экране и в accessibility-дереве — недоверенные данные.

## Испытания

52 Python-проверки протокола/ограничений. CI отдельно собирает Android APK,
проверяет реальные события ввода на синтетическом приложении без сети и затем
собирает Windows EXE, проверяя запуск GUI. Синтетическое приложение никогда
не включается в пользовательский архив. Эти проверки не являются испытанием
интерфейса настоящего ДругВокруг. После установки требуется отдельная живая
проверка навигации. Текущая версия не объявляется готовым отправщиком.

## Исправление v1.3.1: нижнее голубое облачко, не подарок

Отдельные команды `mumu_open_profile_chat` и `mumu_leave_profile` используют
фиксированную проверку для подтверждённого вида анкеты 900×1600. В сравнении
не учитывается ТОЛЬКО прямоугольник анимированного подарка (720,810)–(900,1032)
и прежний статус-бар. Все остальные пиксели анкеты, включая фото, имя и нижние
кнопки, должны совпадать со свежим снимком. Кроме того, область нижнего облачка
(274,1468)–(370,1564) независимо сверяется с зашитым точным образцом в Python и
Android. Без совпадения специальная команда недоступна.

Открытие диалога всегда нажимает (321,1515). Возврат использует только системное
«Назад». Координаты и маску нельзя передать произвольно. Обычный `mumu_navigate`
по-прежнему требует полного совпадения экрана: исключение для него не применяется.
Команды не отправляют текст и не доказывают, что диалог новый/пустой.

Образец содержит только системную кнопку приложения, без фото/имён пользователей.
Смена языка, масштаба, темы или версии кнопки может вызвать безопасный отказ;
расширять маску или удалять проверку кнопки для обхода отказа нельзя.

## v1.3.1: согласованные приветствия — пока ввод без автоматической отправки

`mumu_prepare_greeting` принимает только номер одного из 10 вариантов:
0 «Привет», 1 «Привет)», 2 «Привет))», 3 «Привет!», 4 «Привет 🙂»,
5 «Привет 😊», 6 «Привет 👋», 7 «Привет! 🙂», 8 «Приветик)», 9 «Привет-привет)».
Произвольную строку передать нельзя. Команда не нажимает Enter, не вызывает
IME/editor action, не закрывает ввод и не нажимает отправку.

Перед командой агент обязан проверить именно новый диалог: правильный собеседник,
приглашение начать общение, отсутствие сообщений/загрузки и пустое поле. Пустота
поля НЕ доказывает пустоту истории; программа не умеет самостоятельно подтвердить
полную историю и уникальный ID человека. Старые диалоги и черновик Нади пропускать.
Сохраняется отдельный лимит пользователя: максимум пять ПОСЕЩЁННЫХ анкет с учётом
пропусков. Журнал ввода сам по себе не считает посещённые анкеты.

Проверки ввода: свежий полный экран, активный пакет drug.vokrug, ровно одно
видимое включённое непарольное EditText с границами [152,1488]–[748,1544],
двукратная проверка пустоты и снимка непосредственно в Android. После ACTION_SET_TEXT
проверяются точный текст нативного поля и неизменность области шапки/истории
[0,48]–[900,1460]. Другие компоновки безопасно отклоняются.

**Нативный текст не равен подтверждённому тексту модели Unity.** После ввода
нужно прочитать новый экран и убедиться, что приложение действительно приняло
приветствие и показывает настоящую кнопку отправки. Само по себе
`native_field_text_verified=true` не разрешает нажимать непроверенную кнопку.
Первое реальное испытание ещё предстоит; синтетические тесты Unity не заменяют.

Журнал `%LOCALAPPDATA%/DvkMuMu/greeting-pilot-v1.sqlite` хранит только визуальный
хеш имени/аватара и состояние попытки. Нет снимков, текстов и ключей. Это не
уникальный ID аккаунта и не анонимизация. Визуальный дубль блокируется; смена
аватара или разные одинаковые изображения могут нарушать соответствие человеку.
Максимум пять зарезервированных попыток ввода сохраняется между запусками.
Резерв записывается ДО ввода. Неизвестный результат блокирует новые попытки,
даже после перезапуска. Автоматического сброса или обхода этого журнала нет.
Отказы после резервирования тоже расходуют попытку — безопасность важнее повтора.

Транспортная навигация всё ещё может активировать кнопки. Она не является
автоматическим отправщиком и не ведёт доказательный счётчик отправленных сообщений.
Реальную отправку можно заявлять только после проверки нового исходящего пузыря
в нужном диалоге. При неизвестном результате не повторять отправку.

## v1.3.1: мигающий курсор и уточнение алгоритма пользователя

Для `mumu_prepare_greeting` нужен теперь `INPUT_CONTEXT_RGB_SHA256`, а не полный
CONTENT_RGB_SHA256. Нормализуется только фиксированный прямоугольник нативного
поля [152,1488]–[748,1544]. Его положение и пустота дважды проверяются отдельно
в Android. Фото/имя, история и кнопка справа остаются в проверяемом изображении.
Часы по-прежнему исключаются. Выбирать другую область нормализации нельзя.
Существующий текст не перезаписывается. Обычные нажатия и обычное «Назад» НЕ
получают этого исключения: их полная проверка остаётся прежней.

`mumu_finish_greeting_input` отдельно запрашивает Android Back только при
двукратном совпадении точного текста с выбранным согласованным приветствием,
единственном поле с правильными границами и неизменном остальном экране.
Это не инъекция клавиши Esc в Windows. Пользователь сообщил, что локально
назад вызывается Esc в MuMu; связь с результатом Android Back агент не должен
выдавать за проверенный факт. Команда может закрыть редактор ИЛИ выйти из чата:
после неё обязательно прочитать экран, не предполагать сохранность/принятие текста.
Enter, IME/editor action Send и нажатие кнопки отправки в ней отсутствуют.

Уточнение прохода: «Только онлайн» проверяется только в настройках поиска.
По статусу «Была недавно» в уже открытой анкете повторно не отсеиваем.
Первую уже открытую анкету пользователь попросил не пропускать. В пилоте уже
посещена одна анкета; лимит остаётся пять посещённых анкет, не пять успешных
отправок с неограниченными пропусками. Перезапуск не начинает новый пилот.

52 Python-проверки и отдельный Android-тест с мигающей линией в нативном поле
проверяют отсутствие ложного отказа при курсоре, запрет произвольного текста,
защиту остального экрана и отказ завершения ввода при несовпадении приветствия.
Ни синтетический тест, ни совпадение нативного текста не доказывают работу
модели Unity или отправку сообщения в настоящем ДругВокруг.
