# Пилот приветствий: максимум пять анкет

> Этот документ относится к отдельному контроллеру `greeting_pilot.py` с тестовым
> адаптером. Новый **пошаговый MuMu-тест v1.4.0** реализован отдельно; актуальный
> протокол, лимиты, сохранение истории и ограничения:
> [mumu-navigation/README.md](../mumu-navigation/README.md). Его журнал не заменяет
> журнал этого контроллера, а старые попытки ввода не считаются успешными отправками.

## Статус

Реализован и протестирован **контроллер сценария**, не действующий отправщик.
`greeting_pilot.py` не подключается к ADB/MuMu, не нажимает кнопки и не отправляет
сообщения самостоятельно. Действующий модуль v1.1.1 умеет читать экран и вводить
только фиксированный черновик «Как настроение?)»; он не является адаптером этого
контроллера. Реальный проход ещё не выполнен. Тесты используют FakeAdapter.

## Согласованный сценарий

Главная → поиск → настройки → убедиться, что «Только онлайн» включено (не
переключать вслепую) → подтвердить → ограниченный снимок списка анкет → профиль
→ сообщение → проверить новый пустой диалог → подготовить приветствие → проверить
получателя, текст и кнопку отправки → одна отправка → проверить исходящий пузырь
→ назад без удаления чужих черновиков.

Лимит — **пять посещённых анкет**, включая пропуски, а не пять успешных отправок
с неограниченным поиском остальных. Повторные запуски с тем же журналом лимит
не сбрасывают. Автоматического неограниченного режима нет.

Десять допустимых вариантов: «Привет», «Привет)», «Привет))», «Привет!»,
«Привет 🙂», «Привет 😊», «Привет 👋», «Привет! 🙂», «Приветик)», «Привет-привет)».
Пилот использует первые пять по порядку; остальные сохраняются как варианты,
но не расширяют лимит. Это обычное разнообразие текста, не обход ограничений.

## Обязательный контракт будущего реального адаптера

- Реальное согласие на пилот; активный пакет `drug.vokrug`; проверенное разрешение
  и актуальный экран. Никаких произвольных команд оболочки.
- Стабильный подтверждённый идентификатор профиля. Имя из OCR или пиксельный хеш
  изменяющейся шапки не являются надёжным идентификатором для удаления дублей.
- `ChatEvidence` подтверждает загрузку истории и положительное состояние нового
  диалога. Отсутствие распознанных пузырей не доказывает пустоту истории.
- Старые сообщения, занятый ввод, неизвестный получатель, загрузка или неоднозначное
  состояние — пропуск без ввода. Существующий черновик Нади не отправлять и не стирать.
- `prepare_greeting_if_still_empty` повторно проверяет условия непосредственно перед
  вводом, ничего не перезаписывает. `PreparedDraft` требует реальной проверки ввода,
  получателя, оставшейся пустой истории и именно кнопки отправки (не жёлтого плюса).
- `send_once_and_verify` перед действием вновь проверяет получателя/текст/историю.
  Вернуть True можно только после проверки нового исходящего пузыря именно здесь.
  Ошибка, таймаут или неизвестный результат останавливают пилот без повтора.
- Нельзя выдавать успешное ACTION_SET_TEXT за доказательство отправки или правильной
  работы внутреннего поля приложения. Сначала нужен реальный тест нового адаптера.
- Возврат сохраняет черновики. Не следует нажимать Enter или неизвестные кнопки.

Журнал SQLite сохраняет только SHA256 идентификаторов, порядковый номер и состояние;
никаких сообщений, снимков или токенов. Это псевдонимизация, не гарантия анонимности.
Резервирование попытки сохраняется до отправки: сбой после отправки не вызывает
повторное сообщение после перезапуска. При неопределённости требуется разбор,
автоматического восстановления/сброса нет.
