# Общее ядро Linux / Windows

## Статус

`chat_core.py` — первый переносимый модуль обработки OCR, а не готовый Linux-клиент MoreLogin. Текущие PowerShell/BAT не заменены и пока не вызывают это ядро. Рабочий Windows-предпросмотр сохранён.

Нет ручной конвертации: один исходник выполняется в Linux и Windows. GitHub проверяет обе ОС и собирает `dvk-chat-core.exe` из того же исходника. Установка Python на ноутбуке для EXE не нужна. EXE на этом этапе принимает JSON, не управляет телефоном.

## Запуск разработчиком

```bash
python3 -m pip install -r requirements-core.txt
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 chat_core.py --input examples/synthetic-chat.json
```

Вход и выход — UTF-8 JSON, также поддерживается stdin/stdout. Выход содержит исходный OCR-текст; его нельзя считать обезличенным диагностическим отчётом. В репозиторий входят только придуманные тестовые данные. Снимки пользователя, настоящая переписка, ключи и параметры подключений не публикуются.

## Что делает ядро

- Принимает OCR-строки с прямоугольниками и кандидатные границы пузырей от внешнего детектора.
- Объединяет строки только при однозначном полном попадании в один кандидатный пузырь; сортирует по координатам.
- Не смешивает два пузыря одного отправителя и не удаляет одинаковые реплики.
- Отделяет явно размеченные служебные элементы, сохраняя их в исходных строках. Сам текст «17:30», эмодзи и ошибки OCR не являются основанием для удаления или исправления.
- Сохраняет строки вне пузырей и неоднозначные строки отдельно, не угадывая их назначение.

Без `--image` границы пузырей задаёт входной JSON. С `--image` и обязательным `--roi X Y W H` модуль `bubble_detector.py` сам выделяет кандидатные светлые/бирюзовые области в указанной полосе изображения. Границы из JSON в этом режиме заменяются результатом детектора. Подключение нового ядра к Windows UI, идентификация диалога и новизна сообщений ещё не реализованы. Направления и границы остаются кандидатными, отправка отсутствует.

## Порядок дальнейшей разработки

1. Детектор кандидатных пузырей и интеграция с OCR на Linux; испытания на искусственных изображениях разных размеров и тем.
2. Подключение общего ядра к Windows-предпросмотру без установки Python у пользователя.
3. Отдельные адаптеры MoreLogin / ADB с имитированными ответами для тестов, затем проверка реального подключения при предоставленном доступе.
4. Проверка идентичности диалога перед хранением состояния и защита от повторной обработки. Нельзя использовать один хеш текста как ID сообщения.
5. Любые изменяющие действия — отдельный этап с явным разрешением и проверкой результата.

Linux-тесты не доказывают совместимость Windows GUI и реального телефона. За это отвечают отдельные Windows-тесты архива и согласованная проверка реального окружения.

## Детектор изображений — ограничения первой версии

Детектор использует связные цветовые области и прямоугольность, не нейросеть. Проверены искусственные изображения: три масштаба, светлая палитра, переносы строк, два соседних входящих пузыря, текстовые отверстия в фоне, пустой фон, маленькие иконки, обрезка краёв, смещение ROI и неподдерживаемая тёмная палитра. Изображение и OCR должны иметь одинаковый размер; входные координаты OCR остаются в полном изображении.

Тёмная тема, фотография монитора, градиенты, стикеры, изображения и неизвестные цвета не поддерживаются как надёжные случаи. Область разговора ROI должен передать адаптер; детектор не определяет собеседника или границы интерфейса. Цветной элемент интерфейса внутри ROI может выглядеть как пузырь. Строка вне найденных областей сохраняется как неоднозначная, а не теряется. Обрезанные по краю ROI пузыри отклоняются. Временные метки не удаляются автоматически только по совпадению с форматом времени.

Автотесты используют придуманные координаты OCR и искусственные изображения. Это проверка детектора + группировки, не сквозной тест реального Tesseract на всех темах. Уже существующие тесты готового Windows OCR-архива отдельно проверяют Tesseract. Автоответы и отправка отсутствуют.
