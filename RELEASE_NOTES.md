# DvkAssistant 1.2.4

- Добавлен последовательный inbox-check между завершёнными циклами анкет по
  таймеру, чтобы длинная порция/много пропусков не блокировали ответы до конца.
  Во время нативного send-handler переключений нет; общий lock сохраняется.
- Убрано ожидание после повторной порции анкет: сразу проверяется список диалогов.
  После обработанных чатов идут до трёх быстрых повторных проходов с актуальными
  журналом/целями: сообщения, пришедшие во время ответа в другом чате, не обязаны
  ждать очередного интервала. Затем отдых в диалогах. При активных ответах новая
  порция анкет откладывается. Нет параллельного управления устройством.
- Интервал покоя по умолчанию — 5 секунд (плюс длительность прохода), диапазон
  5–3600. Схема настроек 5: старый 30-секундный default мигрирует в 5; иные значения
  сохраняются. Новое явно сохранённое значение 30 также сохраняется.
  Нет обещания мгновенного push-обнаружения; доступные строки и привязки всё ещё проверяются.
- Прямо присланные после запроса контакта 10–15 ASCII-цифр без «+» сохраняются как
  кандидат номера без выдумывания страны/исправления длины. При явном «мой номер»
  действует тот же путь. В Telegram отмечено, что формат и код страны не подтверждены.
  Обычный общий детектор телефонов не расширен. Чужие контакты, отрицания,
  цитаты, коды/заказы по-прежнему исключаются.
- telegram-disabled / telegram-outcome-unknown / contact-payload-blocked не ставят
  весь мониторинг на паузу. Есть отдельные contact_notifications,
  contacts_detected, contact_delivery_pending. Выключенная передача видна в статусе.
  Неотправленный контакт остаётся в зашифрованной очереди; она обрабатывается отдельно
  от устройства, без повторного открытия done-чата, при включённой передаче и явном запуске.
  Неизвестный результат TG не повторяется. Нового автоматического сообщения в чат нет.
- Добавлены tracked_active / tracked_attention / tracked_terminal для диагностики
  исключённых отслеживаемых чатов и immediate_rechecks в отчёте мониторинга.
- Отбор до открытия, запрет повторного приветствия и неизвестных отправок сохранены.
  Старые seen-сообщения и manual-review автоматически не сбрасываются: ранее
  отброшенный контакт нужно прислать новым входящим, а не переигрывать старую историю.
  Причину пропуска конкретного диалога по одному скриншоту установить нельзя;
  для этого нужен last-monitor.json. Реальный MuMu/доставка не проверены.

# DvkAssistant 1.2.3

- Исправлен широкий read-fallback: отбор ДО открытия по штатному счётчику непрочитанных
  и последнему сообщению. Непрочитанные допускаются; без непрочитанных допускается
  только последнее входящее, ещё не обработанное цепочкой. Последнее исходящее
  без непрочитанных и уже обработанные входящие пропускаются без открытия/чтения/отправки.
  Нет сравнения времени по ID или позиции сообщений. Тексты из списка не читаются.
- Перед открытием повторно сверяются unread и заголовок последнего сообщения,
  включая объект, ID, отправителя, IsMine и ChatId, поверх прежних проверок
  строки/контроллера/таблицы/пользователя. Изменение останавливает выбор до нажатия.
  Локальный отрицательный ChatId исходящего может только исключить ожидающий чат;
  он не разрешает чтение тела или отправку в обход прежних правил привязки.
- Новое прочитанное неотвеченное входящее и непрочитанное продолжают текущий шаг
  алгоритма. Регрессии проверяют реальный резерв, отправку, наблюдение исходящего,
  повторный проход без дубля, оба ИИ-провайдера и возврат в список.
- В отчёт добавлены reply_filter_enabled, waiting_rows_skipped, handled_rows_skipped,
  review_causes. Для новых проверок истории сохраняется безопасная причина
  (например history-missing / history-edited / unjournalled-outgoing /
  incoming-during-pending), которая также включается в уведомление об изоляции.
  Тексты сообщений и идентификаторы в эти причины не входят. У старых блокировок
  причина неизвестна; автоматического разблокирования и сброса журнала нет.
- Сохранены запрет повторного приветствия, полный проверенный ИИ-контекст,
  интервалы/поиск анкет/настройки. Отказы и неизвестные отправки не повторяются.
  Ошибки устройства, идентичности, API, чтения вне точечной изоляции и возврата
  не подавляются. Проверка на живом MuMu требуется отдельно.

# DvkAssistant 1.1.0

- Полный «Старт» повторяет порции подходящих анкет через 120 секунд после окончания
  предыдущей. Каждая повторная порция начинает с другого случайного города;
  между порциями выполняется мониторинг диалогов. Один lock, никаких параллельных

- Добавлены настройки Groq: ключ защищается DPAPI, модель настраивается, есть
  отдельный тест на вымышленной переписке. По умолчанию Groq выключен до настройки.
- Краткие смысловые ответы сохраняют текущие два шага цепочки. JSON-ответ и длина
  проверяются; отказ завершает чат; неоднозначность/ошибка API останавливают работу.
  Запасного шаблона после ошибки API нет. Смысловые ошибки модели всё ещё возможны.
- В Groq передаётся ограниченный контекст, без ID/имени профиля и вложений, с
  маскированием ссылок/контактов. Это внешняя передача переписки, раскрытая в UI.
  В отчётах фиксируются запросы/передача, но не тексты.
- ИИ-черновики сохраняются зашифрованными до отправки. Хеш связывается с тем же
  этапом и журналом. Повторный снимок обязателен; неизвестная отправка не повторяется.
  API-вызов выполняется вне транзакции SQLite. Повторный явный запуск восстанавливает
  готовый черновик, а не генерирует новую формулировку для уже отправленного шага.
- Отдельный переключатель Telegram для ошибок/пауз. Одна попытка уведомления с
  кодами причин, без переписки и секретов. Недоступный Telegram не вызывает рекурсию
  или слепые повторы; результат виден в локальном отчёте и окне.
- Добавлены тесты таймера, длительных порций, режима ответов, HTTP ошибок, отмены,
  валидации ответов, шифрования, восстановления, отказа, изменившейся истории,
  полной короткой цепочки и уведомлений. Нативная интеграция также проверяет
  ИИ-ответ с синтетическим API и задержкой возврата. Реальный Groq и MuMu требуют
  проверки с ключом пользователя; автоматические тесты её не заменяют.

  пользовательские интервалы сохраняются. Новые настройки имеют версию схемы.
- Цель начального прохода — подходящие анкеты, а не число просмотров. Пропущенная
  анкета заменяется следующей. Сохраняются отдельный счётчик просмотров и предел 200,
  защита от повторных отправок и предел трёх смен города.
- Для ошибки bound-chat-read-failed сохранены точный код, этап и безопасная диагностика.
  Временная загрузка/изменение истории допускает одну повторную попытку только чтения
  того же привязанного чата. Ошибки идентичности и неизвестные отправки не повторяются.
- Сценарий ответа «Взаимно» покрыт синтетическим тестом: один вопрос без окна подтверждения.
  Прежний отчёт не содержит низкоуровневой причины ошибки чтения, поэтому устранение
  именно сбоя реального MuMu ещё не подтверждено; при повторе нужен новый last-monitor.json.
- Счётчики ручных подтверждений и автоматических разрешений разделены.

# DvkAssistant 1.0.2

## Исправление выбора города

- Выбирается только первая видимая строка выдачи, после двух стабильных снимков.

# DvkAssistant 1.0.1

## Изменения

- Убраны отдельные кнопки ручного режима из главного окна. Журналы и привязки сохранены.
- «Старт»: один прежний начальный проход, затем мониторинг только отслеживаемых диалогов.
- «Только ответы»: мониторинг без новых анкет. Между проверками окно остаётся на списке диалогов.
- Интервал проверки настраивается: 30–3600 секунд, по умолчанию 120. Проходы последовательные.
- Каждая отправка требует отдельного подтверждения. Отказ/тайм-аут ставят работу на паузу,
  без повторного предложения по таймеру. Продолжение — новым явным запуском.
- При ошибке, неизвестной отправке или сбое записи отчёта мониторинг останавливается.
- Отдельный last-monitor.json: счётчики вызовов отправки, возвратов обработчика и новых
  наблюдений исходящих. Старые наблюдения не суммируются повторно; доставка не заявляется.
- Приветствия больше не считаются доставленными по возврату обработчика. Неизвестное число
  попыток при обрыве цикла помечается отдельно.
- Таймер смены городов и повторные обращения к новым анкетам не добавлены.

## Проверка и ограничения

Добавлены синтетические проверки мониторинга, остановки, пауз, отчётности и навигации
в список диалогов без открытия чата. Native ABI-тесты работают с собственными фикстурами,
без аккаунтов и Android. Windows-сборку проверяет CI; её результат смотри в Actions.
Новая версия ещё требует отдельного прогона на реальном MuMu №4 с тестовым собеседником.
Не удаляй существующую базу: она защищает от повторных отправок.
