# DvkAssistant 1.2.5

- «Старт» / «Только ответы» больше не открывают дополнительное подтверждение.
  Само нажатие разрешает этот запуск. Автозапуска при открытии EXE нет.
- Новые входящие во время подготовки ответа/задержки добавляются в один обновлённый
  черновик. Перепланирование разрешено только ДО резерва отправки и только при
  добавлении сообщений того же собеседника без изменений прежней истории.
  Сохраняется весь входящий пакет, а не только последнее сообщение. Не более
  трёх пересборок подряд, затем продолжение на следующей проверке лички.
- Быстрый самостоятельно присланный контакт обрабатывается даже в снимке с впервые
  увиденной собственной просьбой. Проверяется точный текст и журнал возврата
  обработчика. Неизвестная отправка никогда не сбрасывается ради продолжения.
- Задержка 35 слов/мин перед отправкой, с отменой «Стоп». Затем повторная проверка
  чата и истории. Это пауза, не имитация нативного индикатора печати.
- Отдельные таймеры: личка — по умолчанию 5 секунд после прохода; отдых перед новой
  порцией анкет — 300 секунд, настраивается 30–86400. Во время отдыха проверяются
  входящие; по сроку завершается текущий проход/ограниченная серия перепроверок,
  затем начинается новая порция. Параллельных операций устройства нет.
- Настройки версии 6: прежний длинный интервал (>30 секунд) переносится в отдых
  анкет, личка проверяется через 5 секунд. Старые defaults 30 и 120 (схема 1)
  становятся 5/300. Новые настройки сохраняют оба таймера независимо.
- Telegram сообщает причину проверенного выхода без ответа (переключатель причин
  и ошибок), включая ожидание/нераспознанный контакт и изоляцию. Без текста чата,
  телефонов и прямых ID. Повтор одного состояния исключён, неизвестный результат
  Telegram не переотправляется. Неудача уведомления не останавливает остальные чаты.
- last-monitor.json сохраняет последние 20 выходов без ответа и суммарные причины
  изоляций/ручной проверки, а не только последний проход.

Старые manual-review/неизвестные попытки не сбрасываются. Уже обработанный старой
версией контакт не переигрывается: для новой обработки нужен новый входящий.
После просьбы о контакте обычный текст не считается контактом и не вызывает
повторную просьбу; Telegram объясняет такой выход. Нового «спасибо за номер» нет.
Отбор до открытия (непрочитанные либо новое входящее без ответа), проверка привязки
и запрет повторного приветствия сохранены. История ограничена проверенным снимком
до 19 сообщений / 16 384 символов, не всем архивом.

Проверки и сборка выполняются в CI. Реальный MuMu №4 после обновления нужно проверить.
Закрой старый EXE, распакуй новый архив отдельно; свои config переноси осознанно.
Журналы, базы, защищённую очередь и старые неизвестные попытки не удаляй.
