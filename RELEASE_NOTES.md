# DvkAssistant 1.0.4

## Исправление nonpositive-message-chat-id у исходящего

- Убрано безусловное требование положительного ChatId у каждого собственного
  сообщения. Отрицательная метка допустима только для сообщения текущего аккаунта
  в точной коллекции проверенного диалога, при независимом входящем сообщении
  собеседника с положительным ChatId, равным ID открытого диалога.
- Сначала проверяются заголовки всех сообщений, затем повторно — тот же объект,
  ID, отправитель, направление и ChatId. Только после этого читается текст.
- В стабильность двух снимков включены исходные метки ChatId. Изменение метки или
  подмена записи не допускают отправку. Метки остаются в памяти, не в отчётах.
- Нулевые ChatId, отрицательные ChatId входящих, чужие положительные ChatId и
  отрицательные ID самого диалога/аккаунтов/сообщений по-прежнему блокируются.
- Добавлены нативные сценарии отрицательной метки исходящего, обратного порядка
  сообщений (как в отчёте), отсутствующего/чужого входящего якоря, изменяющейся метки
  и минимального Int64. Проверяется также отправка по тому же защищённому читателю
  с сохранением запрета повторной отправки.
- Автоматическая авторизация явного запуска, интервал 30 секунд и счётчик
  подходящих анкет сохранены. Тесты не заменяют проверку на реальном MuMu.

# DvkAssistant 1.0.3

- Явный запуск разрешает автоматическую отправку фиксированной цепочки; отдельные
  окна подтверждения каждого сообщения убраны. Автозапуска нет, «Стоп» отменяет разрешение.
- Интервал по умолчанию 30 секунд. Старое значение по умолчанию 120 мигрирует в 30;
  пользовательские интервалы сохраняются. Новые настройки имеют версию схемы.
- Цель начального прохода — подходящие анкеты, а не число просмотров. Пропущенная
  анкета заменяется следующей. Сохраняются отдельный счётчик просмотров и предел 200,
  защита от повторных отправок и предел трёх смен города.
- Для ошибки bound-chat-read-failed сохранены точный код, этап и безопасная диагностика.
  Временная загрузка/изменение истории допускает одну повторную попытку только чтения
  того же привязанного чата. Ошибки идентичности и неизвестные отправки не повторяются.
- Сценарий ответа «Взаимно» покрыт синтетическим тестом: один вопрос без окна подтверждения.
  Прежний отчёт не содержит низкоуровневой причины ошибки чтения, поэтому устранение
  именно сбоя реального MuMu ещё не подтверждено; при повторе нужен новый last-monitor.json.
- Счётчики ручных подтверждений и автоматических разрешений разделены.

# DvkAssistant 1.0.2

## Исправление выбора города

- Выбирается только первая видимая строка выдачи, после двух стабильных снимков.
- Убрано требование, чтобы все результаты одновременно помещались на экране.
  Длинный виртуализированный список больше сам по себе не останавливает выбор.
- Сохранены проверки точного названия, типа CITY, идентичности записи перед выбором
  и фактически применённого города. Если первая строка не подходит, нижние не выбираются.
- В last-run.json и вложенном initial_run в last-monitor.json сохраняются точный код
  ошибки выбора города, этап и безопасные счётчики. В статусе показывается причина.
- Подтверждение каждой отправки и защита от повторных отправок не изменены.
- Добавлены регрессионные тесты длинного списка, выбора первого дубликата,
  отказа от нижней строки и сохранения диагностики. Реальный MuMu требует проверки.

# DvkAssistant 1.0.1

## Изменения

- Убраны отдельные кнопки ручного режима из главного окна. Журналы и привязки сохранены.
- «Старт»: один прежний начальный проход, затем мониторинг только отслеживаемых диалогов.
- «Только ответы»: мониторинг без новых анкет. Между проверками окно остаётся на списке диалогов.
- Интервал проверки настраивается: 30–3600 секунд, по умолчанию 120. Проходы последовательные.
- Каждая отправка требует отдельного подтверждения. Отказ/тайм-аут ставят работу на паузу,
  без повторного предложения по таймеру. Продолжение — новым явным запуском.
- При ошибке, неизвестной отправке или сбое записи отчёта мониторинг останавливается.
- Отдельный last-monitor.json: счётчики вызовов отправки, возвратов обработчика и новых
  наблюдений исходящих. Старые наблюдения не суммируются повторно; доставка не заявляется.
- Приветствия больше не считаются доставленными по возврату обработчика. Неизвестное число
  попыток при обрыве цикла помечается отдельно.
- Таймер смены городов и повторные обращения к новым анкетам не добавлены.

## Проверка и ограничения

Добавлены синтетические проверки мониторинга, остановки, пауз, отчётности и навигации
в список диалогов без открытия чата. Native ABI-тесты работают с собственными фикстурами,
без аккаунтов и Android. Windows-сборку проверяет CI; её результат смотри в Actions.
Новая версия ещё требует отдельного прогона на реальном MuMu №4 с тестовым собеседником.
Не удаляй существующую базу: она защищает от повторных отправок.
