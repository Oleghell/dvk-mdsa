# Начни отсюда — MuMu / ДругВокруг

Эта инструкция для Windows. Она не требует разбираться в Python-коде.

## 1. Распакуй проект

Распакуй весь ZIP в отдельную папку, например `C:\\MuMuProject`. Не смешивай файлы из разных версий.

## 2. Установи базовые требования

- Windows 10/11
- Python 3.11 или новее (команда `py -3 --version`)
- MuMu Player с установленным ДругВокруг
- ADB из Android Platform Tools или ADB, который поставляется с MuMu

Не отправляй никому адрес MCP-подключения или Bearer-ключ.

## 3. Сначала запусти безопасную проверку

Дважды щёлкни `CHECK_MUMU_SAFE.bat` в корне проекта. Проверка:
- запускает локальные тесты;
- проверяет, виден ли MuMu через ADB;
- не нажимает кнопки в ДругВокруг, не вводит текст и не отправляет сообщения.

Если проверка ADB говорит, что устройство не найдено, открой MuMu и повтори. Если ADB не найден, укажи путь к `adb.exe` в переменной окружения `ADB_PATH` или открой PowerShell и выполни:

```powershell
$env:ADB_PATH = 'C:\\полный\\путь\\к\\adb.exe'
py -3 .\\mumu-navigation\\production_readiness.py --pretty
```

## 4. Проверь, что реально доступно в UI

Открой ДругВокруг в MuMu и запусти `START_UI_INSPECT.bat`. Он формирует диагностический отчёт о видимых элементах интерфейса. Если дерево интерфейса пустое или неполное, это не означает, что приложение сломано: часть экранов может рисоваться Unity и не отдаваться Android Accessibility.

## Что пока нельзя считать гарантированно работающим

- чтение числа друзей из каждого реального профиля;
- доступ к кнопкам, которые рисуются внутри Unity;
- полное управление всеми экранами приложения.

Статические тесты проверяют логику и защитные ограничения, но не заменяют проверку на твоём компьютере с твоей версией MuMu. Не включай автоматические действия, пока диагностика не подтвердила нужные элементы. Не используй проект для массовых нежелательных сообщений или сбора чужих контактных данных.
