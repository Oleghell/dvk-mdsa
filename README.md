# DvkAssistant

Помощник для ДругВокруг в MuMu №4. Рабочая ветка:
`feature/android-ui-hierarchy`. Один EXE, три кнопки:
**Старт / Стоп / Настройки**.

## Сейчас: один проход по видимым диалогам

«Старт» открывает личку, выбирает **только диалоги, привязанные к приветствиям
в журнале DvkAssistant**, читает проверенную историю и при новом подходящем
ответе автоматически продолжает цепочку. **Отдельного подтверждения нет.**
Затем возвращается в список и в конце — к анкетам. Максимум 32 диалога за проход.

Это **ещё не общий цикл по городам**: новые приветствия и смена города пока
не запускаются. Нет прокрутки списка диалогов, фонового таймера или обещания,
что обработана вся личка. «Старт» выполняет один проход по видимым строкам.
Переход анкеты → личка → анкеты подтверждён на MuMu №4. Выбор строки и работа
цепочки через этот новый обход проверены на стенде, но ещё не на живом MuMu.

После успешного **Build DvkAssistant** распакуй `DvkAssistant-windows-x64`
отдельно, проверь ADB и прежнюю `test-apks`. На №4 открой поиск анкет и нажми
«Старт» один раз. Не управляй экраном во время прохода. Пришли файл
`messages-pass-check.json` из открывшейся папки: он не содержит переписку,
имена, контакты, ID собеседников и токены. Не удаляй базы и журналы.
При ошибке/«Стоп» экран может остаться в диалоге; автоматического отката нет.

Telegram, если включён в настройках, получает **только имя и явно переданный
свой контакт**, а не обычные ответы и не всю переписку. Ошибки/таймауты не
вызывают повторной отправки. Устройство №0 не используется.

## Целевой цикл

1. Выбрать город из `config/cities.json`, проверить «Только онлайн».
2. Проверять новые анкеты, приветствовать подходящих с `< 50` друзьями.
3. После исчерпания города открыть личку и обработать новые ответы.
4. Перейти к следующему городу, периодически проверяя старые диалоги.
5. Telegram: только имя и добровольно сообщённый свой контакт, один раз.

Обычные ответы не вызывают Telegram-уведомлений. Неясные/чужие контакты не
пересылаются. Секреты и контактная очередь защищаются Windows DPAPI;
неизвестный исход отправки не повторяется. Сообщения не отправляются только
потому, что старые сообщения снова стали видны.

[Инструкция и точные границы готовности](rootless-unity/ASSISTANT.md).
Исходный код прежних проверенных режимов сохранён; журналы не удаляются.
Нативные и unit-тесты находятся в проекте для разработки, не в главном окне.
