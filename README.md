## Обновление: группировка OCR в Windows-предпросмотре

Полная сборка содержит Tesseract и общее Linux/Windows-ядро `runtime/chat-core/dvk-chat-core.exe`. `START_CHAT_READ.bat` теперь передаёт обрезанный PNG и OCR-координаты ядру через память/каналы процессов, без сохранения изображения и без установки Python на ноутбуке. В предпросмотре сначала показываются **кандидаты сообщений**, затем все исходные OCR-строки. JSON-диагностика содержит только статус и счётчики группировки, без текста и изображения.

Границы и направления кандидатные, поддержана только ограниченная светлая палитра. Строки вне найденных областей не удаляются. При отсутствии/ошибке EXE сохраняется обычный построчный OCR-предпросмотр. Новизна, идентификация собеседника, очистка временных меток и отправка не реализованы. Нельзя считать последнюю видимую реплику новым сообщением.

Новая цепочка проверяется на искусственных изображениях из готового опубликованного ZIP: PNG → настоящий Tesseract → детектор пузырей → группировка → форматирование предпросмотра. Это не заменяет проверку реального MoreLogin/телефона и интерфейса Windows.

## OCR без системного русского компонента Windows

Добавлен альтернативный локальный Tesseract backend. **Он не меняет службы, реестр или политики Windows и не требует установки языкового компонента.** Это не способ обхода запрета запуска: если ОС блокирует tesseract.exe, потребуется разрешение владельца устройства.

Workflow **Build portable local OCR** устанавливает проверенный дистрибутив Tesseract **только на одноразовом Windows-runner GitHub**, переносит runtime в отдельную папку, добавляет официальные модели rus/eng и проверяет реальное распознавание синтетической русской фразы. Затем публикуется артефакт **dvk-local-ocr-windows-x64** с полной копией проекта и runtime. Обычный Code → Download ZIP не содержит бинарный runtime.

Пользователю: скачайте **успешно собранный артефакт** из GitHub Actions и распакуйте в новую разрешённую папку. Запускайте **START_CHAT_READ.bat** обычным способом. Не запускайте `packaging/build-portable-ocr.ps1`: это установочная процедура исключительно для CI. Оставьте runtime целиком рядом со скриптами. С ключами и adb.exe работайте как раньше. Сам Tesseract и его PNG-ввод/TSV-вывод работают локально в памяти; изображения не отправляются в облако и не сохраняются адаптером на диск.

Успех сборки и чтение русской тестовой фразы не гарантируют точность чтения чата или совместимость со всеми ноутбуками Windows 10. Группировка сообщений, новизна, идентификация собеседника и отправка пока не реализованы. Предыдущие ограничения приватности локального TXT остаются.

Источники: [Windows distribution](https://github.com/UB-Mannheim/tesseract/wiki), [installer verification/version](https://community.chocolatey.org/packages/tesseract), [official models](https://github.com/tesseract-ocr/tessdata_fast/releases/tag/4.1.0). Сборка проверяет закреплённый SHA256 установщика, сохраняет сведения об источниках и SHA256 файлов. Никаких ключей пользователя или реальных снимков в CI нет.

## Локальное чтение видимой переписки — только OCR-предпросмотр

**START_CHAT_READ.bat** распознаёт часть текущего экрана локально. Полная сборка использует Tesseract с русской моделью; русский системный компонент Windows не нужен. Без bundled runtime остаётся старый Windows OCR, которому этот компонент необходим. Ключ ИИ, установка Python и внешний OCR-сервис не нужны.

1. На первом телефоне откройте согласованный тестовый диалог с короткими входящим и исходящим сообщениями.
2. Очистите черновик, закройте клавиатуру. Не прокручивайте и не переключайте экран во время проверки.
3. Скачайте новую версию проекта и запустите **START_CHAT_READ.bat** на своём ноутбуке.
4. Выберите `adb.exe`, введите данные Open API. Подтвердите отдельный вопрос о чтении и локальном сохранении переписки, только если имеете право её обрабатывать.
5. В локальном окне появятся OCR-строки с предположительными метками `ВХОДЯЩАЯ?`, `ИСХОДЯЩАЯ?`, `НЕИЗВЕСТНО`, `ВРЕМЯ?`. Проверьте результат вручную.
6. JSON **reports/chat-read-diagnostic.json** содержит только счётчики и статусы, без распознанного текста. Для диагностики можно передать его.
7. **reports/chat-preview-local-*.txt содержит саму распознанную переписку.** Не отправляйте его без проверки и не публикуйте личную историю. Удалите, когда больше не нужен. Можно просто сообщить, правильно ли прочитались тестовые фразы и направления.

### Что реализовано и что нет

- Полный скриншот и обрезка обрабатываются в памяти; изображения на диск в этом режиме не сохраняются. Область — только видимая полоса между верхней частью экрана и полем ввода, без прокрутки; это не полная история. В полосе может оказаться не только текст сообщений.
- Исходный XML UI собирается с ограничениями, описанными ниже. Встроенный WinRT OCR работает локально. Проверка активного пакета не подтверждает личность собеседника и не гарантирует неизменность диалога.
- Направление строки оценивается грубо по светло-бирюзовому/белому фону и положению. Тема, выделение, фотографии, системные элементы и переносы могут дать ошибки. **Это не классификатор с подтверждённой точностью.**
- OCR-строки ещё **не объединяются в сообщения**. Не реализованы новизна/дедупликация, идентификация собеседника, вся история, ИИ-ответы и отправка. Последняя распознанная строка не считается автоматически новым входящим.
- Сетевые операции режима — только существующие вызовы MoreLogin Open API и ADB. Изображения и OCR-текст не отправляются в сеть. Локальный TXT записывается только после явного подтверждения и исключён из Git вместе с `reports/`.
- Windows OCR может быть недоступен в конкретной редакции/конфигурации Windows или не иметь нужного языка. Ошибка возвращает безопасные диагностические сведения, не сырой OCR/экран. Не отключайте политики и не устанавливайте компоненты вопреки правилам устройства.
- Новая WinRT OCR-функция ещё **не выполнялась на реальном Windows/Android**. JSON-флаг `chat_automation_implemented=false` остаётся верным: диагностическое чтение не является работающим чат-ботом.

## Локальный визуальный предпросмотр — без нажатий

На первом телефоне доступно поле `EditText`, но кнопка отправки не видна отдельным accessibility-элементом (основной интерфейс отображается через Unity). `START_VISUAL_PREVIEW.bat` создаёт **только визуальную гипотезу**: цветной объект справа от поля может быть кнопкой, но цвет и рамка этого не доказывают.

1. Откройте тестовый диалог на первом телефоне. Введите черновик `Привет` и оставьте клавиатуру открытой. Ничего не отправляйте.
2. Скачайте свежий ZIP проекта на свой ноутбук и распакуйте.
3. Запустите **START_VISUAL_PREVIEW.bat**, выберите `adb.exe` и введите APP ID/API Key в локальном окне.
4. Перед снимком появится вопрос о сохранении обрезанной полосы экрана. По умолчанию выбран отказ. Соглашайтесь только для тестового экрана без личных данных.
5. В предпросмотре зелёная рамка обозначает поле; оранжевая — **неподтверждённый бирюзовый объект**. Если рамки нет или она не на кнопке, это нормальный результат калибровки, не повод нажимать её.
6. Закройте окно. Посмотрите `reports/visual-diagnostic.json`. Можно сообщить, правильно ли стоит рамка, или передать этот JSON.
7. PNG находится рядом: `reports/visual-preview-<время>.png`. Перед отправкой кому-либо проверьте изображение и закройте личные данные; отправлять PNG необязательно. Удалите его после проверки, если больше не нужен.

### Приватность и ограничения

- Снимок всего экрана получается через ADB в памяти. Исходный полный PNG не сохраняется на диск.
- **Обрезанная полоса возле поля ввода сохраняется локально** и может содержать черновик или часть переписки. Это не обезличенный JSON. Скрипт не загружает изображение в GitHub, OCR-сервис или другую сеть; Open API используется только для авторизации и параметров телефона.
- Предварительный XML-сбор имеет те же ограничения приватности, что описаны ниже. Проверка пакета до/после снимка не гарантирует, что между ними не изменился диалог.
- Поиск основан на грубой цветовой маске, форме и положении относительно найденного поля. Он не распознаёт стрелку, не устанавливает личность собеседника и не разрешает отправку.
- **Нет `input tap`, ввода текста или отправки.** `automatic_send_allowed=false`, `clicks_performed=0`. Режим не является готовой системой визуального управления.
- Для этого режима используется встроенный System.Drawing/Windows Forms, Python не нужен. Windows/Android-проверка новой функции ещё не выполнена.

## Диагностика элементов тестового диалога

**START_UI_INSPECT.bat** — следующий этап после успешной ADB-проверки. Запускается только по вашему запросу, на первом direct-телефоне. Откройте там тестовый диалог с согласившимся собеседником; используйте экран без личной истории. Не переключайте телефон во время проверки.

1. Скачайте свежий проект и распакуйте в новую папку на своём ноутбуке.
2. На первом телефоне откройте нужное состояние тестового диалога.
3. Запустите `START_UI_INSPECT.bat`, выберите `adb.exe`, введите APP ID/API Key в локальном окне.
4. Передайте **reports/ui-diagnostic.json**, предварительно просмотрев его. Отчёт может быть длинным — удобнее приложить файл.
5. Для сравнения нужны два запуска: с пустым полем/закрытой клавиатурой и с черновиком `Привет`/открытой клавиатурой. Черновик не отправляйте. Сохраните первый отчёт под отдельным именем до второго запуска.

Если возникает ошибка определения приложения, новая версия пробует `dumpsys window`, `dumpsys window windows` и `dumpsys activity activities`. В отчёт при ошибке добавляется `ui_foreground_probe` с кодами завершения и наличием маркеров — без сырых данных окон. Если первый телефон включён, выключенные остальные три не мешают этому этапу.

Режим **не нажимает кнопки, не вводит текст и не отправляет сообщения**. Он проверяет активный пакет `drug.vokrug` до и после сбора структуры. Другие три телефона не подключаются.

### Какие данные читаются

Android `uiautomator dump` временно создаёт XML на самом телефоне. **В исходном XML могут присутствовать имя, сообщения и другой текст экрана.** XML читается в памяти на ноутбуке, не записывается в локальный файл, затем временный файл на телефоне удаляется в `finally`. При ошибке удаления диагностика сообщает о ней и не утверждает, что очистка завершена. При принудительном завершении процесса или потере связи временный файл тоже может остаться. Не запускайте на чувствительной переписке.

В передаваемый отчёт включены только технические поля: статические resource-id, классы, bounds, флаги состояния, признаки наличия текста и небольшие фиксированные метки вроде `send_label`. **Значения `text` и произвольные `content-desc`, фото, скриншоты, имена и сообщения не экспортируются.** Наличие resource-id может раскрывать структуру приложения; не публикуйте отчёт открыто без необходимости.

Поле `chat_content_read=true` в режиме UI честно означает, что исходный XML мог включать содержимое экрана; `text_values_exported=false` означает, что значения текста исключены из отчёта. Это не противоречие. Не отправляйте сырой XML или параметры ADB.

UI-диагностика ещё не проверена на Windows/Android. Она не доказывает, что открытый экран — нужный диалог: проверка пакета не устанавливает личность собеседника. Перед любой будущей отправкой понадобится отдельная надёжная проверка диалога.

## Первый телефон: реальная проверка ADB

Запускайте **START_ADB_CHECK.bat** на своём разрешённом ноутбуке, не на удалённом столе с ограничениями. Режим требует распакованных официальных [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools). Не вынимайте `adb.exe` отдельно: рядом нужны DLL из архива.

1. Скачайте свежую версию проекта и распакуйте в новую папку.
2. Запустите `START_ADB_CHECK.bat`.
3. В окне выбора файла укажите `adb.exe` в своей папке `platform-tools`.
4. В локальном окне введите APP ID и API Key, как при успешной проверке Open API.
5. Дождитесь Блокнота с **reports/adb-diagnostic.json**. Передавайте только этот отчёт; не публикуйте ADB-адреса, код подключения, ключ или токен.

Подключается **только первый ID** из `openapi.config.json` — сейчас `1731099842042760`, ранее имевший режим `direct`. Вариант SSH на этом этапе не автоматизируется. Если первый телефон теперь требует туннель, клиент останавливается, а не исполняет полученную SSH-команду.

Повторный запуск сначала проверяет уже авторизованную сессию через `getprop`. Если Android отвечает корректной версией, код ADB повторно не отправляется. Иначе выполняется одна штатная авторизация, а результат проверяется ещё одним `getprop`; один лишь exit code команды авторизации не трактуется как доказательство неверного кода. Безопасные числовые результаты доступны в `adb_probe_diagnostics`; содержимое ответов скрыто.

Что выполняется: локальный `adb version`, `adb connect`, штатная авторизация MoreLogin через `adb -s ... shell CODE`, затем чтение версии Android (`getprop`), разрешения экрана (`wm size`) и имён установленных пакетов (`pm list packages`). В отчёте сохраняются только версия, размер, результат и кандидаты пакета ДругВокруг по названию. Кандидат — не доказательство, что это нужное приложение.

**Никаких нажатий, текста, сообщений, скриншотов, UI-дампов, файлов переписки или изменений настроек.** Три остальных телефона не подключаются. Локальный ADB-сервер может остаться запущенным; клиент не делает `kill-server`, не отключает существующие устройства и не открывает сервер на внешнем интерфейсе.

Код ADB проверяется как один токен без shell-метасимволов. Произвольная команда из ответа сервиса не выполняется. Адрес ADB принимается только как IPv4 с валидным портом. По штатной схеме MoreLogin код подключения кратковременно передаётся аргументом локального процесса `adb.exe`; он не записывается в отчёт, но может быть виден системным средствам наблюдения за процессами. Запускайте только на доверенном компьютере и не записывайте список процессов. Клиент не утверждает, что прямой ADB-транспорт шифрован.

Результат `adb_check.status=ok` и `android_version` подтверждает shell-доступ только к первому телефону. Наличие параметров у остальных не подтверждает соединение с ними. Реальная Windows/Android-проверка этой новой функции ещё не проведена; ошибки в ответах намеренно не выводятся целиком, чтобы не раскрывать секреты.

## С ноутбука к облачным телефонам: Open API

Этот режим не использует Local API удалённого рабочего стола. Запускайте **на своём ноутбуке**, где у вас есть разрешение на выполнение скриптов. Не переносите его обратно на сервер с административным запретом.

1. Сверьте **API address в блоке Open API**: должен быть `https://api.morelogin.com`. Если указан `127.0.0.1`, это Local API — выбран не тот блок.
2. Скачайте свежий ZIP из GitHub и распакуйте в новую папку на своём ноутбуке.
3. Запустите **START_OPENAPI.bat** обычным двойным щелчком, не от администратора. Python и сторонние пакеты не нужны.
4. Откроется отдельное локальное окно **MoreLogin Open API**. Вставьте **APP ID** в первое поле.
5. Скопируйте полный **API Key** непосредственно из MoreLogin и вставьте через **Ctrl+V** во второе поле. Ключ скрыт, но рядом показано число символов. Убедитесь, что вставилось больше одного символа. Нажмите **Проверить**. Не используйте ClipboardNow и другие сайты обмена текстом для секретов.
6. Дождитесь проверки авторизации и четырёх согласованных Cloud Phone ID.
7. В Блокноте откроется `reports/openapi-diagnostic.json`. Можно передать этот отчёт, предварительно проверив содержимое: код записывает только статусы и ID, без ключа, токена и параметров ADB.

**Не присылайте APP ID/API Key в чат. Не записывайте ключ в GitHub или JSON-конфигурацию.** Данный клиент спрашивает его заново при каждом запуске, не принимает секреты через командную строку и не сохраняет их. Секрет временно присутствует в памяти процесса для HTTPS-запроса; гарантировать полное стирание всех копий из управляемой памяти нельзя. Не включайте запись экрана и PowerShell-транскрипцию во время ввода. Если ключ опубликован, отзовите его в MoreLogin.

Используются только два документированных вызова:

- `POST https://api.morelogin.com/oauth2/token` — `client_id`, `client_secret`, `grant_type=client_credentials`;
- `POST https://api.morelogin.com/cloudphone/batchAdbInfo` — `envIds`, заголовок `Authorization: Bearer ...`.

Адрес сервера жёстко ограничен официальным HTTPS-origin; перенаправления и системный прокси отключены. Проверка TLS-сертификата не отключается. Ответы сервера, секреты, параметры подключения и произвольные сообщения сервиса не печатаются. В режиме `START_OPENAPI.bat` запуск/остановка телефонов, изменение ADB, shell-команды и переписки не выполняются. Отдельный режим `START_ADB_CHECK.bat` описан выше.

**Ограничения:** аккаунт должен быть активен, иметь права на нужную команду/телефоны; внешний IP ноутбука должен соответствовать allow/deny-спискам Open API. Эти ограничения клиент не обходит. Если Open API запрещён, нужен владелец команды. Успешная авторизация ещё не означает доступа к Android UI. ADB должен быть заранее разрешён и включён для поддерживаемой модели телефона.

`openapi.config.json` создаётся из примера и содержит только официальный адрес API и ID телефонов. Не заменяйте его Local API-конфигурацией. Код `35002` означает ошибку проверки APP ID/API Key; `35005` — запрет операции (в том числе ограничения IP или неактивный участник); `12002` — отсутствие команды.

Отчёт показывает этап ошибки: `configuration`, `authentication` либо `phone_query`. Успех `authentication=ok` при `phone_query=failed` означает, что ключ принят, но запрос телефонов не прошёл.

Если ОС запрещает `.bat`/PowerShell, не переименовывайте файлы, не отключайте защиту и не меняйте политики для обхода. Требуется разрешение владельца устройства. PowerShell-версия проверена статически, но ещё не выполнялась на Windows или реальном аккаунте.

## Local API: запуск на том же компьютере, где работает MoreLogin

1. В GitHub нажмите **Code → Download ZIP**.
2. Распакуйте ZIP в свою папку, например **Документы → spam-dvk**. Не запускайте из архива.
3. **Ничего устанавливать не нужно:** основной запуск использует встроенный Windows PowerShell 5.1 и .NET. Права администратора не запрашиваются.
4. На этом же Windows-компьютере откройте MoreLogin. Убедитесь, что четыре телефона запущены и ADB для них уже включён.
5. Дважды нажмите **START_WINDOWS.bat**.
6. Дождитесь результата: откроется Блокнот с `reports/diagnostic.json`.
7. Для следующего этапа можно передать этот отчёт. В нём есть ID и статусы, но нет паролей, адресов ADB, SSH-команд и API-ключей.

Если Windows сообщает, что выполнение сценариев отключено, запрещено политикой или файл заблокирован, **не отключайте защиту и не запускайте от администратора ради обхода**. Обратитесь к администратору. Программа не использует `ExecutionPolicy Bypass`, не меняет ExecutionPolicy и не снимает блокировку файлов. Если скрипт не запустился, существующий отчёт может быть от старого запуска — проверьте `created_at_utc`.

При первом запуске `config.example.json` копируется в локальный `config.json`. В примере уже указаны четыре согласованных ID и адрес Local API `http://127.0.0.1:8001` из настроек пользователя. Другие порты автоматически не перебираются.

Если вы меняли список телефонов или порт, откройте `config.json` Блокнотом. ID оставляйте в кавычках.

## Что проверяется

- Доступен ли Local API MoreLogin на этом компьютере.
- Возвращает ли `POST /api/cloudphone/batchAdbInfo` данные для каждого `envIds`.
- Включён ли телефон, поддерживает ли он ADB, включён ли ADB.
- Есть ли параметры прямого подключения или SSH-туннеля.
- Есть ли локальный `adb.exe` в PATH (в версии PowerShell — только поиск, без запуска ADB).

**«Параметры доступны» не означает, что ADB-соединение уже установлено.** Авторизация телефона, SSH-туннели и Android UI будут отдельным этапом после проверки отчёта. Адрес Local API не является адресом Android/ADB.

## Ошибки

| Результат | Что делать |
| --- | --- |
| Нет ответа от Local API | Откройте MoreLogin на том же компьютере и сверьте порт в Developer & AI Agent → Local API |
| HTTP 401/403 или код ошибки авторизации | Не выключайте защиту. Нужна отдельная настройка авторизации клиента; эта версия её не реализует. Не присылайте ключи в чат |
| `phone_not_powered_on` | Запустите нужный телефон и дождитесь загрузки |
| `adb_disabled` | В списке Cloud Phone: ⋮ → Enable ADB |
| `adb_unsupported` | Проверьте, поддерживает ли выбранная модель/тариф ADB |
| `missing_result` / `duplicate_result` | Сверьте Cloud Phone ID и права команды; программа не угадывает соответствие по порядку |
| `connection_details_missing` / `service_remark_present` | Параметры пока недоступны; проверьте состояние в MoreLogin и повторите позже |
| ADB не установлен | Для проверки API не нужен. Для следующего этапа потребуются [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) |

## Безопасность

- Не открывайте порт 8001 в интернет и не настраивайте проброс портов.
- Программа принимает только loopback-адрес с явным портом; системные прокси и HTTP-перенаправления отключены.
- Код использует текущий режим Local API без авторизации. Он **не меняет** Security verification. Если авторизация требуется, работа останавливается, а не отключает защиту.
- Ответ API читается в памяти. Поля с паролями, командами, адресами и произвольными сообщениями сервиса не выводятся и не сохраняются.
- Не публикуйте снимки экрана с ключами. Токены, отправленные в чат, нужно отозвать.
- Настройки и отчёты исключены из Git. Сам файл отчёта содержит ID профилей — не публикуйте его открыто без необходимости.

## Дальнейшие этапы — пока не реализованы

1. Проверка SSH-подключения остальных телефонов без обхода проверок сервиса. Для первого direct-телефона добавлена диагностическая функция, ожидающая проверки на Windows.
2. Чтение интерфейса ДругВокруг на одном тестовом диалоге; надёжное различение входящих и исходящих.
3. Раздельная история четырёх профилей, очередь черновиков и кнопка остановки.
4. ИИ-помощник с прозрачным обозначением автоматизированного общения.
5. Первое приветствие выбранному пользователем контакту — только с подтверждением; без повторных сообщений при отсутствии ответа. Автоматические ответы на входящие — после тестирования и явного включения.

Не предусмотрены массовая рассылка всем пользователям, обход блокировок, CAPTCHA, лимитов или скрытая выдача ИИ за человека. До автоматизации следует проверить правила приложения.

## Разработка и тесты

`diagnose.ps1` — основной вариант без установки Python. `diagnose.py` оставлен как дополнительный вариант для компьютеров, где Python уже разрешён и установлен.

```powershell
py -3 -m unittest discover -s tests -v
py -3 diagnose.py
```

Тесты не обращаются к аккаунтам, MoreLogin или Android. На реальных телефонах проект ещё не проверен. 14 тестов Python-реализации прошли в Linux. Они не являются проверкой PowerShell-реализации: PowerShell и BAT пока не выполнялись на Windows. Проверены структура файлов, локальный endpoint, отсутствие токенов и отсутствие команд для изменения политик безопасности.
