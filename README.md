# DvkAssistant 1.3.22 — контактный режим и контекстный выбор MAX

- В MuMu включён сохраняемый contact-only режим в том же namespace порта. После проверенного предложения мессенджера допускаются получение контакта и одно уточнение выбранного мессенджера/номера. Посторонние вопросы и общие реплики завершают диалог без генерации ответа: «Ты откуда?», «Женат?», «Чем занимаешься?», «Зачем?», «Давай», смайлик и т. п. В смешанном пакете посторонний вопрос также блокирует дальнейший разговор; непосредственно присланный проверенный контакт обрабатывается раньше этого ограничения. Встречные просьбы прислать наш номер не вызывают выдумывания номера. Начальные приветствие/вопрос/контактное предложение не изменены.
- Старый pending-followup не восстанавливается для отправки после включения режима. Это терминальный пропуск без сброса текста, хеша или статуса резерва. Неизвестные отправки, изменённая история и смена личности не получают разрешения на повтор. MAX/безразличный выбор по-прежнему допускают одно программное уточнение; после него нет общих followup. Legacy/test-only пути без MuMu-политики сохраняют прежнее поведение.
- MAX распознаётся по связям названия и признаков наличия/выбора/использования, а не только по полному совпадению предложения. Поддержаны «макс», «мак», «мах» и MAX, словоформы, эмодзи и составные реплики: «Нет телеграмма и ватсапа, есть макс», «У меня есть макс😉больше не где нет», «В мах можно», «Я только в максе», «Ни того ни другого Макс только». Отсутствие Telegram/WhatsApp не отменяет положительный выбор MAX. Явное отрицание MAX, имя человека, цитата и неоднозначный вопрос не считаются выбором. Короткий текст с номером и меткой «мак/мах» проходит прежние проверки добровольного контакта, а не запускает повторный запрос.
- Предпочтения «Я здесь, почему не хочешь?», «Для начала здесь удобнее», «Да и тут нормально», «А мне удобнее тут остаться», «Пока здесь», явный отказ раздавать номер/контакты и недоступность приложений распознаются до ИИ. Они проверяются также в неизменённой истории активного диалога, где старая версия уже отвечала; новые «Хорошо» не возобновляют цепочку. Явное желание остаться здесь или не давать номер имеет приоритет над выбором MAX. Старые terminal/manual-review цепочки не открываются заново.
- Изучены 33 скриншота галереи пользователя, текстовые сценарии добавлены в синтетические регрессии без данных профилей и реальных контактов. Разбор лексико-контекстный, не обещает безошибочного понимания произвольного естественного языка. Правила ИИ и ключи не менялись. Живой MuMu не проверялся; Windows-архив требует успешного Actions. Версия MuMu 1.3.22 / ядро 1.2.31, только ветка mumu, без Release.

# DvkAssistant 1.3.20 — недоступный ввод и ограничение продолжения диалога

- Если нативный IsInputEnabled=false в том же проверенном чате до публикации резерва приветствия, анкета пропускается без отправки: один вызов штатного Back, проверка возвращённого профиля/поиска, сохранение посещения. Это обычный пропуск, не ошибка порта и не событие восстановления; несколько удалённых анкет подряд не расходуют лимит восстановления истории. Состояние ввода проверяется также в кадре подготовки приветствия. По одному скриншоту/общему screen-not-ready возврат не разрешается.
- После контактного предложения допускается максимум два дополнительных исходящих — уточнения и contextual followup суммарно. Учитываются текущие резервы и архив наблюдавшихся followup, в том числе после перезапуска. Неотправленный awaiting-approval черновик не считается исходящим. При достижении лимита проверенная активная цепочка терминально пропускается, без вызова ИИ и третьего ответа. Уже завершённые цепочки не открываются заново.
- Явный ответ «И то и то работает не очень... Даже с впн...» на контактное предложение — немедленный пропуск без ответа. Общие отказы/предпочтение остаться здесь также прекращают цепочку сразу. Текущий добровольно присланный контакт проверяется до лимита и может завершить активный диалог успехом; повторно завершённые диалоги не возобновляются. Выбор MAX остаётся одним программным уточнением, которое входит в общий лимит.
- Ответ «Да без разницы» / «Мне всё равно» / «Как тебе удобнее» на предложение мессенджеров выбирает однократный программный запрос номера для Telegram/WhatsApp, без генерации ИИ и без предложения остаться здесь. Цитаты, вопросы и старое несвязанное согласие до контактного этапа не используются. Уже присланный контакт не запрашивается повторно; старый наблюдавшийся generic followup может быть исправлен одним уточнением в пределах общего лимита.
- Неизвестные отправки, черновики, fingerprints, claims и резервные записи не сбрасываются. При изменении личности, неизвестном результате Back или уже опубликованном резерве новый локальный пропуск не выполняется. Правила Groq и ключи не меняются.
- Версия MuMu 1.3.20 / ядро 1.2.29. Проверки unit и собственный нативный C/Frida-стенд, не живой MuMu пользователя. Windows-пакет требует успешной сборки Actions. Только ветка mumu, без публикации Release.

- «Общаюсь только тут…» и «Удобнее мне тут… соц.сети не раздаю» завершают диалог без ответа. - «Новые анкеты» рядом со «Старт»: на выбранных портах сохраняется исключение всех уже известных диалогов, даже если позже туда придёт новое сообщение; первым запускается поиск анкет, затем ответы только новым подходящим цепочкам. База посещённых пользователей, общие claims, старые резервы и дедупликация сохраняются. Другие порты не затрагиваются.
- selection-count-changed повторяется максимум два раза только при проверенном read-only сканировании model-list: до любых действий, без identity результата. После повторных изменений допускается прежнее безопасное восстановление экрана. Не добавлен повтор отправки, слепой Back или разрешение обходить ошибки идентичности.

# DvkAssistant 1.3.18 — MAX, отказ от перехода и восстановление подключения

- Явный выбор «У меня работает только Макс / У меня только MAX / Давай в Максе» в активной привязанной цепочке приводит к одному программному уточнению номера в MAX. ИИ не создаёт и не меняет этот новый шаблон. «Только MAX» не считается уже полученным контактом. Полученный затем номер проходит прежние проверки и сохраняется как контакт; резерв уточнения не повторяется. После наблюдавшегося уточнения MAX общие реплики не запускают обычное продолжение «пообщаемся здесь».
- Выбор MAX учитывается и в проверенной полной неизменённой истории активного диалога, где старая версия уже ответила обычным followup, если уточнение ещё не отправлялось. Неизвестные отправки, готовые старые черновики, manual-review и terminal states не переписываются. Отсутствие одного другого приложения не отменяет явный выбор MAX; общий отказ/предпочтение остаться здесь остаётся отказом.
- Опечатка «Сдесь» и «Первое время хотелось бы остаться здесь» после предложения мессенджера завершают цепочку без ответа. Проверены также старые диалоги, где на эти предпочтения уже был отправлен ответ. Цитаты, вопросы и отрицания не принимаются за эти утверждения. Правила Groq не меняются.
- Перед восстановлением теперь выполняется connect только к исходному явно выбранному порту через новый объект ограниченного ADB, затем сравнивается исходный boot ID под прежней блокировкой устройства. Это не принятие другого Android, не сканирование портов, не сброс и не переустановка. Неизвестные сообщения и нажатия не воспроизводятся.
- Быстрый ADB сохраняет закрытую категорию отказа сервиса/сокета вместо общего command-failed. Ответ FAIL читается только в RAM, с ограничением размера; произвольный текст не попадает в события или исключения. Временная потеря связи передаётся восстановлению; unauthorized, permission-denied, неверный формат и смена boot ID не обходятся. При блокировке сохраняется безопасное доказательство причины повторной проверки.
- Версии MuMu и ядра в отчёте worker берутся из mumu_version, а не из устаревших констант. В старых приложенных JSON исходные причины — ошибки закрытия forward, пропажа ADB-сервера/устройства и frame-budget, а окончание восстановления отражено только как state-check-failed. Его точную причину старый JSON не раскрывает: устранение всех возможных причин этого общего кода не заявляется.

MuMu 1.3.18 / ядро 1.2.27. Проверки синтетические, без вызовов пользовательских API и без живых MuMu пользователя. Только ветка mumu; без GitHub Release.

Постоянно слишком большой чат может оставаться отложенным и требует отдельного разбора.
- После недоступности всех ИИ-ключей не фиксируется завершение обработки чата; повторная проверка не раньше чем через 60 секунд. Генерация может повторяться, неопределённая отправка — никогда.
- Причины отказов ИИ сохраняются для каждого сервиса и номера ключа: лимит, сеть, авторизация, непроверенный ответ, ограничение токенов; видны также ключи на временной паузе. Самих ключей и тел ошибок API нет. Краткая причина приходит в Telegram вместо одинакового сообщения для всех сбоев.
- Верхняя граница генерации Groq увеличена с 220 до 1024 токенов: короткий лимит мог обрывать ответ модели. Это не отменяет лимитов API и проверок итогового сообщения (до 240 символов).
- Для MuMu 5563 сохраняется старый путь `%LOCALAPPDATA%\DvkAssistant`; остальные отчёты лежат в `devices/<порт>`. Используй уже существующую кнопку «Открыть отчёты выбранного MuMu».

MoreLogin не изменён. Не удаляй базы/журналы, не переустанавливай APK. Доступность внешних сервисов и успешное чтение каждого большого диалога не гарантируются.

## Предыдущие изменения 1.3.1

- `frame-budget` до открытия фильтра города: до четырёх свежих повторных чтений на следующих кадрах. После вызова изменяющего действия автоматического повтора нет. Общие лимиты и проверка выбранного города сохранены.
- MuMu проверяет доступные ключи **Groq → OpenRouter**. Ключи берутся из `config/ai-keys.txt` и защищённого хранилища Windows, без дублей. После исчерпания обоих сервисов пропускается только текущий чат; новые неотвеченные реплики остаются доступными для следующей проверки. Ошибка правил или отмена не обходится переключением.
- Старый ID модели OpenRouter `minimax/minimax-m3.1-flash:free` автоматически заменяется на `dots-studio/dots-3-note-preview:free`. Только бесплатные модели и прежние ограничения приватности; платного резерва нет.
- В отчётах раздельно учитываются реальные попытки Groq/OpenRouter и закрытые коды отказов. Ключи, заголовки авторизации и тела ответов API туда не записываются.
- При нескольких MuMu сохраняются общая защита от повторного приветствия, скорость 35 слов/минуту и 120 секунд активной проверки лички между порциями.

Файл ключей: скопируй `config/ai-keys.example.txt` в `config/ai-keys.txt`, впиши собственные ключи по одному на строку. Не оставляй `#` перед настоящим ключом. Для OpenRouter используй полный префикс `sk-or-v1-`; также распознаётся 64-значный ключ в секции `[openrouter]`. До 16 ключей на сервис. Не публикуй файл; опубликованные в чате ключи рекомендуется перевыпустить.

Работа проверяется автоматическими тестами и синтетическими запросами к API. Это не заменяет проверку запуска на конкретном MuMu; временные сетевые ошибки, исчерпание лимитов и безопасные остановки при неопределённой отправке всё ещё возможны.

## Обновление

1. Останови старую программу, дождись завершения операций и закрой её.
2. Сохрани резервную копию `%LOCALAPPDATA%\DvkAssistant` и `%LOCALAPPDATA%\DvkRootless`. Не удаляй журналы и базу.
3. Распакуй **весь** архив в отдельную папку. Рядом остаются `DvkAssistant.exe`, `DvkMumuWorker.exe`, `_internal` и `config`. Один EXE отдельно не переносится.
4. Если менял города, приветствия, правила или список ИИ-ключей — перенеси собственные файлы `config` из старой папки. Не отправляй ключи другим людям.
5. Пути ADB/test-apks и защищённые ключи остаются прежними в профиле Windows. APK и аккаунты программа не удаляет, не переустанавливает и не переносит.

## Устройства

Запусти нужные MuMu и открой приложение. На **каждом** устройстве нужен уже установленный совместимый комплект APK с авторизованным Frida Gadget. Обычный APK без Gadget для этого режима не подходит. Автоустановки нет.

В поле программы укажи выбранные локальные ADB-порты по одному на строку:

```
5557
5559
5561
5563
5565
```

Это первые значения из показанного списка MuMu. Альтернативные порты тех же устройств (16416, 16448, 16480, 16512, 16544) одновременно с первыми **не добавляй**: это не дополнительные телефоны. Для новых экземпляров дописывай их реальные ADB-порты; автоматического сканирования портов нет.

Можно оставить один порт. Поддерживается до 128 явно выбранных различных портов. Если два порта ведут в один Android, блокировка по boot identity не позволит двум процессам управлять им одновременно.

«Старт» запускает анкеты и ответы на выбранных устройствах. «Только ответы» — только личку. «Стоп» отзывает разрешение всех процессов. Ошибка одного MuMu не останавливает остальные; повторный запуск только вручную. Во время работы не управляй выбранными эмуляторами вручную.

## Общая история и защита от повторов

Одна SQLite-база на этом Windows-компьютере: `%LOCALAPPDATA%\DvkAssistant\assistant.sqlite3` (WAL, synchronous=FULL).

- Старые таблицы и история MuMu на порту 5563 остаются на месте.
- Журналы чатов и текущий город остальных портов изолированы в таблицах одной базы; одинаковые chat ID разных устройств не смешиваются.
- Глобальный ID пользователя ДругВокруг проверяется по общей истории.
- Глобальный резерв по пользователю и локальный резерв сообщения фиксируются **в одной транзакции до разрешения отправки**.
- Если другой MuMu успел забрать ту же анкету, проигравший не отправляет приветствие и выполняет проверенный возврат к анкетам. Это проверяется повторно после задержки печати, а не только в снимке списка.
- Неизвестные, незавершённые и даже `not-invoked` резервы не снимаются автоматически. Нет повторной отправки «на всякий случай».
- Старые журналы импортируются без удаления исходников. Запускать старую одиночную программу одновременно с новой не нужно.
- Эта общая база работает на **одном компьютере и в одном профиле Windows**; сетевой синхронизации разных ПК нет.

## Задержки и ускорение

- Задержка составленного сообщения: **35 слов/мин**, отменяется кнопкой «Стоп».
- Между порциями анкет: **120 секунд**, но это работа с личкой, а не заморозка. Входящие проверяются и обрабатываются каждые 5 секунд; активная очередь по существующему алгоритму разгребается сразу.
- По истечении 120 секунд программа завершает текущую безопасную операцию/проход лички, затем продолжает анкеты. В середине отправки таймер не прерывает чат.
- У каждого устройства отдельный процесс: длительная операция/ошибка одного не блокирует остальные.
- Общая onedir-упаковка не распаковывает весь runtime заново для каждого устройства.
- Четыре фиксированные команды чтения ADB идут напрямую через локальный сервер, без старта adb.exe на каждое чтение. Разрешённый список, свежая проверка boot ID, состояние устройства и shell exit status сохраняются.
- Подписанный хешами комплект APK полностью проверяется при первом использовании в процессе; неизменность обоих файлов проверяется перед каждым последующим использованием. При изменении файла снова выполняется полная проверка SHA256. Кеш не хранится между запусками.
- Нет непроверенного повторного использования Frida-сессии из MoreLogin Beta.13. Каждая операция использует свежую сессию/скрипт и прежние проверки личности/истории.

Нулевую длительность переключений обещать нельзя: ожидания готовности экрана, чтения истории, сети ИИ и подтверждения результата остаются. Искусственная пауза отдыха — только указанные 2 минуты; дополнительные длинные паузы не добавлялись.

## Отчёты

Выбери строку устройства и нажми «Открыть отчёты выбранного MuMu».

- Порт 5563: `%LOCALAPPDATA%\DvkAssistant\` (как раньше).
- Другие: `%LOCALAPPDATA%\DvkAssistant\devices\<порт>\`.
- `last-startup.json`: версия, стадия запуска, закрытый тип ошибки, без текста исключений/секретов.
- `last-monitor.json`: результаты текущего цикла с выбранным портом.
- `last-performance.json`: суммарные времена/счётчики ADB, без содержимого переписки.
- Telegram-уведомления подписываются `MuMu ADB <порт>`. Команды статистики используют одну общую базу; обработчик Telegram запускается только в GUI.

## Проверено и не проверено

Синтетические тесты проверяют конкурентный резерв из разных процессов/аккаунтов, сохранение старой базы, изоляцию одинаковых chat ID, блокировку двух портов одного Android, отмену и отсутствие повтора неизвестной отправки. Нативный тест Frida выполняет настоящий путь пропуска/возврата на собственном ABI-стенде без реальных аккаунтов.

На реальных нескольких MuMu новая версия ещё требует проверки. Программа не считает возврат обработчика подтверждением доставки сообщения.
