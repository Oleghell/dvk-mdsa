# DvkAssistant 0.4.11 — имя читается только после контакта

Добавлен отдельный режим **«Вся цепочка · открытый чат»** на MuMu №4.
Один запуск наблюдает всю последовательность:

1. Твоё уже отправленное приветствие из `config/greetings.json`.
2. Любой новый ответ собеседника на приветствие.
3. Черновик «Как дела?)» или «Как настроение?)» → твоё подтверждение →
   появление вопроса в истории.
4. Любой новый ответ собеседника (в том числе «Рабочее», эмодзи или вложение).
5. Черновик «Супер, у меня тоже. Ты есть в телеграме или ватцапе?
   А то я тут не часто бываю 😅» → твоё подтверждение → появление в истории.
6. Ожидание следующего ответа собеседника.
7. Только если собеседник сам прислал свой Telegram или телефон/WhatsApp —
   одно уведомление боту:
   `Новый контакт!`, имя и присланный контакт.

Это не автоматическая рассылка: один явно выбранный тестовый чат, отдельное
подтверждение каждого исходящего, без поиска новых собеседников. При отказе,
изменении истории или неизвестной отправке — остановка.
Неизвестные отправки и уведомления автоматически не повторяются.

**Для первого запуска:** включи Telegram и сохрани токен/Chat ID в локальных
настройках. В тестовом чате вручную отправь приветствие из списка, оставь чат
открытым и нажми **«Вся цепочка» до ответа собеседника**. Затем пройди оба
ответа и добровольно присланный контакт в том же запуске. Жди появления окон
подтверждения. Не переключай чат.
Для продолжения ранее сохранённой цепочки используй тот же открытый чат.

Отчёт: `%LOCALAPPDATA%/DvkAssistant/messages-chain-check.json`.
Ожидание ограничено 30 минутами. После окончания чат остаётся открытым.
После предложения перейти в мессенджер обычный ответ, отказ или молчание
не создают уведомление. Распознаются `@username`, ссылка `t.me/...` и
однозначный номер телефона с кодом страны. Сквозные тесты синтетические;
новая цепочка ещё требует полного прохода на реальном MuMu и проверки
уведомления твоим ботом.

Если этот собеседник уже участвовал в остановленной проверке, оставь в открытом
чате ровно одно новое своё приветствие без ответа и нажми
**«Начать цепочку заново · открытый чат»**. После подтверждённого перезапуска
нажми обычную кнопку **«Вся цепочка · открытый чат»**. Другие чаты и настройки
не сбрасываются. Кнопка не работает, если в видимой истории больше одного
сообщения или уже есть входящий ответ.

До получения контакта режим не запрашивает имя собеседника. Оно читается
отдельно только после распознанного нового контакта, непосредственно перед
подготовкой уведомления Telegram.

## «Старт» — прежнее чтение без отправки, модуль 0.4.6

Проверочная ветка: `fix/dialog-selection-diagnostics`.

«Старт» на MuMu №4 открывает до пяти видимых привязанных диалогов
**только с непрочитанными сообщениями**. Прочитанные чаты пропускаются без
открытия. После чтения программа возвращается к анкетам. Новые чаты можно
явно привязать кнопкой «Привязать чат для чтения»; разрешения на отправку нет.

- **Сообщения не отправляются. Telegram выключен.** Имена не читаются.
- Исходный журнал открывается только для чтения. Анализ работает с временной
  SQLite-копией в оперативной памяти; этапы и резервы исходного журнала не меняются.
- Ноль непрочитанных — пропуск. Изменение/ошибка счётчика — остановка,
  без перехода к открытию всех диалогов.
- До 20 сообщений на диалог, без прокрутки, новых приветствий и смены города.
- При неизвестном состоянии проверка останавливается без повторов и отката.
- Открытие чата может изменить отметку «прочитано» в самом приложении.
- В отчёте только счётчики и категории. Переписки, имён, контактов и ID нет.

## Что сделать

1. В GitHub → Actions дождись успешной **Build DvkAssistant** для этой ветки.
2. Скачай `DvkAssistant-windows-x64` и распакуй в отдельную папку.
3. Укажи прежние ADB и `test-apks`. Базы и журналы не удаляй.
4. На тестовом аккаунте с существующими привязками открой анкеты на MuMu №4.
5. Нажми «Старт» один раз и не трогай экран до завершения.
6. Пришли `%LOCALAPPDATA%/DvkAssistant/messages-pass-check.json`.

Если подходящих видимых диалогов меньше пяти, проверятся только они. Это не
полный обход лички. Если активных привязок нет, устройство не используется.

В 0.4.5 на устройстве подтверждены чтение пяти диалогов и возврат к анкетам.
Новый фильтр непрочитанных 0.4.6 пока проверен только синтетическими тестами.
Отправка ответов и общий цикл этой сборкой не проверяются.

Подробнее: [инструкция](rootless-unity/ASSISTANT.md).

### Ответы собеседника в 0.4.11

Списков разрешённых ответов нет: любой новый ответ на приветствие или вопрос, включая вложение и несколько сообщений, продвигает ровно один этап. После предложения мессенджера обычные ответы не останавливают ожидание контакта и не создают уведомление. Явный отказ, изменение истории и неизвестная отправка по-прежнему останавливают цепочку. Подтверждение каждого исходящего сохранено. Ранее остановленная цепочка автоматически не возобновляется.
