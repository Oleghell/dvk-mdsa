# spam-dvk

Первая версия для Windows 10: **диагностика четырёх Cloud Phone в MoreLogin**.

Это НЕ готовый чат-бот. Модуль ДругВокруг, чтение диалогов, ИИ и отправка сообщений ещё не реализованы. Сначала проверяем доступ к телефонам. Программа не запускает/останавливает телефоны, не переключает ADB, не выполняет команды из ответа сервиса и не отправляет сообщения.

## Как запустить без терминала

1. В GitHub нажмите **Code → Download ZIP**.
2. Распакуйте ZIP в обычную папку, например `C:\spam-dvk`. Не запускайте из архива.
3. Если Python ещё нет, установите **Python 3.13 для Windows** с [официального сайта](https://www.python.org/downloads/windows/). В установщике включите **Add python.exe to PATH**. Нужен Python 3.10 или новее; дополнительные пакеты не требуются.
4. На этом же Windows-компьютере откройте MoreLogin. Убедитесь, что четыре телефона запущены и ADB для них уже включён.
5. Дважды нажмите **START_WINDOWS.bat**.
6. Дождитесь результата: откроется Блокнот с `reports/diagnostic.json`.
7. Для следующего этапа можно передать этот отчёт. В нём есть ID и статусы, но нет паролей, адресов ADB, SSH-команд и API-ключей.

При первом запуске `config.example.json` копируется в локальный `config.json`. В примере уже указаны четыре согласованных ID и адрес Local API `http://127.0.0.1:8001` из настроек пользователя. Другие порты автоматически не перебираются.

Если вы меняли список телефонов или порт, откройте `config.json` Блокнотом. ID оставляйте в кавычках.

## Что проверяется

- Доступен ли Local API MoreLogin на этом компьютере.
- Возвращает ли `POST /api/cloudphone/batchAdbInfo` данные для каждого `envIds`.
- Включён ли телефон, поддерживает ли он ADB, включён ли ADB.
- Есть ли параметры прямого подключения или SSH-туннеля.
- Установлен ли локальный `adb` (проверка `adb version`, без подключения к устройствам).

**«Параметры доступны» не означает, что ADB-соединение уже установлено.** Авторизация телефона, SSH-туннели и Android UI будут отдельным этапом после проверки отчёта. Адрес Local API не является адресом Android/ADB.

## Ошибки

| Результат | Что делать |
| --- | --- |
| Нет ответа от Local API | Откройте MoreLogin на том же компьютере и сверьте порт в Developer & AI Agent → Local API |
| HTTP 401/403 или код ошибки авторизации | Не выключайте защиту. Нужна отдельная настройка авторизации клиента; эта версия её не реализует. Не присылайте ключи в чат |
| `phone_not_powered_on` | Запустите нужный телефон и дождитесь загрузки |
| `adb_disabled` | В списке Cloud Phone: ⋮ → Enable ADB |
| `adb_unsupported` | Проверьте, поддерживает ли выбранная модель/тариф ADB |
| `missing_result` / `duplicate_result` | Сверьте Cloud Phone ID и права команды; программа не угадывает соответствие по порядку |
| `connection_details_missing` / `service_remark_present` | Параметры пока недоступны; проверьте состояние в MoreLogin и повторите позже |
| ADB не установлен | Для проверки API не нужен. Для следующего этапа потребуются [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) |

## Безопасность

- Не открывайте порт 8001 в интернет и не настраивайте проброс портов.
- Программа принимает только loopback-адрес с явным портом; системные прокси и HTTP-перенаправления отключены.
- Код использует текущий режим Local API без авторизации. Он **не меняет** Security verification. Если авторизация требуется, работа останавливается, а не отключает защиту.
- Ответ API читается в памяти. Поля с паролями, командами, адресами и произвольными сообщениями сервиса не выводятся и не сохраняются.
- Не публикуйте снимки экрана с ключами. Токены, отправленные в чат, нужно отозвать.
- Настройки и отчёты исключены из Git. Сам файл отчёта содержит ID профилей — не публикуйте его открыто без необходимости.

## Дальнейшие этапы — пока не реализованы

1. Проверка реального ADB-подключения с учётом версии Android и SSH, без обхода проверок сервиса.
2. Чтение интерфейса ДругВокруг на одном тестовом диалоге; надёжное различение входящих и исходящих.
3. Раздельная история четырёх профилей, очередь черновиков и кнопка остановки.
4. ИИ-помощник с прозрачным обозначением автоматизированного общения.
5. Первое приветствие выбранному пользователем контакту — только с подтверждением; без повторных сообщений при отсутствии ответа. Автоматические ответы на входящие — после тестирования и явного включения.

Не предусмотрены массовая рассылка всем пользователям, обход блокировок, CAPTCHA, лимитов или скрытая выдача ИИ за человека. До автоматизации следует проверить правила приложения.

## Разработка и тесты

```powershell
py -3 -m unittest discover -s tests -v
py -3 diagnose.py
```

Тесты не обращаются к аккаунтам, MoreLogin или Android. На реальных телефонах проект ещё не проверен. Windows BAT-файл требует проверки на пользовательском Windows 10; Python-тесты выполнялись в Linux.
