# DvkAssistant — проверка переходов 0.4.3

Проверочная ветка: `fix/dialog-selection-diagnostics`.

## Что изменилось

«Старт» теперь только проверяет путь на MuMu №4:
**анкеты → список сообщений → один привязанный диалог → список → анкеты**.

- Сообщения **не отправляются**, даже если раньше была включена автоцепочка.
- Переписка и имена не читаются. Telegram не используется.
- Журнал SQLite открывается только для чтения. Новых резервов отправки нет.
- Только существующие активные привязки журнала, максимум один диалог.
- При неизвестном состоянии проверка останавливается без повтора и без отката.

Причина прежнего `selection-changed` пока НЕ исправлена: сначала нужно точно
узнать, какая проверка не прошла. Все прежние проверки выбора сохранены.
Вместо общего сообщения отчёт различает изменение экрана, контроллера, таблицы,
коллекции строк, количества строк, ячейки, объекта чата и отсоединение ячейки.
Никаких адресов объектов, ID людей или текста переписки в отчёте нет.

## Что сделать пользователю

1. В GitHub → Actions открой **Build DvkAssistant** для этой проверочной ветки.
2. Только после успешной сборки скачай `DvkAssistant-windows-x64` и распакуй отдельно.
3. Укажи прежние пути ADB и `test-apks`. Базы и журналы не удаляй.
4. Для проверки используй тестовый аккаунт с уже существующей привязкой журнала.
5. На MuMu №4 открой анкеты. Нажми «Старт» один раз и не трогай экран.
6. Пришли новый `messages-pass-check.json` из `%LOCALAPPDATA%/DvkAssistant/`.
   При остановке проверь экран вручную; автоматического отката нет.

Если активных привязок нет, программа ничего не открывает. Это не повод
рассылать приветствия или очищать журнал для получения привязки.

Это диагностическая сборка, а не готовый цикл по городам. На реальном MuMu её
нужно проверить отдельно: локальные тесты этого не доказывают.
