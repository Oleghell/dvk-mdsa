# DvkAssistant MoreLogin 2.0.0-beta.7

Основная ветка `main` — MoreLogin Cloud Phone. Сохранённая ветка `mumu` — DvkAssistant 1.2.16 для MuMu №4. Это разные сборки и разные каталоги данных.

## Важно перед запуском

Это предварительная сборка переноса. Автотесты проверяют изоляцию телефонов, общую базу, API/SSH и прежний алгоритм, но НЕ доказывают работу на настоящих Cloud Phone Android 14–15. Сначала проверь один телефон в режиме «Только ответы».

Обычный цикл НЕ устанавливает и не модифицирует приложение на телефоне. В сборке есть отдельный явный установщик с подтверждениями; см. раздел ниже. Нужны твой совместимый приватный комплект `test-apks` и уже установленная совместимая тестовая копия ДругВокруг с аутентифицированным Frida Gadget (arm64), открытая на нужном аккаунте. Обычный магазинный APK автоматически совместимым не становится. Если на облачном Android другой ABI/нет Gadget/не совпадает комплект — запуск запрещается. Совместимость конкретных Android 14–15 ещё требует проверки; гарантировать её заранее нельзя. Сам комплект `test-apks` не публикуется.

## Настройка

1. Распакуй Windows-архив в отдельную папку. В ней должны лежать `DvkAssistant.exe`, `DvkCloudWorker.exe`, `config` и инструкция. Старую MuMu-папку и журналы не удаляй.
2. Запусти `DvkAssistant.exe`. В «Настройки → MoreLogin API» введи **APP ID** и **Secret Key**, нажми «Сохранить MoreLogin API». Они используются как `client_id` / `client_secret` официального Cloud Phone Open API `https://api.morelogin.com`; временный OAuth-токен программа получает сама. Если твои ключи выданы только для Local API, нужны права именно на Cloud Phone Open API. Должны быть разрешены IP компьютера и доступ к выбранным телефонам.
3. В «Поиск и ответы» укажи свой `adb.exe` и приватную папку `test-apks`. Настрой размер порции, период проверки лички и отдых перед новой порцией. Настройки ИИ и Telegram задаются отдельно, как в прежней версии.
4. В главном окне введи **новый список Cloud Phone ID — один ID на строку**. Список не берётся из MuMu или случайных устройств ADB. Все указанные и доступные телефоны запускаются одновременно; максимум 200 ID — предел запроса API, не обещание производительности ПК.
5. В MoreLogin включи нужные Cloud Phone и их ADB-доступ. Программа сама не создаёт и не включает платные телефоны, не меняет их тарифы и настройки ADB.
6. Нажми «Проверить подключения». Для прямого ADB проверяются вход по коду и загрузка Android (без шифрования SSH). Для SSH считывается ключ без отправки пароля: сверь SHA256-отпечаток через доверенный канал и подтверди его. При смене SSH-ключа нужна новая ручная проверка; само получение ключа не подтверждает подлинность сервера.
7. Нажми «Только ответы» для первой проверки, затем «Старт» для анкет + ответов. Нажатие разрешает автоматические сообщения в рамках запуска. На старте приложения действий нет.

## Подключение Android 14–15

Способ выбирается по ответу `cloudphone/batchAdbInfo`: SSH-команда означает туннель с проверкой ключа, а отсутствие команды или точная команда `adb connect IP:PORT` — прямой ADB по публичному IPv4, порту и числовому коду. В обоих случаях создаётся отдельный локальный endpoint `127.0.0.1:<свободный порт>` для выбранного телефона. SSH поддерживает IPv4 и DNS-имя, совпадающее с adbIp этого телефона; DNS проверяется до подключения. Известные параметры совместимости и кавычки разбираются, но не исполняются и не отключают закрепление ключа. Команды API не выполняются через shell. Неизвестная схема и некорректная SSH-команда отклоняются, а не вызывают переключение на другой способ или устройство.

Никакого запасного подключения к MuMu, неявного ADB-устройства, общего фиксированного порта или `adb kill-server` нет. Перед работой проверяется загрузка Android, пакет и идентичность устройства. Второй процесс с тем же ID или тем же boot UUID не допускается.

## Установка частного Gadget-комплекта через Cloud Phone ID

Закрой циклы, выбери «Установить Gadget» в DvkAssistant или запусти DvkCloudInstaller.exe. Укажи один Cloud Phone ID, свой adb.exe и частную папку test-apks с двумя APK. Сначала проверь и закрепи SSH-ключ этого телефона обычной кнопкой «Проверить подключения». Открытие установщика ничего не запускает и не читает ключи до явного нажатия «Проверить и установить Gadget».

Установщик получает подключение по существующим ключам DPAPI, проверяет SDK 34/35, основную архитектуру ARM64 и хеши комплекта. Нажатие кнопки НЕ удаляет приложение: перед записью есть подтверждение. Существующая версия сначала обновляется без удаления. Только если Android точно сообщает несовместимость подписи, предлагается замена с ручным вводом точного ID телефона. До удаления сохраняются исходные APK, проверяется их целостность и повторно сверяется идентичность телефона. Для резервирования требуется 4 ГБ свободного места.

**Удаление стирает данные приложения. Копия APK не сохраняет аккаунт, текущий вход или локальную переписку.** Новая установка может завершиться ошибкой; автоматического отката, повторного удаления или автоповтора после неопределённого результата нет. Сначала обеспечь повторный вход в аккаунт. Отмена до удаления сохраняет установленное приложение; отмена после записи не откатывает выполненное.

Отчёт: `%LOCALAPPDATA%\DvkAssistantMoreLogin\phones\<ID>\last-install.json`. Исходные установочные APK: подпапка `apk-backups` там же. Приватные APK и токен Gadget не публикуются. Установщик не запускает приложение, не входит в аккаунт, не отправляет сообщения и не подтверждает работоспособность Gadget. После успеха открой приложение и войди самостоятельно, затем проверь «Только ответы» на одном телефоне.

## Одна общая база

Файл на ЭТОМ компьютере, у ЭТОГО Windows-пользователя:

`%LOCALAPPDATA%\DvkAssistantMoreLogin\shared.sqlite3`

Это ОДНА SQLite-база для всех Cloud Phone ID. В ней:
- общая история проверенных анкет;
- общие атомарные резервы первого обращения к пользователю: два телефона не получают разрешение отправить ему одно и то же первое сообщение;
- отдельные по ID журналы диалогов, этапов цепочки, черновиков, неизвестных отправок и уведомлений. Одинаковые локальные chat ID разных телефонов не смешиваются.

Резерв записывается до разрешения отправки и сохраняется после сбоя/перезапуска. Неизвестная отправка не повторяется автоматически. Если два телефона одновременно выбрали одну анкету, один получает резерв, второй безопасно прерывает свою попытку до отправки; остальные процессы продолжаются. Такой конфликт пока может завершить текущий проход второго телефона — это не обход проверки на дубли.

SQLite использует WAL и короткие транзакции с ожиданием блокировки до 30 секунд. Держи базу на локальном диске, не в сетевой папке/синхронизируемом облачном диске. Это НЕ межкомпьютерный сервер общей базы. Если база вырастет до безопасного лимита 10 000 известных анкет, потребуется контролируемое архивирование, а не удаление резервов. В интерфейсе нет очистки общей истории.

Данные MuMu не импортируются, не очищаются и не объединяются молча. Отчёты не являются отдельными базами: `%LOCALAPPDATA%\DvkAssistantMoreLogin\phones\<ID>\last-monitor.json`, ошибки старта — `last-startup.json`. В Telegram текст и подпись фото помечены Cloud Phone ID.

## Алгоритм

Перенесён алгоритм MuMu 1.2.16: проверка входящих и прочитанных без ответа, контекст цепочки, защита от повторного приветствия и дублей, распознавание контактов, фото профиля с контактом одним сообщением Telegram, локальная изоляция проблемных чатов, отдых в личке между порциями анкет, задержка набора 35 слов/мин. ИИ и отправка контекста внешнему провайдеру — только при включении пользователем. `config/ai-keys.txt` принимает несколько ключей выбранного провайдера по шаблону; не публикуй заполненный файл. Переход на платные модели автоматически не выполняется.

Список диалогов не прокручивается. Используется доступная приложению модель диалогов без прежнего лимита в 10 чатов; недоступный серверный архив не загружается скрытым способом. Ошибка одного телефона не отменяет остальные, но потеря идентичности, SSH/ADB или неизвестная отправка остаются основаниями для безопасной остановки. Восстановление через повтор неизвестной отправки запрещено.

«Стоп» отменяет все текущие процессы, даёт им завершить ограниченные операции, затем при зависании завершает только свой дочерний процесс. Выполненные сообщения не откатываются. Не переключай экраны выбранных телефонов во время работы.

## Секреты и приватность

APP ID / Secret Key, одиночные ключи ИИ из настроек и Telegram-токен хранятся отдельно через Windows DPAPI. Но заполненный файл пула `config/ai-keys.txt` — обычный открытый текст: DPAPI его не шифрует. Не публикуй этот файл и ограничь доступ к нему. В командной строке процесса, GitHub и отчётах ключей нет. Пароль SSH передаётся дочернему процессу по приватному каналу в памяти, не записывается в базу. DPAPI защищает хранение, но не заменяет защиту Windows-учётной записи. Сама база не зашифрована и содержит рабочую историю/данные диалогов — не отправляй её публично.

Проверка подключения (SSH или прямого ADB) не доказывает готовность приложения/Gadget. Не присылай Secret Key или заполненные файлы ключей в чат. Для диагностики присылай отчёт конкретного ID после просмотра на личные данные.

## Исходники и тесты

`python rootless-unity/run_unit_tests.py` — синтетические тесты, без аккаунтов и Android. CI Linux/Windows выполняет также native fixture-тесты. Windows CI собирает GUI и отдельный worker, запускает их офлайн self-check без устройств и создаёт manifest с SHA256. `live_verified` для MoreLogin остаётся false до реальной проверки на облачных телефонах. Для запуска исходников: Python 3.13, frida==17.24.1, paramiko==4.0.0, `python rootless-unity/morelogin_app.py` на Windows.

### Диагностика подключения (beta.2)
Ошибки API больше не затираются успешным завершением проверки. Для каждого ID показаны этап, HTTP-код или числовой код MoreLogin. Безопасный отчёт: `%LOCALAPPDATA%\DvkAssistantMoreLogin\last-connection.json`. В отчёте нет APP ID, Secret Key, токенов, паролей, заголовков или тела ответа. Временные сетевые/HTTP 429/5xx ошибки повторяются до трёх попыток только для получения токена и чтения ADB-параметров; ошибки авторизации и TLS не обходятся. Реальная причина прежнего api-unavailable без нового отчёта неизвестна.

### Windows HTTP-клиент (beta.3)
На Windows запросы Open API выполняются системным Windows PowerShell / .NET HttpWebRequest — тем же механизмом, который прошёл локальную проверку авторизации пользователя. Секреты передаются процессу только через stdin, не через аргументы или временные файлы. Используется фиксированный встроенный код без профиля, перенаправлений, прокси и обхода TLS; только два разрешённых read-only endpoint. Если системный PowerShell заблокирован, будет явная ошибка, скрытого отката к прежнему транспорту нет. В настройках MoreLogin API кнопка «Проверить сохранённые ключи» выполняет только авторизацию и пишет безопасный last-api-check.json. Пустые поля не означают отсутствия ранее сохранённых ключей. Это исправление ещё нужно проверить в самой программе на Cloud Phone пользователя.

### Прямой ADB без SSH (beta.4)
Если Open API возвращает прямой `adb connect` или не возвращает команду, используются adbIp/adbPort/adbPassword для документированной схемы Android 12/15: подключение и вход по числовому коду. При наличии SSH-команды её ошибки не обходятся переключением на прямой ADB. Прямой режим поддерживает публичный IPv4, порт 1–65535 и числовой код 1–32 знака; неизвестные форматы отклоняются. Прямой ADB не имеет шифрования SSH — используйте доверенную сеть. Кнопка проверки выполняет авторизацию ADB и read-only проверки загрузки Android, не запускает цикл, не устанавливает/удаляет APK. Код передаётся через ADB smart-socket, а не аргументы процесса. На каждый телефон отдельный loopback relay, фиксированная привязка выбранного API ID, проверка boot UUID и общая база сохраняются. Отключается только созданное этой программой локальное подключение. Реальный Cloud Phone ещё требуется проверить.


## beta.7: проверка Gadget, причина установки и компактная сборка

В окне «Установить Gadget» появилась отдельная кнопка **«Проверить установленный Gadget»**.
Для неё нужны только Cloud Phone ID и ADB: локальная папка test-apks не нужна.
Она читает только установленные APK и сравнивает SHA256 всего комплекта с известными APK Gadget.
Ничего не устанавливает, не удаляет, не запускает приложение, не подключается к Gadget и не отправляет сообщения.
Результаты: наш комплект подтверждён / другой комплект / приложение отсутствует / проверка не завершена.
Другой комплект НЕ означает доказанное отсутствие любого Gadget: проверяется именно наш частный комплект.
Отчёт — `phones/<ID>/last-gadget-check.json`. Временные APK после проверки удаляются.
Нужно 2 ГБ свободного места на компьютере; одна передача APK может ждать до 240 секунд.
Работу самого Gadget на Android 15A совпадение APK ещё не доказывает.
Перед проверкой остановите рабочий цикл. Блокировки не допускают одновременную работу с одним телефоном.

Обработчик SSH больше не подменяет ошибки операций внутри туннеля кодом ssh-unavailable.
Таймаут установки сохраняется как operation-uncertain, Android Failure — как adb-failed с разрешённым Android-кодом.
Неопределённая установка автоматически не повторяется. Старые отчёты не позволяют восстановить потерянную причину.
После сообщения Android об успешной установке программа дополнительно сравнивает установленные APK.
При несовпадении или ошибке проверки успех не подтверждается и повтор/удаление не выполняются.

Три EXE теперь используют одну общую папку **_internal**, а не три отдельных копии Python/Frida/библиотек.
Распаковывайте **весь архив в новую папку**; не переносите отдельные EXE и не удаляйте _internal.
Настройки DPAPI и общая база остаются в прежнем LOCALAPPDATA и не мигрируют молча.
Контрольные суммы общих библиотек включены в build-manifest.json.
CI запускает все три EXE из перемещённой папки с пробелами, без телефона и учётных данных.
